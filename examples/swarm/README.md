# swarm — многопоточная симуляция с повтором

Программа ROADMAP v0.3 «многопоточная программа с повтором» (DoD,
раздел C: «симуляция на системе задач с повтором»). Рой агентов на
плоскости: шаг идёт `parallel for` по пулу агентов, состояние — класс D
(Р12, Р55). Запись прогона — зерно, вход каждого такта и хэш состояния
после него; повтор подаёт записанный вход и сверяет хэш на каждом такте
(`docs/policy/DETERMINISM.md`, раздел 4).

| файл | что |
|---|---|
| `swarm.dpm` | модуль класса D: мир, входы «игрока», такт, подпись агента и хэш мира |
| `main.dpm` | программа: запись и повтор, разбор записи, отчёт; тесты `@test` |
| `samples/` | записи для повтора: верная, с изменённым входом, не запись |
| `expected/` | ожидаемое: отчёт тестов, вывод повтора и его аргументы |

## Запуск

    swarm record <зерно> <агентов> <тактов>    — запись в stdout
    swarm replay <файл>...                     — повтор записей

Повтор пишет «файл: replay ok, N ticks, M agents, hash H» или
«файл:строка: error: …» в stderr; код выхода 1, если хоть одна запись
не сошлась.

## Запись

Текст, строки через LF:

    swarm-record 1
    seed <зерно>
    agents <число агентов в начале>
    <такт> goal <x> <y>        — новая цель роя
    <такт> spawn <x> <y>       — новый агент
    <такт> kill <n>            — удалить n-го живого агента по номеру слота
    <такт> hash <16 цифр hex>  — хэш после такта

Команды такта идут перед его строкой `hash`, такты — подряд с 1.
Координаты — целые в тысячных долях единицы, мир — 400 × 400 единиц.

## Модель

- Агент: номер, координаты и скорость — целые с фиксированной точкой,
  «нагрев» — `f64`, подпись `sig` — хэш всех полей после такта.
- Такт: команды по порядку; снимок агентов и сетка соседей 16 × 16
  (рабочая память переживает такты, Р68); затем `parallel for a in
  &mut w.agents` — агент читает соседей из снимка и меняет только себя
  (Р69): сближение с центром соседей, выравнивание скорости,
  отталкивание вблизи, тяга к цели.
- Случайность — по ключам (splitmix64 от зерна, такта и номера), без
  общего генератора.
- Хэш мира — FNV-1a от такта, цели и подписей агентов по номеру слота:
  подписи считаются в пуле потоков, объединение — в одном порядке
  (отображение с упорядоченным объединением). Нагрев входит в подпись
  точной записью `str(x)` (Р48).

## Что проверяется

- Проход example (`tests/run.py`): тесты `@test`, повтор интерпретатором,
  повтор сборкой `--release` с числом потоков по умолчанию и при
  `DPL_THREADS` 1, 3 и 8 — вывод один, канонический вид исходников.
  Запись `samples/short.rec` сделана интерпретатором, поэтому её повтор
  сборкой сверяет нативный код с эталонным на каждом такте.
- Вручную (31 октября): сборка debug и release дают один хэш; сборка с
  TSan гонок не находит.

## Замер

Сборка `--release`, `record 20261031 5000 100` (5000 агентов, 100
тактов), 4 ядра, медиана трёх прогонов, 31 октября 2026:

| `DPL_THREADS` | время | вывод |
|---|---|---|
| 1 | 8,46 с | один и тот же (sha256 совпадает) |
| 2 | 4,57 с | |
| 4 | 2,41 с | |

Первая версия считала нагрев в хэше мира — после шага, по очереди:
запись `f64` (printf и strtod libc) занимала больше половины времени, и
четыре потока давали ускорение 1,14. Подпись агента в самом шаге
перенесла эту работу в пул потоков.
