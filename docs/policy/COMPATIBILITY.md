# Политика совместимости

Что гарантируется потребителю языка, что допускается как ломающее
изменение и как это проверяется. Основание — Р0, Р18, Р26. Классы
артефактов S0–S2 — `docs/design/ARCHITECTURE.md`, раздел 2.

Абсолютной обратной совместимости нет. Цель — чтобы основная стоимость
изменения лежала в компиляторе и инструментах, а не в ручном
переписывании проекта (Р0), и чтобы каждое обещание ниже проверялось
автоматически.

## 1. Определения

- **Consumer project** — проект с production-кодом на C-; тесты, замеры
  и синтетические примеры им не являются (Р0).
- **Редакция** — именованная версия исходного языка; указывается в
  манифесте пакета (Р18).
- **Ломающее изменение** — любое из:
  1. программа, которую принимала версия компилятора, отвергается
     следующей в той же редакции;
  2. меняется наблюдаемое поведение программы детерминированного класса
     (`docs/policy/DETERMINISM.md`);
  3. меняется артефакт класса S0 несовместимо;
  4. удаляется или меняет смысл публичный API стандартной библиотеки.
- **Машинная миграция** — правка `fix`, применимая без участия человека,
  после которой программа принимается и проходит свои тесты.

## 2. Режимы

| режим | когда | что действует |
|---|---|---|
| R&D | до первого consumer project | гарантий нет; изменения — по возможности с `fix` |
| production | с первого consumer project | гарантии раздела 3 и процесс раздела 4 |

Переход в режим production — запись в `DECISIONS.md`.

## 3. Гарантии режима production

| № | гарантия | исключения |
|---|---|---|
| Г1 | программа, принятая компилятором X.Y в редакции E, принимается любым X.Y′ (Y′ ≥ Y) той же мажорной версии в редакции E и сохраняет поведение детерминированного класса | исправление дыр в надёжности; исправление ошибок компилятора, расходившегося со спецификацией; ошибки, включённые проектом из предупреждений |
| Г2 | компилятор поддерживает все редакции начиная с редакции v1.0 | снятие редакции — только решением с путём миграции |
| Г3 | переход модуля на новую редакцию выполняется `fix --edition`; ручная доля — не больше заявленной в примечании к выпуску редакции | изменения, у которых машинной правки нет, перечисляются поимённо |
| Г4 | публичный API стандартной библиотеки не удаляется внутри мажорной версии; устаревание — минимум два минорных выпуска с правкой `fix` | исправление дыр в надёжности |
| Г5 | данные, записанные стандартной сериализацией версии формата N, читаются, пока N объявлен поддерживаемым; одинаковое значение со схемой даёт одинаковые байты в любой версии компилятора | — |
| Г6 | C ABI объявлений `extern` — как у C на платформе | — |
| Г7 | манифест и lockfile старого формата инструменты переводят вперёд автоматически | — |
| Г8 | схема диагностики меняется внутри мажорной версии только добавлением; коды ошибок не переиспользуются | — |
| Г9 | артефакты компилятора (кэш, сводки, объектные файлы) совместимости между версиями **не** имеют и всегда пересоздаются | — |
| Г10 | сгенерированные файлы (привязки) пересоздаются закреплённым генератором; дифф проходит ревью | — |

## 4. Процесс ломающего изменения (режим production)

1. Предложение в `DECISIONS.md`: мотив, альтернативы, путь миграции,
   оценка ручной доли.
2. Реализация в новой редакции (или новой мажорной версии библиотеки) и
   машинная правка `fix`.
3. Прогон корпуса (раздел 5) старым и новым компилятором.
4. Решение автора и запись в историю.
5. Раздел «Ломающие изменения» в `docs/CHANGELOG.md`: что, почему, как
   мигрировать, ручная доля.

## 5. Как проверяется (формально)

| что | проверка | когда |
|---|---|---|
| Г1, Г2 | корпус программ по редакциям — тесты соответствия, программы `examples/`, представительный consumer project — собирается каждым выпуском компилятора; результаты тестов совпадают | каждый выпуск; перед вливанием изменений семантики |
| Г1 (поведение) | золотые хэши состояния детерминированных программ (побитово) | каждый выпуск |
| Г3 | `fix --edition` на корпусе: доля ручных правок, тесты после правки | выпуск редакции |
| Г4 | сравнение публичного API библиотеки с прошлым выпуском (инструмент) | каждый выпуск |
| Г5 | золотые файлы сериализации всех поддерживаемых версий формата: чтение и повторная запись | каждый выпуск |
| Г6 | тесты ABI: обвязка на C проверяет раскладку и вызовы на каждой цели | каждый выпуск |
| Г7 | старые манифесты и lockfile из набора тестов переводятся и собираются | каждый выпуск |
| Г8 | проверка схемы диагностики и реестра кодов | каждое изменение диагностики |

Выпуск с непрошедшей проверкой — только по записанному решению
(`docs/policy/RELEASE.md`).

## 6. Долгоживущие форматы данных

| формат | владелец | правило |
|---|---|---|
| форматы стандартной сериализации | стандартная библиотека | версия формата в каждом блоке; канонический вид (порядок байтов, NaN, порядок ключей); не зависит от раскладки типов в памяти и версии компилятора |
| сохранения программы (например, VoxelRPG) | программа | схема — данные программы с её версией; миграции — код программы; изменение языка не меняет байты сохранения при той же схеме (Г5) |
| метаданные проекта и пакета | инструменты | поле `format`; перевод вперёд (Г7) |
| артефакты компилятора | компилятор | без совместимости (Г9) |
| сгенерированные файлы | генератор | закреплённый генератор, ревью диффа (Г10) |

**Сохранения VoxelRPG.** Пока VoxelRPG на C++, язык на них не влияет.
После переноса (Р31) сохранения пишутся только стандартной
сериализацией со схемой; память в файл напрямую не пишется. Политику
совместимости самих сохранений решает VoxelRPG (его `DECISIONS.md`).
