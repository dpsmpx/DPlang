# Детерминизм и воспроизводимость

Нормативный документ: слово «детерминированный» в проекте применяется
только в смысле этого документа (Р29). Основание — Р12, Р29.

## 1. Определения

- **Входы** детерминированного вычисления — явные параметры, включая
  зерно, и данные, переданные в него явно. Часы, ОС, файлы, потоки и
  адреса входами не являются.
- **Результат** — возвращённые значения, изменённое состояние и байты
  сериализации.
- **Одинаковость результата:** целые, логические, байтовые и плавающие
  значения — побитово. NaN в коде класса D после каждой операции
  приводится к каноническому (Р56), поэтому совпадает и он.
- **Область гарантии** — одна редакция языка и одна версия стандартной
  библиотеки, любые поддерживаемые цели первой волны (x86-64, arm64),
  любой профиль сборки и любое число потоков.

## 2. Четыре класса поведения

| класс | смысл | примеры | где разрешено |
|---|---|---|---|
| **D** — гарантированно детерминированное | одинаковые входы → одинаковый результат в области гарантии | целочисленная арифметика, базовые операции IEEE, упорядоченные контейнеры, ГПСЧ библиотеки, сериализация | везде |
| **I** — определяемое реализацией | фиксировано для версии компилятора и цели, задокументировано, не наблюдаемо из класса D | раскладка не-`extern` типов, размер стека, адреса | везде; из D не наблюдаемо |
| **P** — платформозависимое | различается между целями | платформенная libm, приближённые SIMD-операции, порядок файлов в каталоге, API ОС | только вне D |
| **N** — намеренно недетерминированное | зависит от времени, планирования или внешнего мира | часы, энтропия ОС, мьютексы и каналы, ввод-вывод | только вне D |

Код помечается как детерминированный (по умолчанию — модуль, уточнение
— функция, Р55): модуль — у импорта, `@det import m`; функция —
`@det fn`. Компилятор проверяет, что код класса D вызывает только
код класса D; значения из P и N попадают в D только явными параметрами.
API стандартной библиотеки помечены классом.

## 3. Правила по областям

| область | правило |
|---|---|
| числовые типы | целые — фиксированной ширины; переполнение — ловушка, заворачивание и насыщение — явными операциями (Р11); деление на ноль и сдвиг на ширину и больше — ловушка; преобразование плавающей точки в целое вне диапазона — ловушка |
| состояние управления плавающей точкой | на входе в код класса D runtime проверяет и восстанавливает режим: округление к ближайшему чётному, без сброса денормалов; внешняя библиотека, сменившая режим на потоке, не меняет результат D (аудит 3 октября 2026) |
| плавающая точка | IEEE 754 binary32/64, округление к ближайшему чётному; в D — только операции с корректным округлением (сложение, вычитание, умножение, деление, корень, явный `fma`); без слияния в FMA (флаг C-компилятора `-ffp-contract=off`), без fast-math, без смены режима округления и сброса денормалов; трансцендентные функции — свои реализации библиотеки; `fma` в D корректно округлена, на целях без аппаратного FMA — программно |
| случайность | алгоритмы ГПСЧ и случайности по ключам указаны и версионированы; одинаковое зерно и ключи дают одну последовательность на всех целях; смена алгоритма — новая версия; общего изменяемого генератора нет; энтропия ОС — класс N |
| порядок обхода | у контейнеров библиотеки определён; не зависит от адресов и соли хэша |
| сортировка | в D — устойчивая сортировка с указанным алгоритмом; равные ключи сохраняют исходный порядок |
| хэш-таблицы | встроенная `Map` — обход по возрастанию ключа (Р54); таблица библиотеки (О12, рекомендация) — порядок обхода как порядок вставки, хэш-функция указана и версионирована; быстрая неупорядоченная таблица в D не даёт обхода |
| параллелизм | в D — только параллельные циклы и отображения с упорядоченным объединением; разбиение на части не зависит от числа потоков (фиксированный размер части), объединение — по фиксированному дереву; результат не зависит от числа потоков и планирования; атомики с гонками, мьютексы, каналы — класс N |
| планирование задач | порядок исполнения задач — класс N; в D наблюдаем только результат с упорядоченным объединением |
| сериализация | канонический вид: порядок байтов от младшего, канонический NaN, порядок ключей определён; одинаковое значение → одинаковые байты |
| время | в D нет часов; время — входной параметр (номер такта, длительность) |
| внешний ввод-вывод | в D нет; данные — входные параметры |

## 4. Воспроизводимое выполнение игровых систем

Схема — как у детерминированной симуляции TigerBeetle и как уже устроен
VoxelRPG (фиксированный такт, случайность по ключам):

- **запись:** начальное состояние или зерно + поток входов по тактам;
- **повтор:** симуляция класса D на тех же входах;
- **проверка:** хэш состояния на каждом такте побитово совпадает — между
  запусками, профилями, числом потоков и целями x86-64 и arm64.

Повтор и сравнение хэшей — штатные средства тестов (Р13); arm64 на
Linux-хосте — через эмулятор пользовательского режима или устройство.

## 5. Проверки

| что | как |
|---|---|
| компилятор соблюдает правила класса D | тесты отказа компиляции: вызов N/P из D, часы, ввод-вывод, неупорядоченный обход |
| результат не зависит от цели | межплатформенные повторы: золотые хэши x86-64 = arm64 |
| результат не зависит от потоков и профиля | повторы с 1…N потоков, `debug` и `release` |
| сериализация каноническая | золотые файлы байт-в-байт |
| библиотека помечена верно | ревью и тесты на каждую функцию класса D |

## 6. Воспроизводимая сборка

- **Определение:** одинаковые исходники, lockfile, версии инструментов
  (компилятор dpl, компилятор C, NDK, MinGW), цель и профиль дают
  побитово одинаковые артефакты.
- **Меры:** нет времени и случайных значений в артефактах;
  упорядоченные входы; перенос путей сборки; закреплённые инструменты;
  `SOURCE_DATE_EPOCH`, где инструмент требует время.
- **Проверка:** две сборки в разных каталогах и в разное время → хэши
  совпадают; выполняется перед каждым выпуском
  (`docs/policy/RELEASE.md`).
