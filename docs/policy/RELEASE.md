# Выпуск

Как выпускаются версии компилятора, стандартной библиотеки и runtime.
Основание — Р4, Р5, Р23, Р26; версионирование —
`docs/design/ARCHITECTURE.md`, раздел 4.

## 1. Виды выпусков

| вид | что | кому |
|---|---|---|
| веха v0.x | состояние после этапа `ROADMAP` | внутренне |
| кандидат в выпуск | версия, проходящая проверки выпуска | внутренне |
| выпуск (v1.0 и далее) | версия, прошедшая все проверки и решение автора | внутренне; наружу — только отдельным решением (Р5) |

## 2. Проверки выпуска

1. Полный и расширенный прогон (`docs/policy/TESTING.md`, раздел 5) на
   всех целях уровня 1 (`docs/policy/PLATFORMS.md`).
2. Корпус совместимости и золотые файлы
   (`docs/policy/COMPATIBILITY.md`, раздел 5).
3. Воспроизводимая сборка: две сборки — одинаковые хэши
   (`docs/policy/DETERMINISM.md`, раздел 6; проход `repro`
   `tests/run.py`).
4. Замеры против базы (`docs/policy/BENCHMARKS.md`); превышение порогов —
   объяснено.
5. Нет известных необъяснённых критических ошибок
   (`docs/policy/SECURITY.md`, раздел 5).
6. Документы обновлены; `docs/CHANGELOG.md` с разделом «Ломающие
   изменения», если они есть.
7. Решение автора — записью в `DECISIONS.md` для v1.0 и мажорных
   выпусков.

Выпуск с непрошедшей проверкой — только по записанному решению с
причиной.

## 3. Артефакты

- компилятор и инструменты для хоста Linux x86-64 (Windows-хост — позже,
  отдельным решением);
- стандартная библиотека и runtime для каждой цели;
- описания целей;
- документация версии;
- манифест выпуска: версии, хэши всех артефактов, версии закреплённых
  инструментов (компилятор C, NDK, MinGW).

## 4. Установка и сборка из исходников

- **Сборка компилятора** — из исходников закреплённым набором
  инструментов хоста (C++20, Р34); одна команда, без сети
  после получения зависимостей.
- **Раскладка установки:** `bin/` (компилятор, инструменты),
  `lib/<цель>/` (runtime), `stdlib/`, `targets/` (описания целей),
  `docs/`.
- **Кросс-компиляция** — указать цель; закреплённый компилятор C и SDK
  берутся из описания цели (`docs/policy/PLATFORMS.md`).

## 5. Откат

Выпуск, у которого после выхода найдена критическая ошибка, помечается
отозванным в CHANGELOG; следующий выпуск-исправление — с регрессионным
тестом.
