# Политика замеров

Что, как и на чём меряется до стабилизации v1.0. Основание — Р15, Р24,
Р32, постановка автора (раздел 14). Решения о языке и компиляторе
принимаются по представительным нагрузкам, а не только по
синтетическим (Р24).

## 1. Что меряется

| показатель | как | единица |
|---|---|---|
| время компиляции | чистая сборка эталонных проектов | с; строк/с |
| инкрементальная компиляция | правка тела функции; правка публичного интерфейса | мс до вердикта `check` и до готовой программы |
| память компилятора | пиковая память на эталонных проектах | МБ |
| производительность | нагрузки раздела 2 против эталона на C++ | медиана времени; отношение к эталону |
| размер программы | исполняемый файл и `.so` в профиле `release` | КБ |
| время запуска | до первого кадра или первой строки вывода | мс |
| выделения памяти | число и объём выделений за кадр и за задачу | шт., байт |
| цена FFI | вызов C-функции против вызова из C | нс на вызов |
| качество кода | отношение к эталону на C++ (`-O2`); размер горячих функций | отношение |
| цена гарантий | те же нагрузки с проверками и без (в `unsafe`-варианте) | % |
| работа с ИИ | токены на принятое изменение, успешность, циклы исправления на эталонном наборе (`GOAL.md`, раздел 2) | токены, % |

## 2. Нагрузки

**Представительные** — уровня будущих игровых систем; у каждой —
эталон на C++, написанный заново (не код VoxelRPG):

| нагрузка | что моделирует |
|---|---|
| greedy meshing вокселей | мир и чанки |
| генерация рельефа по шуму с ключевой случайностью | процедурная генерация, детерминизм |
| обход 100 тыс. сущностей по компонентам | ECS |
| A* на сетке | ИИ |
| широкая фаза столкновений AABB | физика |
| параллельный цикл системы задач | многопоточность |
| сериализация изменений мира | сохранение |
| разбор TOML и форматирование строк | контент и интерфейс |
| запись командного буфера Vulkan (заглушка драйвера) | рендер и FFI |
| сценарий кадровых аллокаций | память |

**Синтетические** — только для ловли регрессий отдельных механизмов;
решения по ним одним не принимаются.

## 3. Методика

- Прогрев, не меньше 10 прогонов, медиана и разброс; закрепление
  процессора, где возможно.
- Раскладка кода: время программы может зависеть от выравнивания кода
  сильнее, чем от сравниваемой правки (симуляция тел — в полтора раза
  от одного `-falign-loops`, у любого варианта). Варианты сравниваются
  по нескольким раскладкам каждого, по лучшей (`bench/det/measure.py`).
- Окружение записывается вместе с результатом: процессор, ОС, версии
  компиляторов, профиль.
- Результаты — файлы данных в `bench/results/` (внутренний материал,
  Р5), сравнение с базой — инструментом.
- **Пороги регрессии** (предложение; уточняются после первых замеров,
  Р15): производительность хуже базы больше чем на 5% или время
  компиляции больше чем на 10% — разбор причины до вливания.
- **База** записывается до стабилизации v1.0 и обновляется только
  осознанно, с записью причины.

## 4. Когда

| что | когда |
|---|---|
| быстрые замеры затронутого | при правке оптимизатора, бэкенда, runtime |
| полный набор | на каждой вехе `ROADMAP` и перед выпуском |
| работа с ИИ | этап замеров (v0.0) и ворота v0.1 |
