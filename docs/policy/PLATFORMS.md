# Платформы

Матрица целей и уровни поддержки. Основание — Р28; границы платформенного
кода — `docs/design/ARCHITECTURE.md`, раздел 6.

## 1. Первая волна

| цель | роль | инструменты (закрепляются в описании цели) | как проверяется |
|---|---|---|---|
| Linux x86-64 | хост разработки и цель | clang | весь набор тестов natively |
| Windows x86-64 | цель | кросс-сборка на Linux: clang + lld поверх MinGW-w64; MSVC — цель, проверяется отдельно | тесты под Wine; периодически — на настоящей Windows |
| Android arm64 | цель | Android NDK (clang); окно — SDLActivity из SDL3 (Р64) | тесты в эмуляторе пользовательского режима или эмуляторе Android; графика — на устройстве (Р64) |

## 2. Уровни поддержки

| уровень | что значит |
|---|---|
| 1 | собирается и проходит полный набор тестов перед каждым выпуском; блокирует выпуск |
| 2 | собирается; тесты — по возможности; не блокирует выпуск |
| 3 | архитектура допускает; не проверяется |

Сейчас: все три цели первой волны — уровень 1. Позже, отдельными
решениями: iOS и macOS arm64, Linux arm64, Windows arm64.

## 3. Допущения первой волны

64-битные адреса, порядок байтов от младшего, IEEE 754. Спецификация
вправе на них опираться; цель, нарушающая их, — отдельное решение с
пересмотром спецификации.

## 4. Состояние целей

| цель | описание (`compiler/driver/build.cpp`, `targets`) | порт runtime | проверка |
|---|---|---|---|
| Linux x86-64 | хост | `runtime/linux` | весь набор тестов |
| Windows x86-64 | `windows-x86_64`: clang + lld поверх MinGW-w64 | `runtime/windows` | проход `windows` в `tests/run.py`: набор исполнения в профилях debug и release под Wine; инструменты — `tools/setup/cross_windows.sh` |
| Android arm64 | `android-arm64`: clang из Android NDK r30, API 24, статическая программа; графическая — библиотека `dpl build --lib` в пакете APK с SDL3 (`examples/triangle/android/`) | `runtime/linux` (POSIX; bionic) | проход `android`: тот же набор под qemu-aarch64 (эмулятор пользовательского режима); инструменты — `tools/setup/cross_android.sh`; графика — сборка APK в сессии (сборки — ветка `apk-builds`, `tools/apk/publish.sh`), запуск на устройстве автора (Р64) |

На настоящей Windows и на устройстве Android программы ещё не
запускались (уровень 1 требует периодического запуска — до выпуска).
Программа командной строки для Android — статический исполняемый файл;
графическая — библиотека в пакете APK с `SDLActivity` из SDL3 (Р64,
v0.2, шаг 7). Статическая
сборка связывает bionic из NDK: его уведомления — обязанность
платформенных инструментов, не dpl (`docs/policy/LICENSING.md`,
раздел 3).

## 5. Как добавить цель

1. Описание цели: тройка, размеры, компилятор C и флаги, SDK.
2. Порт runtime: вход в программу, потоки, время, файлы, ловушки.
3. Модуль `platform` стандартной библиотеки.
4. Задача CI и прогон полного набора.
5. Документированный порядок отладки.

Фронтенд и Core IR при этом не меняются; если пришлось — это ошибка
границы, её исправляют отдельно.
