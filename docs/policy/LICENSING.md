# Политика лицензирования

Рабочие правила по модели лицензирования. Решение — `DECISIONS.md`,
Р39; обоснование и источники — `docs/research/LICENSING.md`. При
расхождении прав `DECISIONS.md`. Это правила проекта, а не текст
лицензии и не юридическая консультация.

## 1. Что действует сейчас

- **Этап 0** (Р39). Всё содержимое репозитория — под временной
  редакцией `LICENSE` «все права защищены» (Р4). Ничего не
  распространяется (Р5).
- **Этап 1** начинается к первой передаче двоичной поставки кому-либо
  вне автора. До неё нужны:
  - текст «Лицензии DPlang SDK» по спецификации
    `docs/research/LICENSING.md`, раздел 21, проверенный юристом;
  - до v1.0 — ещё договор о конфиденциальности с получателем (Р5).

  Передать сборку раньше, чем готов текст, нельзя.

## 2. Карта компонентов

Группа определяет условия, которые получит компонент на этапе 1.
Каталоги — по целевой раскладке (`docs/design/ARCHITECTURE.md`,
раздел 10).

| группа | каталоги | условия этапа 1 |
|---|---|---|
| toolchain | `compiler/` (кроме вставляемого в вывод), инструменты в поставке | Лицензия DPlang SDK |
| runtime-компоненты | `runtime/`, `stdlib/`, код, который компилятор вставляет в вывод (шаблоны генерации, проверки, ловушки, обёртки FFI) | норма «runtime-компоненты»: встраивание в любые программы без уведомлений и раскрытия исходников |
| официальные привязки | `bindings/vulkan/`, `bindings/sdl3/`, `bindings/jni/` | лицензия источника: Vulkan — Apache-2.0 OR MIT, SDL3 — Zlib, JNI — Apache-2.0 (заголовок AOSP) |
| генераторы привязок | `bindings/gen/` | как toolchain |
| образцы и шаблоны | `examples/`, шаблоны проектов | при публикации — 0BSD или MIT-0 |
| внутреннее | `tests/`, `bench/`, `tools/`, `.github/`, `.claude/`, `docs/` | не поставляется; «все права защищены» |

**Новый каталог** — сначала строка здесь, потом код. Код, который
компилятор вставляет в вывод, держится отдельно от остального
компилятора (файлы или каталог шаблонов). Тогда граница «toolchain —
runtime-компоненты» видна и в коде, и в тексте лицензии.

## 3. Сторонний код

**Каждый сторонний компонент** — строка в `docs/THIRD_PARTY.md` до
вливания: лицензия выражением SPDX, где используется, попадает ли в
программы пользователя.

| куда | допустимые лицензии | нельзя |
|---|---|---|
| toolchain | разрешительные без copyleft: MIT, BSD-2/3-Clause, ISC, Apache-2.0, Apache-2.0 WITH LLVM-exception, Zlib, BSL-1.0 | GPL, LGPL, MPL, AGPL, SSPL, BSL 1.1, «некоммерческие» и прочие ограничивающие |
| runtime-компоненты | только без обязательных уведомлений в двоичной форме: Apache-2.0 WITH LLVM-exception, Zlib, BSL-1.0, MIT-0, 0BSD, CC0-1.0, или собственный код | MIT, BSD, Apache-2.0 без исключения: их уведомление становится обязанностью каждой программы на DPlang |
| привязки | лицензия источника; источник с GPL не брать | `jni.h` из OpenJDK (GPL) — только AOSP |
| тесты, замеры | собственное; чужое — только с записью | код VoxelRPG — никогда |

- **Платформенные SDK и компиляторы C** (Android NDK, Windows SDK,
  MinGW-w64, GCC, MSVC) в поставку не включаются: пользователь ставит
  их сам.
- **Включение clang** — отдельное решение с уведомлением.
- **Уведомления, которых требуют сами платформенные инструменты** в
  программах (runtime MinGW-w64, musl в статических сборках Linux), —
  не обязанность перед DPlang. Документация поставки говорит о них
  прямо.

## 4. Вывод

- В сгенерированный C и другой вывод **не вставлять строк о лицензии**
  или копирайте DPlang. Они создают видимость, что код пользователя под
  лицензией DPlang.
- Если вывод содержит сторонний материал (официальные привязки), он
  несёт строку `SPDX-License-Identifier` источника.

## 5. Вклады и авторство

- **Внешних вкладов нет** (Р5, `docs/policy/ENGINEERING.md`, раздел 7).
  Патч, присланный посторонним, не вливается: сначала договор с правом
  перелицензирования (CLA) или договор об отчуждении (подрядчики) — после
  юриста.
- **Сессии ИИ** — инструмент автора: их код попадает в `main` только
  через PR, который вливает автор.
- **Следы человеческого вклада хранятся:**
  - решения автора — в `DECISIONS.md`;
  - постановки задач и ревью — в PR;
  - история — не переписывается.

  Охрана кода, созданного ИИ, зависит от творческого вклада человека
  (`docs/research/LICENSING.md`, раздел 17).
- **Закрытость** — часть защиты (режим секрета производства, ГК РФ,
  ст. 1465): правила `CLAUDE.md` («Защита и оригинальность») и
  `docs/policy/SECURITY.md` обязательны.

## 6. Имя и знак

- **До проверки у патентного поверенного** имя DPlang не используется
  публично: домены, логотип, публикации (`TODO.md`). Причина — риск
  смешения с D (dlang): `docs/research/LICENSING.md`, раздел 13.2.
- **Политика знака** (`TRADEMARKS.md`) — к первой внешней поставке, по
  разделу 13.3 исследования.

## 7. Когда что менять

| событие | что сделать |
|---|---|
| появился каталог или компонент | строка в разделе 2 |
| сторонний код или зависимость | строка в `docs/THIRD_PARTY.md` до вливания; проверка по разделу 3 |
| первая передача сборки вне автора | текст `LICENSE` этапа 1 (с юристом); уведомления третьих лиц в поставке; `TRADEMARKS.md`; до v1.0 — договор о конфиденциальности |
| первый внешний вклад | CLA или договор об отчуждении, `CONTRIBUTING.md` |
| решение по Р5 после v1.0 | путь этапа 2 (Р39): лицензия runtime-компонентов или всего toolchain |
