# Core IR: устройство, понижение, верификатор, интерпретатор

Описание устройства Core IR компилятора v0.1 (шаги 6–7,
`ROADMAP/IMPLEMENTATION.md`). Место в конвейере —
`docs/design/ARCHITECTURE.md`, раздел 1. Решения: Р36 (ловушка), Р43
(интерпретатор только для тестов), Р45 (память `List` и `str`). Смысл
программ задаёт спецификация `docs/spec/core.md`; IR его не расширяет.

```
проверенный AST (типы, преобразования, разрешённые имена)
  → понижение (compiler/ir/lower.cpp)
  → Core IR (compiler/ir/ir.h)
  → верификатор (compiler/ir/verify.cpp)
  → эталонный интерпретатор (compiler/ir/interp.cpp) — тесты
  → C-бэкенд — шаг 8
```

Core IR — внутренний контракт фронтенда и бэкендов (S1); наружу он не
поставляется, текстовая запись нестабильна (`dpl debug ir`).

## 1. Устройство

| сущность | что это |
|---|---|
| `Program` | функции всех модулей, таблица строк, номер `main` главного модуля |
| `Function` | имя `модуль.функция`, переменные (сначала параметры), тип результата, базовые блоки; вход — блок 0 |
| `Local` | переменная с типом и видом: `Param` — параметр-значение, `ParamRef` и `ParamMut` — параметры `&T` и `&mut T`, `Var` — переменная программы, `Temp` — временное |
| `Block` | инструкции и один терминатор |
| `Place` | место: переменная и путь проекций |
| `Operand` | `copy` места, `move` временного или константа |
| `Rvalue` | правая часть: операция над операндами |
| `Inst` | `Assign` (место = правая часть), `Eval` (правая часть ради действия), `Drop` (освободить переменную) |
| `Term` | `Jump`, `Branch`, `Return`, `Trap` (ловушка с сообщением), `Unreachable` |

**Проекции места:**
- `Field` — поле структуры;
- `Index` — элемент `List` или среза, байт `str`; номер берётся из
  переменной `i64`;
- `Payload` — данные варианта с номером;
- `Unwrap` — значение `?T`;
- `ResultValue` и `ResultError` — успех и ошибка `E!T`;
- `MapValue` — значение `Map` по ключу из переменной типа ключа; нет
  ключа — ловушка «key is not in the map» (Р54).

У параметра-ссылки место — значение вызывающего.

**Правые части:**
- `Use`, `Binary`, `Unary`, `Cast`;
- построение значений: `MakeStruct`, `MakeVariant`, `MakeList`,
  `MakeMap` (пустое отображение), `MakeSome`, `MakeNone`, `MakeOk`,
  `MakeErr`;
- `SliceOf` — срез `List` или среза; у `str` — копия части строки;
- `Call` — вызов функции с аргументами-значениями и аргументами-местами
  (`&`, `&mut`); `CallPtr` — то же через значение `extern fn(...)`
  первым операндом (Р61);
- `Intrinsic` — встроенная функция или метод (раздел 9 спецификации);
  у изменяющего метода `List` получатель — изменяемое место. Методы `Map`
  (Р54): `MapSet` (`m[k] = v`: вставка или замена), `MapRemove`,
  `MapClear` — с местом-получателем; `MapGet`, `MapContains`, `MapKeys`
  — с отображением первым операндом. `MapKeys` даёт ключи по
  возрастанию; `for k in &m` понижается в обход этого снимка. Ещё три —
  внутренние стандартной библиотеки (Р51, `docs/stdlib/README.md`):
  `ArgsLen`, `ArgAt` и `ReadFile`; у `ReadFile` место — строка для текста.
  `Probe` — проверки места (индексы, ключ `Map`) без чтения: ранняя
  ловушка места (порядок вычисления, ниже);
- проверки для ветвлений: `Tag` (номер варианта), `IsSome`, `IsOk`;
- структуры C (Р62): `Zero` — ноль типа (пропущенное поле `@c`),
  `AddrOf` — ссылка `&T` на место, приведение `ref_up` — `&S` в `&B` по
  общему началу; у `MakeStruct` объединения `variant` — заданное поле + 1;
  встроенные `CArenaMark` и `CArenaRelease` — арена C вокруг вызова.
  Проекция `Index` работает и у массива `[N]T`.

**Функции C** (Р59): `Function::is_extern` — функция без блоков, только
сигнатура и символ C (`c_name`); вызов — обычный `Call`. Библиотеки
`@link` — в `Program::links`. Интерпретатор функции C не вызывает:
программа с таким вызовом исполняется только сборкой (`dpl build`), в
`debug run` — внутренняя ошибка с подсказкой. В дампе — `extern fn
модуль.имя(…) = символ`.

**Вызов из C** (Р61): `Function::exported` — функция `@export`, `c_name`
— её символ C; в дампе — `export символ` после сигнатуры. Константа
`Fn` — адрес такой функции, значение типа `extern fn(...)`; в дампе —
`fn модуль.имя`. Интерпретатор хранит в нём номер функции, и `CallPtr`
вызывает её; указатель из C в интерпретатор не попадает: функции C он
не вызывает.

**Виды операций.**
- `canon` (`UnKind::Canon`) — NaN становится каноническим NaN, остальное
  не меняется (Р56). Понижение ставит его там, где плавающее значение
  становится видно. В функции класса D (`Function::det`, Р55):
  - на результат операции (арифметики, смены знака, приведения, `abs`,
    `min`, `max`) или вызова, который пишется в память — поле, элемент,
    место по ссылке: флаг `Inst::canon` у `Assign`, значение становится
    каноническим до записи, место вычисляется один раз; в дампе —
    `место = canon(правая часть)`;
  - на операнд — копией во временном, — когда значение переменной,
    параметра или временного уходит в литерал, в память, во встроенную
    функцию или метод (кроме `abs`, `min`, `max`), в функцию вне класса D,
    в `str` и по ссылке.

  Вне класса D — флаг `Inst::canon` у `Assign`, которое принимает
  плавающий результат вызова функции класса D: результат выходит из
  класса D. Возврат внутри класса D канона не несёт. Обёртка `@export`
  функции класса D отдаёт C канонический результат; интерпретатор,
  вызывая её по указателю (`CallPtr`), делает так же.

  Переменная, параметр-значение и временное с плавающим значением
  целиком могут держать NaN с битами процессора: их значение без канона
  идёт только в арифметику, сравнения, приведения, в аргументы функций
  класса D и в их результат для кода класса D. Память — только
  канонический NaN. В дампе заголовок функции класса D кончается словом
  `det`.
- `add sub mul div rem` над целыми — с проверкой переполнения и деления
  на ноль.
- `add.wrap sub.wrap mul.wrap` — по модулю 2^N.
- `concat` — склейка `str`.
- Приведения:
  - `widen` — неявное расширение без потерь;
  - `check` — `T(x)`, значение вне `T` — ловушка;
  - `wrap` — `T.wrap(x)`;
  - `str` — `str(x)`.

## 2. Смысл

- **Ловушки внутри операций.** Проверки — часть смысла операций и
  проекций, отдельных инструкций проверки нет. Переполнение, деление на
  ноль, сдвиг вне ширины, индекс и срез вне границ, неверное
  преобразование — ловушка (Р36, спецификация, раздел 10). Поэтому
  в IR нет неопределённого поведения.
- **Память значений (Р45).**
  - `copy` копирует значение целиком.
  - `move` забирает значение временного (или его части) и оставляет
    временное пустым. Забирать можно только у временных.
  - `Assign` освобождает старое значение места после вычисления правой
    части.
  - `Drop` освобождает переменную и обнуляет её. Он идемпотентен:
    освободить пустое значение можно.
  - Освобождать нужно только значения с памятью — где внутри есть `List`
    или `str` (`needs_drop`).
- **Ссылки.** Аргумент `&x` и `&mut x` передаёт место; значение по
  ссылке читается копией (Р44), поэтому ссылка не переживает вызов.
- **Ветвление `Branch`** — по операнду `bool`. `Unreachable` ставится
  там, куда исполнение не приходит по доказанному проверкой программы:
  конец функции с результатом (E0504), выход из полного `match` (E0415).

## 3. Понижение

Вход — AST, прошедший проверку без ошибок: понижение берёт типы,
неявные преобразования (`Expr::conv`), разрешённые имена и вызовы из
пометок проверки. Каждая функция понижается отдельно (`FnLower`).

**Выражения.** Выражение даёт операнд: место (`copy`), константу или
временное (`move`). Неявное преобразование — отдельная правая часть:
`widen`, `slice` для `List → []T`, `some`, `ok`.

**Время жизни.**
- Временное освобождается в конце инструкции исходника, в которой
  создано: его `Drop` стоит в области этой инструкции.
- Переменная `let` и `var` освобождается в конце своего блока; связанное
  образцом имя — в конце ветви.
- Параметр-значение освобождается при выходе из функции.

**Выходы из областей.** Конец блока, `return`, `break`, `continue`,
`fail` и ошибка `try` выполняют очистку каждой покидаемой области:
- `Drop` её переменных и тела `defer` в обратном порядке;
- тело `defer` понижается заново на каждом выходе и вычисляется со
  значениями переменных на момент выхода (`stmt.defer`);
- тело `errdefer` (`stmt.errdefer`) — только на выходе с ошибкой: `fail`
  и ошибка `try`. У `return` значения `E!T` без обёртки `ok` перед телом
  стоит ветвление по `is_ok` результата; конец блока, `break`,
  `continue` и прочие `return` его пропускают.

**Разбор** `let S { f, g: x } = v`: значение вычисляется во временное,
каждое названное поле — `Assign` новой переменной (`move` у временного,
`copy` у места). Линейность — проверка `sema` (`ffi.linear`): в IR
линейное значение — обычная структура.

Переменная попадает в очистку после записи значения. Поэтому выход
через `try` в её же начальном значении её не освобождает.

**Порядок вычисления — слева направо** (`expr.order`).
- Операнды, аргументы, элементы списка и поля литерала структуры
  вычисляются в порядке записи. В правой части поля стоят в порядке
  объявления, недостающие — значениями по умолчанию.
- Если правее места стоит выражение с действием (вызов функции или
  изменяющий метод), место читается заранее во временное
  (`stabilize`). Поэтому вызов не меняет уже прочитанный операнд.
- Место с проверкой — индекс или ключ `Map` — само читается в последней
  инструкции выражения. Если правее операнд может дать ловушку
  (`may_trap`: арифметика и сдвиги целых, преобразование к целому, индекс,
  вызов, `try`), место проверяется раньше (`force`): скаляр читается во
  временное, остальное — `Probe` без копии. Выход `try` с ошибкой —
  тоже ловушка для места левее. Так же — место присваивания, получатель
  метода, основа индекса и среза, аргумент `&место`, субъект `match` и
  `_ = место`: в `xs[9] + 1 / z` ловушка индекса — раньше деления. Если
  выражение правее меняет корень такого места (`xs[1] = grow(&mut xs)`),
  проверка остаётся при записи — вопрос автору (`TODO.md`).
- Вид — срез, ссылка `&x` для параметра `&T` или адрес `&T` для C —
  указывает в чужую память и строится над самим местом, без копии: вид
  левее действия, которое меняет его место, отвергает проверка типов
  (E0502, Р66; `compiler/sema/access.cpp`), так же — действие в
  границах среза и в индексе вида. `&mut x` — место на время вызова.
  Корни, которые меняет действие правее (`changed`: `&mut` и получатель
  изменяющего метода), понижение считает только для порядка проверок
  места (`Probe`).
  - Нижняя граница среза читается до верхней; вызываемое по указателю
    `extern fn` — до аргументов.
  - Из вида не забирают (`move`): элемент среза — чужого списка, его
    значение копируется (`place_of`).
- В присваивании место (его индексы) вычисляется до значения; в
  `x op= e` значение `x` читается до `e`.

**Ветвления.**
- `&&` и `||` — короткое вычисление переходами.
- `a ?? b` — `b` вычисляется, только если у `a` нет значения.
- `if let v = e` — проверка `IsSome` и копия значения.
- `match` — цепочка проверок по порядку ветвей. Образец проверяется по
  частям: номер варианта (`Tag`), `IsSome`, `IsOk`, равенство литералу.
  При несовпадении — переход к следующей ветви; `p | q` пробует
  альтернативы по очереди. Имена связываются копиями только после
  совпадения всего образца. За последней ветвью — `Unreachable`.

**Циклы.**
- `while` — блок условия, тело, переход назад; `while true` — без
  проверки.
- `for i in a..b` — `a` и `b` вычисляются один раз. Сравнение
  `i < b` — до тела, поэтому шаг `i + 1` (`add.wrap`) не переполняется.
- `for x in &xs` — счётчик `k` и `len(xs)` на каждом шаге. Переменная
  цикла — место `xs[k]`, а не копия: изменение `xs` в теле не оставляет
  висячей ссылки.
- `parallel for` в v0.1 понижается как `for` (`stmt.for`).

**Ошибки.**
- `try e` — `IsOk`. При ошибке: `err` той же ошибки в результат
  функции, очистка всех областей, `Return`.
- `fail e` — то же без проверки.
- Конец тела функции без результата и функции `E!void` — успешный
  возврат.
- `assert(c)` — ветвление на `Trap "assertion failed"`.

**Недостижимые блоки** после понижения удаляются (`prune`), номера
блоков сжимаются.

## 4. Верификатор

`verify` проверяет каждую функцию программы. Нарушение — внутренняя
ошибка компилятора (код 3), а не диагностика пользователя. `debug ir`,
`debug run`, `debug c` и `dpfuzz check` запускают его на каждой
понижаемой программе.

Инварианты:
- виды переменных: параметры — первыми, ровно `param_count`; у каждой
  переменной есть тип; есть тип результата и хотя бы один блок;
- место подходит к типу переменной (`place_type`); номер индекса —
  переменная `i64`; байт `str` — только последней проекцией;
- писать можно только в `Var`, `Temp` и `ParamMut` и не через элемент
  среза или байт строки. То же требование — к получателю изменяющего
  метода `List` и к аргументу `&mut`;
- `move` — только из временного и только там, где значение сохраняется:
  запись, аргумент-значение, построение значения, возврат, значения
  `push` и `insert`;
- константа совпадает со своим типом; строка есть в таблице; константа
  `Fn` — функция `@export` с сигнатурой типа;
- типы операндов и результата у каждой операции: арифметика над числами
  одного типа, целочисленные операции над целыми, сравнение — не над
  `E!T`, `concat` над `str`;
- приведения: `widen` — только без потерь, `check` и `wrap` — между
  разными числовыми и целыми типами, `str` — из числа и `bool`;
- построение значений: число и типы частей по объявлению;
- вызов: функция существует, число аргументов, режим каждого совпадает с
  параметром, типы равны; у `CallPtr` — то же по сигнатуре типа
  вызываемого значения;
- встроенное: число и типы операндов и результата; получатель-место —
  только у изменяющих методов `List` и `Map`, у `ReadFile` (изменяемое
  место `str`) и у `Probe`;
- `Drop` — только переменной целиком, не ссылки и только с памятью;
- переходы — в существующие блоки; условие — `bool`; `Return` со
  значением тогда и только тогда, когда результат не `void`, и тип
  значения равен типу результата.

## 5. Интерпретатор

Эталонный интерпретатор (`run`) исполняет Core IR по его смыслу. Он
только для тестов (Р43): оракул различающих тестов с C-бэкендом
(шаг 8) и проверка самого понижения.

- **Значения.** Значение хранит свои части целиком: копия глубокая,
  `move` забирает. Срез — представление: список и границы. Пустое
  значение — освобождённое или ещё не записанное.
- **Строгость.** Строже бэкенда — так проверяется и понижение. Внутренняя
  ошибка (код 3), а не ловушка:
  - чтение пустого значения;
  - переменная с памятью, которая не освобождена к возврату (утечка);
  - проекция не того варианта или пустого `?T`;
  - достигнутый `Unreachable`.
- **Кадры.** Кадры вызовов лежат в своём стеке, а не в стеке C++.
  Глубина вызовов ограничена (2^15 кадров), сверх неё — ловушка
  «stack overflow».
- **Память.** Список или строка длиннее 2^26 элементов (байтов) —
  ловушка «out of memory». Это предел интерпретатора; у runtime свой
  (`docs/runtime/README.md`, раздел 4).
- **Вывод.** `print` и `println` — в stdout, `eprintln` — в stderr.
  Перед записью в stderr stdout сбрасывается, поэтому порядок строк
  сохраняется.
- **Завершение** (спецификация, `trap.exit`):

  | исход | stderr | код выхода |
  |---|---|---|
  | `main` вернулась | — | 0 |
  | `main` вернула ошибку | `error: main failed with E.V` | 1 |
  | ловушка | `файл:строка:столбец: trap: сообщение` | 101 |

  Ловушка останавливает программу сразу: `defer` не выполняются.

## 6. Текстовая запись

`dpl debug ir программа.dpm` печатает IR всех функций программы:
модули — в порядке зависимостей, функции — в порядке объявления. Формат служит тестам и отладке и не
стабилен.

```
fn calls.bump(%0 n: &mut i32) i32
  tmp %1: i32
bb0:
  %0 = add copy %0, 1:i32  @5:5
  %1 = copy %0  @6:5
  return move %1  @6:5
```

- Заголовок — параметры с режимами и результат. Дальше — переменные
  (`var`) и временные (`tmp`).
- Место — `%N` с проекциями: `.поле`, `[%i]`, `.Вариант.k`, `.some`,
  `.ok`, `.err`.
- Константа — `значение:тип`, строка — в кавычках JSON.
- `@строка:столбец` — позиция в исходнике, от которой инструкция
  получена; по ней ловушка называет место.

## 7. Тесты

| набор или проход | что проверяет |
|---|---|
| `tests/ir/` | золотые дампы `debug ir`: память значений, ветвления и циклы с `defer`, `match`, `try` и `fail`, ленивые `??` и `&&`, режимы аргументов и порядок вычисления |
| `tests/run/` | вывод и код выхода `debug run`: числа, строки, списки, структуры и перечисления, ошибки, `defer`, ссылки, порядок вычисления, модули; ловушки — по файлу на каждую; `main` (E0322, ошибка из `main`) |
| проход `verify` | верификатор на каждой программе `.dpm` всех наборов: программа с ошибками — код 1, без них — 0; внутренняя ошибка — сбой |
| проход `native` | программы `tests/run/` через C-бэкенд: вывод нативной программы совпадает с выводом интерпретатора (`docs/compiler/backend_c.md`, раздел 7) |
| `tests/fuzz/check.args` | `dpfuzz check`: испорченные входы разбираются и проверяются, а программы без ошибок понижаются и проходят верификатор |

Исполнитель и форматы — `docs/compiler/README.md`, раздел «Тесты».
