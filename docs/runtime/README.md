# Runtime dpl

Описание устройства runtime v0.1 (`ROADMAP/IMPLEMENTATION.md`,
шаги 8–9). Runtime — библиотека на C11, с которой собирается
сгенерированный C (`docs/compiler/backend_c.md`). Тексты ловушек и
запись значений совпадают с эталонным интерпретатором
(`docs/ir/README.md`, раздел 5): это сверяют различающие тесты.

## 1. Раскладка

| файл | что |
|---|---|
| `runtime/core/dp_rt.h` | контракт с бэкендом: типы, проверенная арифметика (встраиваемая), объявления |
| `runtime/core/dp_rt.c` | ядро без зависимости от платформы: ловушки, память, преобразования, строки, запись плавающих, вывод, проверки индексов |
| `runtime/linux/dp_entry.c` | порт Linux: поток `main`, код выхода, открытие файла |
| `runtime/windows/dp_entry.c` | порт Windows x86-64 (MinGW-w64): то же, двоичный вывод, аргументы и пути в UTF-8 |

Android arm64 пользуется портом `runtime/linux`: bionic даёт POSIX
threads и `fopen`, как glibc.

Порты под другие цели (`docs/policy/PLATFORMS.md`) заменяют только
каталог платформы: вход `dp_run`, `dp_run_test` и `dp_os_open_read`.
Зависимостей, кроме библиотеки C, нет: под Linux — ещё POSIX threads,
под Windows — Win32 (`kernel32`, `shell32`).

## 2. Требования

- **C11 без неопределённого поведения**, без предупреждений с `-Wall
  -Wextra -Wpedantic -Werror` у gcc и clang. Флаги — как у
  сгенерированного C (`docs/compiler/backend_c.md`, раздел 2).
- **Плавающие без лишней точности**: `FLT_EVAL_METHOD == 0`, иначе
  `dp_rt.h` не собирается (`#error`).
- **Тексты сообщений — по-английски** (Р47), те же, что у интерпретатора.

## 3. Ловушки (Р36, `trap.def`)

`dp_trap(loc, msg)` и `dp_trapf(loc, fmt, …)` делают одно и то же:

1. сбрасывают stdout;
2. пишут в stderr `loc: trap: msg`;
3. завершают процесс `_Exit(101)` — без `atexit` и без `defer`.

`loc` — строка `"файл:строка:столбец"` от бэкенда. Если места нет
(`NULL` или пусто), пишется только `trap: msg`.

`dp_unreachable` — не ловушка программы, а внутренняя ошибка: исполнение
пришло туда, куда по проверке программы прийти не может. Сообщение
`internal error: …`, код выхода 3.

| проверка | функции | сообщение |
|---|---|---|
| целые (`trap.int`) | `dp_sadd` … `dp_urem`, `dp_shift_count_*` | `integer overflow in '+' on 'i32'`, `division by zero`, `shift count N is out of range for 'T'` |
| проверяемая арифметика (Р53) | `dp_try_sadd` … `dp_try_udiv` — без ловушки: `false`, если вне типа или делитель 0 | — |
| преобразования (`trap.convert`) | `dp_cast_*` | `value V does not fit 'T'`, `NaN does not fit 'T'` |
| индексы (`trap.index`) | `dp_check_index`, `dp_check_slice`, `dp_check_insert`, `dp_str_slice` | `index I is out of bounds for length N`, `slice A..B is out of bounds for length N`, `insert position I is out of bounds for length N`, `slice A..B of a str does not fall on character boundaries` |
| встроенное (`trap.builtin`) | `dp_check_repeat`; `split` и `assert` — в сгенерированном коде | `repeat count N is negative`, `split separator is empty`, `assertion failed` |
| память (`trap.memory`) | `dp_alloc`, `dp_realloc`, `DP_CALL_CHECK` | `out of memory`, `stack overflow: calls are nested too deeply` |

## 4. Пределы (`trap.memory`)

| предел | значение | как |
|---|---|---|
| один буфер `List` или `str` | 2^31 байт (`DP_MAX_BYTES`) | больше или нет памяти у `malloc` — ловушка `out of memory` |
| глубина вызовов | 2^15 кадров (`DP_MAX_DEPTH`) — как у интерпретатора | счётчик `dp_depth` — у каждого потока свой (`_Thread_local`); вызов сверх предела — ловушка `stack overflow` в месте вызова |
| стек потока `main` и рабочего потока пула | 256 МБ | предел глубины срабатывает раньше, чем кончается стек |

Предел буфера у интерпретатора другой: 2^26 элементов или байтов
(`docs/ir/README.md`, раздел 5). `trap.memory` оставляет пределы
реализации.

**Счётчик выделений (Р68).** `dp_alloc` и `dp_realloc` считают вызовы,
которые выделили память, и их байты. Счётчики атомарные (`relaxed`):
библиотеку `--lib` могут звать из нескольких потоков C.

- `dp_alloc_stats(&count, &bytes)` отдаёт значения счётчиков.
- Если задана переменная окружения `DPL_ALLOC_STATS`, порт после входа
  программы или теста пишет в stderr строку `dpl: N allocations, B bytes`
  (`dp_alloc_report`).

**Пул (Р67).** `dp_hnd` — хэндл: номер слота и поколение `u32`.
`dp_pool` — служебная часть `Pool[T]`; значения хранит сгенерированный
тип.

- `dp_pool_take` занимает наименьший свободный слот (минимальная куча
  номеров) или новый; ёмкость растёт вдвое.
- `dp_pool_release` освобождает слот: поколение +1. На пределе
  `DP_POOL_GEN_LIMIT` (2^32 − 1) слот в кучу не возвращается — он
  выведен из оборота.
- `dp_pool_clear` освобождает все живые слоты.
- `dp_pool_valid(p, h)` — хэндл не устарел.
- Ещё: `dp_pool_grow`, `dp_pool_copy`, `dp_pool_drop`.

Тест — `unit_pool` в `tests/runtime/rt_test.c`: туда же входит вывод слота
из оборота, которого не достичь программой за разумное время.

Счётчик выделений нужен для тестов и замеров кадровой памяти: после прогрева временные
данные кадра, очищаемые `clear()`, не выделяют памяти. Пример —
1000 кадров по 100 `push` после `clear()` дают 7 выделений, все при
прогреве.

## 5. Значения

- **`dp_str`** — `{ptr, len}`: байты UTF-8, без нуля в конце; владеет
  памятью; пустая строка — `{NULL, 0}`. `DP_STR_LIT` — представление
  строки программы без копии: только для чтения. Сохранить её можно
  только копией `dp_str_own`.
- **Память** — `malloc`, `realloc`, `free` за `dp_alloc`, `dp_realloc`,
  `dp_free`. Запрос нуля элементов даёт `NULL`.
- **Сравнение строк** — по байтам без знака (`dp_str_lt`).
- **Строки на границе C** (Р59) — `dp_str_to_c` (копия с нулём в конце;
  байт 0 внутри — ловушка) и `dp_str_from_c` (копия строки C; NULL и не
  UTF-8 — ловушка). Строку, которую C передал функции `@export` (Р61),
  копирует `dp_str_from_c_arg`: в сообщении ловушки — параметр и функция.
- **Арена C вызова** (Р62) — `dp_carena_mark`, `dp_carena_alloc`,
  `dp_carena_str`, `dp_carena_release`: строки и массивы заимствующих
  структур живут от отметки до конца вызова; освобождение — всех блоков
  после отметки.
- **Библиотека для хоста C** (`dpl build --lib`, Р61): те же `dp_rt.c` и
  порт цели в архиве; `dp_run` и поток с большим стеком хост не
  использует — функции dpl идут на стеке потока хоста.
- **Канонический NaN** класса D (Р56) — `dp_canon_f64` и `dp_canon_f32`:
  NaN становится положительным тихим без полезной нагрузки
  (`0x7ff8000000000000` и `0x7fc00000`), остальное — как есть.
- **Хэш ключа `Map`** (Р54) — `dp_hash_u64` (перемешивание целого) и
  `dp_hash_str` (FNV-1a), без случайной соли. Обход `Map` — по
  возрастанию ключа, хэш нужен только для поиска
  (`docs/compiler/backend_c.md`, раздел 4).
- **Запись плавающего** (`dp_str_from_f`, Р48) — тот же алгоритм, что
  `compiler/support/format.h`: кратчайшая запись, которая читается
  обратно в то же число (у `f32` — в то же `f32`). Обычная форма — при
  десятичном порядке от −4 до 15, без хвоста `.0`; иначе
  экспоненциальная (`docs/spec/core.md`, expr.convert).
  - Для каждой длины p от 1 до 17 цифр проверяются правильно округлённая
    p-значная запись (`%.*e`) и её соседи на единицу последнего разряда.
    Сосед нужен у степеней двойки: там промежуток округления
    несимметричен, и обратно читается только он (`2^-1017` —
    `7.120236347223045e-307`, а не 17 цифр).
  - Обратно запись читает `strtod`, у `f32` — `strtof`: без двойного
    округления через `double`.
  - Из двух одинаково близких p-значных записей `%.*e` даёт запись с
    чётной последней цифрой — так её и определяет спецификация.
- **`f64` → `f32`** (`dp_cast_f64_to_f32`, `trap.convert`) — округление к
  ближайшему по IEEE 754. Конечное значение больше наибольшего `f32` —
  ловушка. Преобразование не опирается на поведение C вне диапазона
  `float`.

## 6. Вывод

- `print` и `println` пишут в stdout. Он буферизован библиотекой C.
- Вывод — байты как есть на всех целях: под Windows stdout и stderr
  переводятся в двоичный режим (`\n` не становится `\r\n`), кодовая
  страница консоли — UTF-8.
- `eprintln` сначала сбрасывает stdout, потом пишет в stderr: строки
  выходят в порядке программы.
- Ловушка и завершение тоже сбрасывают stdout: напечатанное до них
  сохраняется.

**`parallel for` (Р69).** `dp_parallel_for(n, body, env)` зовёт
`body(env, k)` для `k` из `[0, n)` в пуле потоков.
- **Пул.** Рабочие потоки запускаются при первом цикле и живут до конца
  программы; первый цикл начинается, когда все они дошли до ожидания
  заданий, — выход из программы не застаёт поток на старте. Их число —
  `DPL_THREADS` или число процессоров (не больше 64), вызывающий поток
  работает наравне с ними. Потоки и синхронизация — у платформы
  (`dp_sys_*`: pthreads под Linux и Android, Win32 под Windows).
- **Части.** Итерации раздаются частями по возрастанию `k` (около восьми
  частей на поток); часть исполняет один поток по порядку.
- **Вывод.** `print`, `println`, `eprintln` в итерации пишут в буфер её
  части; после цикла буферы выходят по порядку частей. Вывод побайтно
  равен исполнению по очереди.
- **Ловушка.** Ловушка в итерации запоминается (наименьшая `k`) и
  прерывает её часть (`longjmp`), мьютексы, захваченные прерванной
  итерацией, отпускаются; части дальше неё не начинаются, итерации до
  неё доделываются. После цикла выходит вывод итераций до
  ловушки, затем ловушка — как при исполнении по очереди.
- **По очереди** — вложенный цикл (в итерации внешнего), одна итерация
  и пул из одного потока (`DPL_THREADS=1`).

**Конкурентные типы и задачи** (Р70; `docs/spec/core.md`,
type.concurrent и stmt.tasks). Значения не копируются (E0518): живут в
своём месте, задачи получают их по ссылке.
- **`Atomic[T]`** — целое или `bool` прямо в месте (тип C — `T`);
  операции — встроенные `__atomic_*` компилятора с последовательной
  согласованностью; `add` и `sub` проверяют переполнение по старому
  значению.
- **`Mutex[T]`** — `{dp_mtx mx; T v;}`. `dp_mtx_lock(m, loc)`:
  повторный захват тем же потоком — ловушка «mutex is already locked by
  this thread»; захват — атомарная замена владельца `NULL` на поток,
  занят — короткое ожидание без сна, затем сон на условии под мьютексом
  платформы, в счёте взаимной блокировки. `dp_mtx_unlock` пишет `NULL`
  и, если спящие есть, будит одного и снимает его со счёта (сигнал —
  после отпускания мьютекса платформы); не получивший захват засыпает
  снова. Счётчик `waiters` и порядок «запись, затем чтение» у обеих
  сторон не дают потерять побудку. `dp_mtx_drop`. Захваченные потоком
  мьютексы — стек (`held_up`): итерация `parallel for`, прерванная
  ловушкой, отпускает свои. Цена — на уровне мьютекса платформы
  (t24 и нагрузочная программа, 31 октября).
- **`Channel[T]`** — `{dp_chan* c; T* buf;}`, кольцо на `n` мест:
  `dp_chan` (мьютекс, два условия, голова, длина, признак закрытия) и
  буфер `T` в сгенерированном коде. `send` ждёт места, `recv` ждёт
  значения или закрытия. Отправка в закрытый и повторное закрытие —
  ловушки.
- **Блок задач.** `dp_tasks_begin()` открывает группу (стек групп — у
  потока), `dp_spawn(body, env, size, loc)` копирует окружение и
  запускает задачу в своём потоке (стек — как у main),
  `dp_tasks_end(loc)` ждёт задачи группы. Вывод задачи — в её буфер;
  конец блока выводит буферы по порядку запуска — в вывод потока (у
  задачи — в её буфер). Ловушка в задаче выводит её буфер, затем
  ловушку; вывод других задач теряется. `parallel for` в задаче идёт по
  очереди: пул — у main.
- **Взаимная блокировка.** Runtime считает живые потоки dpl (main,
  задачи, рабочие пула в задании: `dp_dl_enter`, `dp_dl_exit`) и ждущие:
  канала, мьютекса, конца блока задач, рабочих пула (main после своих
  частей `parallel for`). Ждут все — ловушка «deadlock: every thread is
  waiting» с местом последнего ждущего; у ожидания рабочих места нет —
  остаётся место ждущей итерации. Будящий снимает ждущих со счёта сам,
  поэтому ложной ловушки, пока разбуженный ещё не проснулся, нет.
- **Вызов из потока C** (П7) — после v1.0; до того функции dpl
  вызываются из одного потока за раз (Р61).

## 7. Вход и код выхода (`trap.exit`)

Сгенерированный `main(argc, argv)` C запоминает аргументы
(`dp_set_args`, для `os.args`) и вызывает `dp_run(dp_entry)`. Под
Windows `dp_run` берёт их заново из командной строки UTF-16 и
переводит в UTF-8: `argv` MinGW — в кодовой странице ANSI. У сборки
тестов (`dpl test`, Р50) вход другой: `программа N` исполняет тест
номер N через `dp_run_test`, аргументов программы у теста нет, а ошибка
пишется как `error: test failed with E.V`.

1. `dp_run` обнуляет `dp_depth` и исполняет `dp_entry` в потоке со
   стеком 256 МБ (Linux — `pthread`, Windows — `CreateThread` с
   резервом стека). Если поток создать нельзя, `dp_entry` вызывается
   прямо.
2. После возврата stdout сбрасывается.
3. Код выхода:

| исход | stderr | код |
|---|---|---|
| `main` вернулась | — | 0 |
| `main` вернула ошибку `E.V` | `error: main failed with E.V` | 1 |
| ловушка | `файл:строка:столбец: trap: сообщение` | 101 |
| внутренняя ошибка | `internal error: …` | 3 |

## 8. Аргументы и файлы (Р51)

Внутренние функции модуля `os` (`docs/stdlib/README.md`):
- `dp_args_len`, `dp_arg(i)` — аргументы без имени программы; `dp_arg`
  вне границ — ловушка индекса;
- `dp_read_file(path, &out)` — файл целиком. Файл открывает порт
  (`dp_os_open_read`): путь — UTF-8, под Windows — через `_wfopen`.
  - Код результата: 0 — прочитан; 1 — нет файла (`ENOENT`, `ENOTDIR`,
    байт 0 в пути); 2 — нет прав (`EACCES`, `EPERM`); 3 — не UTF-8; 4 —
    другое (например, каталог: под Windows его отказ `EACCES` тоже
    становится 4).
  - При ошибке `out` не меняется. При успехе прежнее значение
    освобождается.
- Файлы `os.File` (Р71): `dp_file_create(path)`, `dp_file_open(path)` —
  `FILE*` через порт (`dp_os_open_write`, `dp_os_open_read`; под Windows
  — `_wfopen` с путём UTF-16) в таблице открытых файлов под мьютексом.
  Дескриптор — `(поколение << 32) | (слот + 1)`; ошибка открытия — минус
  код. `dp_file_write(f, ptr, len)`, `dp_file_read(f, &ptr, &len, &cap, n)`
  (дописывает в `List[u8]`), `dp_file_close(f)` сначала проверяют
  дескриптор: неоткрытый, закрытый или собранный литералом вне `os` —
  ловушка `file is not open`. Коды: 1 — нет файла, 2 — нет прав, 4 —
  другое, 5 — места нет (`ENOSPC`, `EDQUOT`, `EFBIG`); ошибка, отложенная
  буфером `FILE`, приходит из `fclose`.
- Биты плавающих (Р71): `dp_f64_bits`, `dp_f64_from_bits`,
  `dp_f32_bits`, `dp_f32_from_bits` — `memcpy` в целое той же ширины и
  обратно.
  - Файл больше `DP_MAX_BYTES` — ловушка `out of memory`.
- `dp_utf8_valid` — строгая проверка UTF-8, как у лексера: без
  обрезанных, избыточных записей, суррогатов и символов больше U+10FFFF.

## 9. Проверки

Обе проверки — в `tests/run.py`; runtime собирается с ASan и UBSan, если
компилятор C (`$CC` или `cc`) их умеет.

- **Проход `native`.** Сгенерированная программа каждого теста набора
  `run` собирается с runtime, а её вывод сверяется с интерпретатором
  (`docs/compiler/backend_c.md`, раздел 7). Так проверяются ловушки,
  пределы, запись значений и код выхода в связке с бэкендом.
- **Проход `runtime`** (`tests/runtime.py`, `tests/runtime/rt_test.c`) —
  функции runtime по одной:
  - `runtime/unit` — граничные значения без ловушек: проверенная
    арифметика у краёв типов, сдвиги, преобразования, строки, разбор
    целого, поиск, классы байтов, индексы, память. Утечки ловит ASan;
  - `runtime/trap/ИМЯ` — каждая ловушка отдельным запуском: точный
    текст в stderr, вывод до неё, код 101. Сюда же входят: ловушка без
    места, длинное сообщение (обрезается до 511 байт), внутренняя ошибка
    `dp_unreachable` с кодом 3, порядок строк stdout и stderr;
  - `runtime/run/ИМЯ` — вход `dp_run`: код 0, ошибка `main` (код 1),
    ловушка в потоке `main`, предел глубины на 2^15 кадров;
  - `runtime/floats` — запись плавающих против образца. Образец
    вычисляется в `tests/runtime.py` по определению из спецификации,
    точной арифметикой, без `printf` и `strtod`; у `f64` он совпадает с
    `repr` Python. Значения: все степени двойки `f64` и `f32`, особые и
    случайные. Программа из них исполняется интерпретатором (запись
    компилятора, `format.h`) и нативно (runtime).
