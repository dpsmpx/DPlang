# Карта документации

Документация — часть инженерной системы (Р3): по ней можно понять
архитектуру, найти компонент, понять контракт, внести изменение,
запустить проверки и истолковать результат.

## 1. С чего начать

| задача | куда смотреть |
|---|---|
| понять, зачем язык и куда он идёт | `direction/VISION.md`, затем `direction/GOAL.md` |
| узнать, что решено и почему | `direction/DECISIONS.md` (источник истины) |
| узнать, что ещё не решено | `direction/OPEN_DECISIONS.md` |
| понять архитектуру toolchain | `design/ARCHITECTURE.md` |
| понять устройство языка | `design/LANGUAGE.md`, затем спецификация (`spec/`, появится в v0.1) |
| найти компонент в коде | `design/ARCHITECTURE.md`, раздел 10; затем `compiler/`, `ir/`, `runtime/`, `stdlib/` (появятся с кодом) |
| понять контракт для потребителя | `policy/COMPATIBILITY.md`, `policy/DETERMINISM.md`, спецификация |
| внести изменение | `../CLAUDE.md` (обязательный минимум), `policy/ENGINEERING.md` |
| запустить проверки и прочитать результат | `../tools/check/run.sh`, `policy/TESTING.md` (разделы 5–6) |
| понять, что делать дальше | `../ROADMAP/ROADMAP.md`, `../ROADMAP/IMPLEMENTATION.md`, `../TODO.md` |
| понять, когда v1.0 | `direction/DEFINITION_OF_DONE.md` |

## 2. Каталоги

| каталог | что в нём | статус |
|---|---|---|
| `direction/` | видение, цели, решения, открытые решения, Definition of Done, риски | нормативно |
| `design/` | проект архитектуры и языка до спецификации | проект; при реализации переходит в `spec/` и описание устройства |
| `policy/` | правила: совместимость, детерминизм, тесты, замеры, платформы, инженерия, безопасность, выпуск | нормативно |
| `research/` | исследования с источниками | материал, не решения |
| `audits/` | аудиты на дату | срез на дату |
| `spec/` | спецификация языка | появится в v0.1 |
| `compiler/`, `ir/`, `runtime/`, `stdlib/` | описание устройства | появятся с кодом |
| `archive/` | отработанное, с описью | появится с первым архивным документом |

Корень репозитория: `README.md`, `CLAUDE.md`, `TODO.md`, `LICENSE`;
`ROADMAP/` — планы; `docs/CHANGELOG.md` — вехи; `docs/THIRD_PARTY.md` —
сторонние компоненты.

## 3. Порядок источников истины

`direction/DECISIONS.md` → `../CLAUDE.md` → `../ROADMAP/` → `../TODO.md`
→ спецификация и описание устройства → `design/` → `research/`,
`audits/`, `archive/`. При расхождении прав старший; расходящийся
документ исправляется.
