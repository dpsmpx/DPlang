# Карта документации

Документация — часть инженерной системы (Р3): по ней можно понять
архитектуру, найти компонент, понять контракт, внести изменение,
запустить проверки и истолковать результат.

## 1. С чего начать

| задача | куда смотреть |
|---|---|
| понять, зачем язык и куда он идёт | `direction/VISION.md`, затем `direction/GOAL.md` |
| узнать, что решено и почему | `direction/DECISIONS.md` (источник истины) |
| узнать, что ещё не решено | `direction/OPEN_DECISIONS.md` |
| понять архитектуру toolchain | `design/ARCHITECTURE.md` |
| понять устройство языка | спецификация ядра `spec/core.md` (пишется в v0.1), за ней — проект `design/LANGUAGE.md` |
| быстро начать писать на dpl | краткое руководство с приёмами `guide/README.md` (нормативна спецификация) |
| найти компонент в коде | `design/ARCHITECTURE.md`, раздел 10; затем `compiler/README.md` (устройство компилятора), `compiler/cli.md` (команды `dpl`), `ir/README.md` (Core IR, понижение, верификатор, интерпретатор), `compiler/backend_c.md` (C-бэкенд), `runtime/README.md` (runtime), `stdlib/README.md` (стандартная библиотека) и `bindings/README.md` (привязки) |
| понять контракт для потребителя | `policy/COMPATIBILITY.md`, `policy/DETERMINISM.md`, спецификация |
| внести изменение | `../CLAUDE.md` (обязательный минимум), `policy/ENGINEERING.md` |
| запустить проверки и прочитать результат | `../tools/check/run.sh`, `policy/TESTING.md` (разделы 5–6) |
| понять, что делать дальше | `../ROADMAP/ROADMAP.md`, `../ROADMAP/IMPLEMENTATION.md`, `../TODO.md` |
| понять, когда v1.0 | `direction/DEFINITION_OF_DONE.md` |
| понять, как лицензируются компилятор, runtime и вывод | `direction/DECISIONS.md`, Р39; правила — `policy/LICENSING.md`; обоснование — `research/LICENSING.md` |
| понять онлайн-компилятор: устройство, изоляция, профиль, контракт для сайта | `service/README.md`, `service/integration.md`; решение — Р49 |

## 2. Каталоги

| каталог | что в нём | статус |
|---|---|---|
| `direction/` | видение, цели, решения, открытые решения, Definition of Done, риски | нормативно |
| `design/` | проект архитектуры и языка до спецификации | проект; при реализации переходит в `spec/` и описание устройства |
| `policy/` | правила: совместимость, детерминизм, тесты, замеры, платформы, инженерия, безопасность, выпуск, лицензирование | нормативно |
| `research/` | исследования с источниками | материал, не решения |
| `audits/` | аудиты на дату | срез на дату |
| `spec/` | спецификация языка: `core.md` — ядро v0.1 | нормативно; пишется по шагам v0.1 |
| `compiler/` | описание устройства компилятора, сборка, тесты; C-бэкенд — `backend_c.md`; CLI — `cli.md`, схема диагностики — `diagnostics.schema.json` | v0.1, по шагам |
| `ir/` | описание Core IR: устройство, понижение, верификатор, эталонный интерпретатор | v0.1, шаги 6–7 |
| `runtime/` | описание устройства runtime: ловушки, пределы, вход, код выхода | v0.1, шаги 8–9 |
| `service/` | онлайн-компилятор (Р49): worker, песочница, шлюз, профиль, модель угроз, DoD сервиса; контракт для dpsmpx.com | основа сделана, запуск выключен |
| `stdlib/` | описание устройства стандартной библиотеки: модули, внутренние встроенные, `os` | v0.1, шаг 11 |
| `bindings/` | привязки: генераторы, закреплённый вход, перевод типов C (Vulkan), проверки | v0.2, шаг 6 |
| `../examples/` | программы на dpl с описанием в своём `README.md`: `tomlcheck` (v0.1), `triangle` (v0.2), `swarm` — многопоточная симуляция с повтором (v0.3) | v0.1, шаг 12 |
| `archive/` | отработанное, с описью | появится с первым архивным документом |

Корень репозитория: `README.md`, `CLAUDE.md`, `TODO.md`, `LICENSE`;
`ROADMAP/` — планы; `docs/CHANGELOG.md` — вехи; `docs/THIRD_PARTY.md` —
сторонние компоненты.

## 3. Порядок источников истины

`direction/DECISIONS.md` → `../CLAUDE.md` → `../ROADMAP/` → `../TODO.md`
→ спецификация и описание устройства → `design/` → `research/`,
`audits/`, `archive/`. При расхождении прав старший; расходящийся
документ исправляется.
