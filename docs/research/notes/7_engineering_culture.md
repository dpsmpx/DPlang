# 7. Инженерная культура проектов языков и компиляторов; практика ИИ-агентов

Заметки исследования, 3 октября 2026.

## Решения

- **RFC/предложения:** Rust RFC (https://github.com/rust-lang/rfcs),
  Go proposals, Python PEP, Swift Evolution — изменение языка проходит
  письменное обоснование, альтернативы, обсуждение и запись решения.
- **ADR** (Nygard, 2011): короткая запись «контекст → решение →
  последствия», неизменяемая, новая запись заменяет старую.
  https://cognitect.com/blog/2011/11/15/documenting-architecture-decisions ·
  https://adr.github.io/
- У VoxelRPG уже есть облегчённый вариант — `DECISIONS.md` с историей:
  решения Р0–Р16, «рассмотрено и отклонено», запись в историю при каждом
  изменении.

## Тесты компилятора

- **Rust UI-тесты:** исходник с пометками ожидаемых ошибок
  (`//~^ ERROR …`) + файл `.stderr` с точным выводом компилятора рядом;
  `--bless` перезаписывает ожидание, а человек смотрит дифф — так
  сообщения об ошибках сами становятся тестируемым продуктом.
  https://rustc-dev-guide.rust-lang.org/tests/ui.html ·
  https://rustc-dev-guide.rust-lang.org/tests/adding.html
- **LLVM lit + FileCheck:** тест — файл с командой запуска и шаблонами
  ожидаемого вывода в комментариях.
  https://llvm.org/docs/CommandGuide/lit.html ·
  https://llvm.org/docs/CommandGuide/FileCheck.html
- **Go:** каталог `test/` с пометками `// ERROR "…"` в исходниках.
  https://github.com/golang/go/tree/master/test

## Фаззинг компиляторов

- **Csmith:** случайные программы на C без неопределённого поведения,
  сравнение компиляторов между собой; к ноябрю 2013 — 481 ошибка в
  LLVM, GCC, CompCert и др., около 120 — ошибки генерации кода.
  https://www-old.cs.utah.edu/~regehr/papers/pldi11-preprint.pdf
- **YARPGen:** > 220 ошибок в GCC, LLVM и Intel C++ (OOPSLA 2020);
  генерация выразительных программ без неопределённого поведения без
  проверок во время выполнения. https://users.cs.utah.edu/~regehr/yarpgen-oopsla20.pdf
- Для своего языка: генератор случайных корректных программ +
  сравнение двух бэкендов / двух уровней оптимизации / интерпретатора и
  компилятора.

## Выпуски и регрессии

- **Правило «не ракетная наука»** (Graydon Hoare): автоматически держать
  репозиторий, который всегда проходит все тесты; вливание — только
  после прохождения CI на свежей базе (bors, очереди слияния).
  https://graphite.com/blog/bors-google-tap-merge-queue
- **Crater** — корпус как тест (заметки 5); **perf.rust-lang.org** —
  замер скорости компилятора на каждом изменении.
  https://perf.rust-lang.org/

## ИИ-агенты в репозитории (2025–2026)

- **Файлы контекста стоят дорого.** Gloaguen, Mündler, Müller, Raychev,
  Vechev, «Evaluating AGENTS.md» (февраль 2026, ICLR 2026):
  сгенерированные моделью файлы контекста **снижают** успех (≈ −3%) и
  **увеличивают** стоимость на 20%+; написанные разработчиком дают
  небольшой плюс (≈ +4%), но тоже добавляют токены и шаги. Вывод: держать
  файл минимальным — только то, что агент не выведет сам.
  https://arxiv.org/html/2602.11988v1
- **Агенты «чинят» уже исправленное.** FixedBench (2026): 200 задач, где
  менять ничего не нужно; современные модели вносят ненужные правки в
  35–65% случаев — «склонность к действию». Явное разрешение «ничего не
  делать» помогает (см. разбор в VoxelRPG
  `docs/direction/AGENT_PROCESS_PROPOSALS.md`: 65% → 80,5%).
  https://www.alphaxiv.org/abs/2605.07769 ·
  https://codex.danielvaughan.com/2026/06/19/coding-agents-fixing-correct-code-fixedbench-codex-cli-abstain-reproduce-before-patch-action-bias/
- **Проверка, которую агент запускает сам** (тесты, код возврата
  сборки, линтеры, сравнение снимков) — главное условие качества по
  рекомендациям Anthropic; хуки делают правила детерминированными,
  а не «по желанию модели». https://www.anthropic.com/engineering/claude-code-best-practices
- **Краткий вывод инструментов** (заметки 1): на зелёном — счёт и путь
  к журналу, на красном — первый сбой и хвост.
- Стандарт **AGENTS.md** — общий формат файла правил для агентов.
  https://agents.md/

## Что взять

1. **`DECISIONS.md` по образцу VoxelRPG** + для изменений языка —
   короткие предложения (RFC-лайт): мотив, синтаксис, правка-миграция,
   альтернативы, замер токенов.
2. **Тесты компилятора — файлы-примеры с ожидаемым выводом** (UI-тесты
   Rust, lit): `.cm` + `.out`/`.err`, команда «принять» с просмотром
   диффа. Сообщения об ошибках — тестируемый продукт.
3. **Фаззинг с первого бэкенда:** генератор корректных программ,
   сравнение интерпретатора (или второго бэкенда) с основным.
4. **`main` всегда зелёный**; вливание после полного прогона.
5. **Замер скорости компилятора в CI** с порогом регрессии.
6. **Минимальный `CLAUDE.md`** — инварианты, запреты, проверки,
   процесс; описание устройства — в `docs/`, а не в правилах агента.
7. **Проверить — сделать или не трогать; остановиться, когда готово;
   сбой инструмента ≠ сбой кода** — правила из разбора VoxelRPG,
   подтверждённые FixedBench.
8. **Детерминированные ограничители:** хуки и скрипты проверок вместо
   абзацев текста.
