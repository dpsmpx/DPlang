# 6. Взаимодействие с C/C++ и постепенный перенос кода

Заметки исследования, 3 октября 2026.

## Механизмы взаимодействия

- **Zig:** до 0.15 — `@cImport`/`@cInclude` в языке через libclang; в
  0.16 они **удалены из языка**, перевод заголовков C — шаг системы
  сборки (`addTranslateC`), транслятор на своём фронтенде Aro, дальше —
  отдельный пакет `translate-c`. Урок: импорт C — инструмент сборки, а
  не часть языка. https://ziggit.dev/t/translate-c-failure-after-upgrade-to-0-16/15067 ·
  https://ziggit.dev/t/cimport-going-away/5132
- **Carbon:** цель 2025 — взаимодействие с C++ **без шаблонов** (сначала
  вызов C++ из Carbon, потом наоборот); шаблоны и корутины — вне рамок;
  веха 0.1 — не раньше конца 2026. Даже команда Google не обещает
  шаблоны C++. https://docs.carbon-lang.dev/docs/project/roadmap.html ·
  https://docs.carbon-lang.dev/proposals/p004880-safety-milestones-and-a-2025-roadmap.html
- **cppfront (Cpp2):** компилируется в обычный C++, без своей
  экосистемы; полная совместимость с C++ — за счёт того, что результат и
  есть C++. Развитие практически остановлено (последний коммит автора —
  февраль 2026). https://github.com/hsutter/cppfront/wiki
- **Vulkan из vk.xml:** привязки для Zig (vulkan-zig, zvk) и Rust (ash,
  vulkane) **генерируются** из машиночитаемого реестра Khronos: типы,
  перечисления, функции, загрузчик, таблицы диспетчеризации; ошибки
  Vulkan — в систему ошибок языка, выходные параметры — в возвращаемые
  значения. https://github.com/flut2/vulkan-zig ·
  https://docs.rs/crate/ash/latest

## Постепенный перенос — что показали другие

- **fish shell, C++ → Rust:** ≈ 57 тыс. строк C++ → ≈ 75 тыс. строк Rust
  за ~2 года (2023–2024, fish 4.0); переносили **подсистему за
  подсистемой**, мост C++ ↔ Rust — autocxx; смешанная кодовая база жила
  до начала 2024. Итог — довольны; трудности — переносимость,
  локализация, сборка (CMake остался).
  https://fishshell.com/blog/rustport/ ·
  https://www.phoronix.com/news/Fish-Shell-Rust-Challenges
- **Android: новый код — на безопасном языке, старый не переписывать.**
  Доля уязвимостей памяти — с 76% (2019) до < 20% (2025); плотность
  таких уязвимостей в Rust ≈ в 1000 раз ниже, чем в C/C++ Android;
  изменения на Rust в 4 раза реже откатываются и на 25% быстрее
  проходят ревью. https://blog.google/security/rust-in-android-move-fast-fix-things/
- **DARPA TRACTOR** (с августа 2024): автоматический перевод C в
  идиоматичный безопасный Rust; ForCLift (2025, $5 млн) сочетает
  формальные методы, анализ программ и LLM; Intel (август 2026) —
  «улучшенное декодирование и проверка эквивалентности в масштабе».
  Главное — **проверка эквивалентности**, а не сам перевод.
  https://www.darpa.mil/program/translating-all-c-to-rust ·
  https://www.cs.wisc.edu/2025/07/15/translating-legacy-code-for-a-safer-future ·
  https://www.intel.com/content/www/us/en/security/security-practices/blogs/ideas-for-tractor.html
- Google, LLM-миграции (заметки 5): ~70% правок делает модель,
  остальное и проверки — люди и инструменты.

## Что это значит для VoxelRPG

- Vulkan, SDL3, JNI — C API: привязки **генерируются** (vk.xml, заголовки
  SDL3), как у Zig и Rust.
- glm, EnTT, toml++ — заголовочные шаблонные C++-библиотеки: через C ABI
  их не вызвать, шаблоны не обещает даже Carbon. Решение — заменить:
  glm → встроенная математика языка, toml++ → свой разбор TOML на языке
  (или C-обёртка на время), EnTT → ECS на языке (у VoxelRPG своя обёртка
  над EnTT — граница уже есть).
- Порядок — как у fish и Android: **новое — на языке, старое — по
  подсистемам, листья первыми** (чистая логика: предметы, ремесло,
  задания, прогрессия), рендер и платформа — последними или никогда.
- Проверка переноса — **детерминированная симуляция**: старая и новая
  подсистема на одном зерне, сравнение хэшей состояния каждый такт.

## Что взять

1. **Граница — C ABI**, генерация привязок в обе стороны (язык → C
   заголовок, C заголовок → объявления языка) как шаг сборки.
2. **Привязки к Vulkan из vk.xml**, к SDL3 и JNI — из заголовков.
3. **Нет обещания шаблонов C++** — заменять шаблонные библиотеки своими.
4. **Перенос по подсистемам с мостом**, новое — сразу на языке
   (Android), подсистема переносится целиком (fish).
5. **Перевод C++ → язык — ИИ + механика, приёмка — по эквивалентности**
   (TRACTOR, Google): тесты, повтор симуляции, хэши.

## Осторожно

- fish — 57 тыс. строк и 2 года у опытной команды при зрелом целевом
  языке; у VoxelRPG — 89 тыс. строк и язык, которого ещё нет.
- Смешанная кодовая база — двойная цена сборки и проверок, пока перенос
  идёт; держать её короткой.
- cppfront и Carbon показывают, как трудно и долго даётся
  взаимодействие с C++ даже большим командам.
