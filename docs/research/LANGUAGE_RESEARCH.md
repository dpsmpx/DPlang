## 0. Коротко

1. **Знакомое, а не изобретательное.** Модель хорошо пишет на языке,
   похожем на те, что знает; экзотический синтаксис экономит символы, но
   стоит ошибок и повторов — а повторы и чтение и есть главная цена
   агента. Синтаксис — в духе Go, Rust, Zig, Swift.
2. **Главная мера — токенов на принятое изменение**, а не длина строки.
   В агенте 67% стоимости — чтение контекста (замер VoxelRPG); языки
   различаются по токенам до 2,6 раза; форматирование съедает ~25% входа.
3. **Компилятор — часть цикла ИИ:** проверка без сборки за миллисекунды,
   короткие точные ошибки с правкой, ответы на вопросы о коде («что в
   модуле», «кто вызывает») вместо чтения файлов.
4. **Надёжность без проверки заимствований:** хэндлы с поколениями и
   арены (как в движках и Vale), ссылки только на время вызова (как в
   Hylo), ошибки — значения, нет null, границы и переполнения
   проверяются всегда (цена — доли процента).
5. **Проверяемость — встроенная:** контракты в сигнатуре, тесты рядом с
   кодом, expect-тесты, фаззинг, детерминизм как гарантия языка.
6. **Бэкенд первой версии — генерация C.** Сразу Android NDK, MinGW и
   MSVC без своей кодогенерации; позже — быстрый отладочный бэкенд.
7. **Игровая математика встроена** (векторы, матрицы, кватернионы,
   swizzle — как в Odin и GLSL): 1 792 обращения к glm в VoxelRPG
   становятся обычной арифметикой.
8. **Язык меняется редакциями с машинной правкой**, а каждое изменение
   компилятора проверяется на представительном consumer project
   («crater» на одном проекте; VoxelRPG — только после v1.0, Р22).
   Основная стоимость изменения — в компиляторе, а не в переписывании
   (Р0).
9. **VoxelRPG переходит постепенно** (после v1.0 и по его решению,
   Р22): граница — C ABI, новое — сразу на
   языке, старое — по подсистемам с листьев; приёмка — повтором
   детерминированной симуляции (C++ и язык на одном зерне, хэш на каждом
   такте).
10. **Шаблонные C++-библиотеки не тянуть:** glm, EnTT, toml++ заменяются
    средствами языка; Vulkan, SDL3, JNI — привязки генерируются.

## 1. Постановка

Решения автора, 3 октября 2026:

- главная задача — краткость синтаксиса и упор на работу с ИИ; экономия
  токенов, скорость сборки, надёжность и проверяемость; совместимость с
  другими языками по синтаксису — не цель ([`GOAL.md`](../direction/GOAL.md));
- язык применяется для **продолжения разработки VoxelRPG**;
- ИИ (Claude) **понимает язык без проблем**;
- язык **собирает реальные приложения для конечных устройств**;
- при изменении языка **игру не переписывают** — меняется только
  компилятор, либо игре нужны небольшие правки;
- в репозиторий переносится **инженерная культура VoxelRPG** и лучшие
  практики.

## 2. Что VoxelRPG требует от языка

Подсчёт по исходникам игры и движка (442 файла `.cpp`/`.h`; ≈ 89 тыс.
строк C++ без проверок). Код наружу не выносился — только счёт
конструкций.

| что в коде | сколько | что нужно от языка |
|---|---|---|
| `glm::` (векторы, матрицы) | 1 792 | встроенные `vec2/3/4`, `mat3/4`, `quat`, swizzle, арифметика |
| `constexpr` | 1 005 | константы и таблицы, вычисляемые при компиляции |
| `std::vector` | 769 | динамический массив и срезы — в ядре языка |
| лямбды | ≈ 550 | замыкания; `std::function` (71) — указатели на функции с контекстом |
| `std::string` / `string_view` | 487 / 59 | строки и срезы строк |
| вызовы Vulkan | 357 | привязки из `vk.xml` |
| журнал в стиле printf | 347 | форматирование строк с проверкой типов |
| `enum class` | 120 | перечисления; суммы типов заменят часть |
| `virtual`/`override` | 70 / 103 | интерфейсы с динамическим вызовом — умеренно |
| шаблоны | 53 | обобщённые типы — умеренно |
| `atomic`/`mutex`/`thread_local` | 58 / 64 / 46 | примитивы потоков; система задач |
| `shared_ptr`/`unique_ptr` | 51 / 30 | владение — хэндлы и арены вместо умных указателей |
| JNI | 11 файлов | вызовы C ABI на Android |
| EnTT / toml++ | 16 / 43 | своя ECS и свой разбор TOML на языке |

Плюс то, что уже решено в VoxelRPG и должно поддерживаться языком:
сборка без исключений и RTTI; фиксированный такт 60 Гц и случайность по
ключам — детерминизм; устойчивые ID сущностей; сохранение каталогом
мира; контент в TOML; ≈ 4 900 проверок своим каркасом; Android
(NativeActivity, AAudio, JNI) и Windows через MinGW.

## 4. Предложения по устройству языка

Номера П — предложения. Решения по ним — Р7–Р20 (П15 отложено); прав
`DECISIONS.md`.

**П1. Синтаксис — знакомый и однозначный.** Короткие английские
ключевые слова (`fn`, `let`, `var`, `if`, `for`, `match`, `return`),
фигурные скобки, однозначная грамматика LL(1) без зависимости от
контекста. Без перегрузки операторов пользователем (кроме встроенной
математики), без макросов, меняющих синтаксис. Один канонический формат.

**П2. Типы.** Явные сигнатуры функций и типов на верхнем уровне,
вывод внутри тел. Встроенные: целые с явной шириной, `f32/f64`, `bool`,
`str`, срезы, массивы, `vec2/3/4`, `mat3/4`, `quat`, `?T` (может не
быть), `!T` (может быть ошибка), суммы типов с полным разбором `match`.
Обобщённые типы — с ограниченной мощностью (без вычислений на уровне
типов).

**П3. Память.** Без сборщика мусора и без проверки заимствований.
Долгоживущие связи — хэндлы с поколением (проверка при обращении);
владение — у систем и арен; ссылки — только параметры на время вызова
(как в Hylo), хранить ссылку в поле нельзя. Аллокатор — явный
(контекстный, как в Odin/Zig). Небезопасное — в блоках `unsafe`,
компилятор считает их по модулю.

**П4. Ошибки.** `!T`, `try`, `defer`, `errdefer`; игнорировать ошибку
молча нельзя. Исключений нет — как в VoxelRPG сейчас.

**П5. Неопределённого поведения в обычном коде нет.** Границы и
переполнения проверяются (переполнение — ошибка; обёртка — явной
операцией), переменные инициализируются обязательно, порядок вычислений
определён. Режимы сборки: отладка, безопасный выпуск (по умолчанию для
игры), быстрый — только явно и для отдельных модулей.

**П6. Детерминизм — свойство языка.** Нет скрытого глобального
состояния и общего генератора случайных чисел; функции симуляции
помечаются и не видят часов, файлов и потоков; `fp-contract` выключен,
правила плавающей точки одинаковы на arm64 и x86-64; тип
фиксированной точки в стандартной библиотеке — для сетевой симуляции.

**П7. Проверяемость.** Контракты `pre`/`post`/`assert` в сигнатурах
(проверяются в отладке и безопасном выпуске); блоки `test` рядом с
кодом; expect-тесты (ожидание — в исходнике, обновляется командой);
встроенный фаззинг и проверка свойств; повтор симуляции по зерну —
штатная команда.

**П8. Модули.** Модуль — каталог; граф модулей без циклов; сводка
интерфейса модуля (публичные сигнатуры) — файл, который компилятор
пишет сам и читает вместо исходников зависимостей. Та же сводка — ответ
ИИ на вопрос «что есть в модуле».

**П9. Компилятор для ИИ.** Команды: `check` (типы без генерации, цель —
десятки миллисекунд на модуль), `build`, `test`, `fmt`, `fix`,
`explain <код ошибки>`, `query` (сводка модуля, где объявлено, кто
вызывает, тип выражения). Ошибка — одна строка: место, код, причина,
предложенная правка; машиночитаемый режим (JSON). Без каскадов.

**П10. Бэкенд.** Первая версия — генерация переносимого C11 с `#line`,
без неопределённого поведения C (явные проверки, арифметика, не
зависящая от флагов вроде `-fwrapv`, временные переменные для порядка
вычислений). Сборка — тем же
компилятором C, что и сейчас: NDK clang для Android, clang + lld поверх
MinGW-w64 для Windows. Второй бэкенд для быстрых отладочных сборок и
LLVM для выпуска — по замеру, не раньше, чем C-бэкенд станет узким
местом. Рассмотрено: генерация C++ (прямой вызов C++-кода VoxelRPG, но
медленная сборка и чужая семантика) — как запасной вариант для
переходного периода.

**П11. Взаимодействие.** C ABI в обе стороны: `extern` объявления
генерируются из заголовков C (шагом сборки, как в Zig 0.16), язык
выдаёт заголовок C для своих публичных функций. Vulkan — из `vk.xml`,
SDL3 и JNI — из заголовков. Шаблоны C++ не поддерживаются.

**П12. Эволюция.** Редакция — в манифесте модуля; модули разных
редакций собираются вместе. Каждое изменение языка — с машинной правкой
(`fix --edition`), модернизаторы (`fix --modernize`). Изменение без
автоматической правки — исключение, решение автора. Перед выпуском
версии компилятора — сборка и тесты VoxelRPG и полигона языка.

**П13. Стандартная библиотека — маленькая и игровая:** коллекции,
строки, форматирование, математика, хэндлы и арены, ECS-хранилище,
разбор TOML, система задач, журнал, тестовый каркас.

**П14. Спецификация в бюджете токенов** — до 20 тыс. токенов, с
примером на каждый раздел; документация — с поиском по разделам
(исследование Cangjie: без поиска по документации точность падает с 74
до 54%).

**П15. Имя и расширение файлов** — открытый вопрос; в примерах ниже —
`.cm`.

### Иллюстрация (не решение — синтаксис выбирается замером)

```text
module game.items

use engine.world (World, Actor)

pub struct Item {
    id:     ItemId      // хэндл с поколением
    name:   str
    weight: f32
}

pub fn pick(w: &mut World, who: Actor, it: ItemId) !void
    pre  w.alive(who)
    post w.inventory(who).has(it)
{
    let drop = w.pos(who) + vec3(0, 1, 0)   // встроенная математика
    let item = try w.items.get(it)          // ошибка — значение
    w.inventory(who).add(item)
}

test "pick adds item" {
    var w = World.test(seed: 42)
    let a = w.spawn_actor()
    let it = w.spawn_item("stone")
    try pick(&mut w, a, it)
    expect(w.inventory(a).has(it))
}
```

## 5. Как продолжить VoxelRPG на языке

> По Р22 до v1.0 основная кодовая база VoxelRPG на язык не переносится
> (включая её вспомогательные программы); раздел — материал на после
> v1.0, решение — только в `DECISIONS.md` VoxelRPG. Этап 0 таблицы
> соответствует этапам 4–5 `ROADMAP` языка и делается на тестовых
> приложениях.

Порядок — как у fish shell и Android: новое — сразу на языке, старое —
по подсистемам, листья первыми, с мостом через C ABI.

| этап | что | приёмка |
|---|---|---|
| 0. Срез языка | компилятор: модули, типы, ошибки, тесты, C-бэкенд; программа «окно, треугольник Vulkan, звук SDL3» на Linux, Windows и Android | собирается и запускается на трёх целях |
| 1. Инструменты | вспомогательные программы VoxelRPG на языке (проверки, генераторы) — без риска для игры | работают как прежние, сравнение вывода |
| 2. Первая подсистема-лист | чистая логика без рендера (предметы, ремесло, прогрессия) — на языке, остальное — C++ через C ABI | все проверки подсистемы; повтор симуляции: хэш состояния совпадает с C++ на N тысячах тактов |
| 3. Новые системы | всё новое в VoxelRPG — на языке | замер: токены на задачу и ошибки против C++ (эталонный набор) |
| 4. Остальная логика | подсистема за подсистемой; glm → встроенная математика, toml++ → разбор на языке, EnTT → ECS на языке | то же, что в этапе 2 |
| 5. Движок | платформа и рендер — последними, только если выгода доказана замером | — |

Условие каждого этапа — **ворота**: если язык по замеру проигрывает C++
(токены, ошибки, скорость сборки или кадра), этап останавливается, а
язык остаётся там, где уже доказал пользу.

Перевод подсистемы — ИИ + механические правила, приёмка — по
эквивалентности, а не на глаз (схема Google и DARPA TRACTOR: модель
делает ~70% правок, остальное и проверку — инструменты).

**Расхождение с правилами VoxelRPG.** В VoxelRPG действует правило:
запрос сверяется с его `DECISIONS.md`, а приоритет до выпуска — версия 1
(Р4). Перенос любой части VoxelRPG на язык — решение, которое
записывается **в `DECISIONS.md` VoxelRPG** до работы; этот документ его
не заменяет.

## 6. Как менять язык, не переписывая игру

1. **Редакции** (П12): старая редакция модуля продолжает собираться,
   новый смысл — только в новой.
2. **Машинная правка у каждого изменения**: компилятор знает старую и
   новую форму, предупреждает и правит; `fix --edition` переводит
   модуль целиком; после правки — `check` и тесты.
3. **Однозначная грамматика и один формат** — условие безопасных
   механических правок.
4. **«Crater» на consumer project:** CI компилятора собирает и тестирует
   представительный consumer project и полигон языка (Р0); изменение,
   которое ломает его без автоматической правки, не вливается без
   решения автора. VoxelRPG становится таким проектом только после v1.0
   и по его решению (Р22).
5. **ИИ — для остатка**: то, что механика не правит, делает модель под
   проверками и повтором симуляции.
6. **Стабильность ядра**: синтаксис ядра после 1.0 не меняется без
   редакции; эксперименты — за флагом и не используются в игре.

Предостережение (Zig, Dart): автоправка делает ломку обманчиво дешёвой —
каждая ломка всё равно проходит через решение и замер.

## 7. Как добиться, чтобы ИИ понимал язык без проблем

Гарантировать заранее нельзя: на старте модель языка не знает. Цель
достигается устройством языка и проверяется замером.

1. **Знакомый синтаксис** (П1) — перенос знаний с Go, Rust, Zig.
2. **Спецификация до 20 тыс. токенов** (П14) с примером на каждый
   раздел; в `CLAUDE.md` — ссылка и краткая шпаргалка.
3. **Корпус примеров** растёт с проектом: проверенные решения
   возвращаются как образцы («самоподмости»: Pyth 16,7% → 30,8%).
4. **Компилятор объясняет и правит** (П9): короткие ошибки с правкой,
   `explain`, `query`.
5. **Замер:** эталонный набор задач (раздел 2 `GOAL.md`); ворота этапа 4
   `ROADMAP` — модель решает задачи на языке не менее корректно, чем на
   C++, и тратит меньше токенов (порядок — Р6). Применение в VoxelRPG —
   по Р22.
6. **Позже — ограничение генерации грамматикой и типами** (MoonBit,
   Mündler и др.), если появится свой инструмент генерации.

## 8. Риски и чего не делать

| риск | мера |
|---|---|
| язык съест время игры | Р21: ~1/6 ресурса, без календаря; VoxelRPG язык не ждёт; приоритет версии 1 — по его `DECISIONS.md` |
| ИИ пишет на языке хуже, чем на C++ | эталонный набор и порог приёмки (раздел 7) |
| C-бэкенд наследует неопределённое поведение C | генератор без UB, фаззинг сравнением с интерпретатором |
| смешанная кодовая база дорога | держать переход коротким, подсистема — целиком |
| «инструмент поправит» — ломка слишком частая | каждая ломка — решение и замер |
| шаблонные C++-библиотеки | не поддерживать, заменять |
| детерминизм на разных процессорах | `fp-contract` выключен, фиксированная точка для сети |
| лицензия репозитория — Unlicense | решено: проприетарная (Р4), временная редакция в `LICENSE`; окончательный текст — `TODO.md` |

Не делать: автоматически копировать проверку заимствований Rust (Р9;
дополнительные статические гарантии — открытый вопрос), макросы,
меняющие грамматику, пользовательскую перегрузку операторов на первом
этапе (Р7), исключения, сборщик мусора, свой оптимизирующий бэкенд до
замера, взаимодействие с шаблонами C++.
