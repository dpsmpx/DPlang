# Definition of Done: v1.0, миграция VoxelRPG, главная метрика

Постановка автора (разделы 20–22), адаптированная под итоги
исследования: у каждого условия — проверяемый критерий и способ
проверки. Основание — Р23, Р31, Р32. Числовые пороги с пометкой
«(предложение)» — ориентиры сессии; их подтверждают или меняют записью в
`DECISIONS.md` после первых замеров (Р15, Р24).

v1.0 достигнута, только когда выполнены **все** разделы A–L.

## 1. Language v1.0

### A. Спецификация

| критерий | как проверяется |
|---|---|
| выпущенная, версионированная, внутренне согласованная спецификация (публикация наружу — Р5) | номер версии; аудит согласованности без открытых противоречий |
| определены синтаксис, семантика, ядро системы типов | каждый нормативный пункт — с идентификатором и тестами соответствия |
| перечислены области I, P, N и места неопределённого поведения (только `unsafe`) | раздел спецификации и `docs/policy/DETERMINISM.md` |
| политика совместимости, версионирование, политика ABI | `docs/policy/COMPATIBILITY.md` в режиме production; ABI — раздел спецификации |

### B. Компилятор

| критерий | как проверяется |
|---|---|
| язык компилируется полностью; в production-пути нет интерпретатора | эталонный интерпретатор Core IR используется только тестами (Р43) |
| хотя бы один бэкенд production-качества | C-бэкенд: весь набор соответствия на целях уровня 1; сгенерированный C компилируется без предупреждений (`-Wall -Wextra`); различающий фаззинг (предложение: ≥ 72 процессорных часов на кандидата) без новых ошибок генерации кода |
| цели первой волны | Linux x86-64, Windows x86-64, Android arm64 — уровень 1 (`docs/policy/PLATFORMS.md`) |
| качественная диагностика | у каждого кода ошибки — тест отказа, снимок и текст `explain`; машиночитаемый режим по схеме |
| набор отказа компиляции | все запреты спецификации покрыты |
| полная автоматическая проверка | полный и расширенный прогоны зелёные |

### C. Native-приложения

Нетривиальные программы (не hello-world и не тесты компилятора), каждая
собирается и запускается на целях уровня 1 (где применимо):

| программа | что доказывает |
|---|---|
| CLI-инструмент (например, проверка и форматирование файлов контента TOML) | файлы, строки, ошибки, CLI |
| программа с большими данными (например, генератор мира с сериализацией гигабайтов) | память, арены, сериализация, производительность |
| многопоточная программа (например, симуляция на системе задач с повтором) | параллелизм без гонок, детерминизм |
| графическая native-программа (Vulkan + SDL3 на Linux и Windows, Vulkan + NativeActivity на Android) | FFI, ресурсы, платформы |
| программа с FFI (одна из выше или отдельная: библиотека C с обратными вызовами) | C ABI в обе стороны |

### D. Взаимодействие

| критерий | как проверяется |
|---|---|
| C ABI работает | тесты ABI на всех целях уровня 1 |
| FFI покрыт тестами | раскладка, вызовы, обратные вызовы, ошибки, владение |
| записаны правила владения на границе | раздел спецификации и документация привязок |
| постепенная интеграция с C/C++ | демонстрация: хост на C++ вызывает модуль dpl и наоборот через C-прослойку (Р30) |

### E. Детерминизм

| критерий | как проверяется |
|---|---|
| правила формально определены | `docs/policy/DETERMINISM.md` нормативен и согласован со спецификацией |
| автоматические тесты детерминизма | повторы с золотыми хэшами; x86-64 = arm64; 1…N потоков; `debug` = `release` |
| одинаковые входы — одинаковый результат в области гарантии | те же тесты на многопоточной программе C |
| N и P помечены и локализованы | тесты отказа компиляции; ревью меток библиотеки |

### F. Надёжность

| критерий | как проверяется |
|---|---|
| регрессионный набор, фаззинг, санитайзеры, статический анализ, интеграционные, нагрузочные, отрицательные и детерминированные тесты | все наборы `docs/policy/TESTING.md` существуют и зелёные |
| нет известных необъяснённых критических ошибок компилятора и runtime | список ошибок класса «критический» пуст или каждая объяснена записью |

### G. Производительность

| критерий | как проверяется |
|---|---|
| база замеров и документированные ограничения | `bench/results/` и раздел ограничений в документации |
| пригодность для production | представительные нагрузки: время не хуже эталона на C++ больше чем в 1,25 раза по медиане (предложение) |
| нет архитектурных узких мест для VoxelRPG | аудит по нагрузкам `docs/policy/BENCHMARKS.md` |
| скорость сборки | `check` и инкрементальная сборка эталонного проекта — в порогах, назначенных после замеров (Р15) |

### H. Инструменты

| что | минимально |
|---|---|
| форматировщик | идемпотентен, один формат |
| language server | диагностика, переход к определению, поиск ссылок, переименование |
| отладка | документированный порядок на трёх целях |
| исполнитель тестов | блоки тестов, expect, фаззинг, повтор |
| сборка и пакеты | манифест, lockfile, профили, кросс-компиляция |
| профилирование | маркеры зон + порядок работы с perf, simpleperf, ETW |
| CLI компилятора | `check`, `build`, `test`, `fmt`, `fix`, `explain`, `query` |

### I. Сборка и выпуск

Воспроизводимая чистая сборка (проверена двойной сборкой); CI или, пока
его нет, документированный полный прогон; версионированные артефакты;
порядок сборки и установки; порядок кросс-компиляции; документация
выпуска (`docs/policy/RELEASE.md`).

### J. Эволюция — эксперимент

Доказать: «небольшое или среднее изменение языка реализуется внутри
компилятора и инструментов без обязательного переписывания большого
consumer project».

- **Проект:** представительный (раздел L или отдельный, не меньше
  20 тыс. строк — предложение).
- **Изменения:** не меньше трёх разного рода — переименование
  конструкции, смена смысла конструкции в новой редакции, устаревание
  API библиотеки.
- **Успех:** миграция `fix`; ручные правки — не больше 1% изменённых
  строк (предложение); все тесты и хэши детерминизма прежние.

### K. Документация

Законченные: спецификация языка; архитектура компилятора; Core IR;
runtime и ABI; стандартная библиотека; совместимость; детерминизм;
тестирование; замеры; платформы; инженерные правила; выпуск.
**Проверка по критерию Р3:** новая сессия ИИ, получив только
документацию, выполняет набор задач — найти компонент, понять контракт,
внести изменение, запустить проверки, истолковать результат — без
обращения к истории разговоров.

### L. Проверка на реальном проекте

Хотя бы один достаточно крупный production-style проект на dpl с
реальным toolchain — не код VoxelRPG (Р22): например, отдельная
небольшая игра или инструмент уровня редактора мира. Критерии
(предложение): не меньше 30 тыс. строк, многомодульный, многопоточный,
с тестами, разрабатывался не меньше нескольких месяцев; собирается на
целях уровня 1; доказывает пригодность языка, а не демонстрирует его
возможности.

## 2. Условия начала миграции VoxelRPG (Р31)

Решение и аудит — в `DECISIONS.md` VoxelRPG. Для первой миграции
(подсистема-лист) доказать на ней:

| условие | мера (предложение) |
|---|---|
| качество не хуже | плотность ошибок и падений перенесённой подсистемы — не выше, чем на C++, за сопоставимый период |
| производительность приемлема | не хуже версии на C++ больше чем на 10% на её нагрузке |
| поведение памяти приемлемо | пик и число выделений — не хуже больше чем на 10% |
| детерминизм сохранён | повтор: хэши состояния совпадают с версией на C++ на всех тактах |
| отладка не хуже | на трёх целях отлаживается тем же порядком, что и C++ |
| CI и выпуск не менее надёжны | доля красных прогонов и время сборки — не хуже |
| разработка ускоряется | исследование раздела 3 на задачах этой подсистемы |

Миграция — постепенная, со смешанным кодом C++ и dpl (Р30).

## 3. Главная метрика — сравнительное исследование (Р32)

После v1.0, на реальных задачах:

- **Сравнение:** текущий процесс на C++ против dpl и его инструментов.
- **Задачи:** набор однотипных по объёму задач из реальной работы
  (VoxelRPG — только после решения о его участии; до этого — проект
  раздела L), распределённых между вариантами без подбора.
- **Меры:** время реализации; плотность ошибок; доля регрессий; усилия
  на тесты; объём кода; усилия на ревью; цена рефакторинга; время
  сборки; производительность; усилия на отладку; успешность ИИ-агента
  (принято без исправлений, циклы, токены).
- **Итог:** запись в `docs/audits/` и решение о дальнейшем пути.
