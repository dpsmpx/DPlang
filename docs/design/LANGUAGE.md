# Устройство языка dpl (проект)

**Статус:** проект ядра языка до спецификации. Решённое — в
`docs/direction/DECISIONS.md` (Р7–Р20, Р29, Р30); здесь — анализ
механизмов, выбранная модель и её цена. Открытые места —
`docs/direction/OPEN_DECISIONS.md`. Синтаксис — Р40 (вариант B,
`docs/research/syntax/spec_B.md`); здесь механизмы описаны словами, без
записи.

## 1. Типы (кратко, Р8)

Целые фиксированной ширины и целое размера адреса; `f32`/`f64` (IEEE
754); `bool`; строки (UTF-8, Р42); срезы; массивы фиксированной длины;
встроенные векторы, матрицы и кватернионы с арифметикой; «может не
быть»; «значение или ошибка»; структуры; суммы типов с исчерпывающим
`match`; обобщённые типы ограниченной мощности (Р42); ресурсные
(линейные) типы — раздел 2.

### 2.2. Выбранная модель

- **Значения.** Типы — значения; присваивание простых данных копирует.
- **Ссылки второго сорта** (Hylo): живут только в параметрах и
  локальных временных; не хранятся в полях и глобальных данных, не
  возвращаются из функции. Висячая ссылка в безопасном коде
  невозможна статически.
- **Исключительный изменяемый доступ на границе вызова** (Swift,
  статически): изменяемая ссылка на объект не может существовать вместе с
  другой ссылкой на него в одном вызове. Закрывает инвалидацию срезов и
  итераторов и даёт основу защиты от гонок (раздел 3).
- **Куча — через явный аллокатор.** Контейнеры хранят свой аллокатор;
  арены и кадровые аллокаторы — в библиотеке; язык сам память не
  выделяет. В v0.1 (Р45) встроенные `List[T]` и `str` — значения с
  копированием и автоматическим освобождением, память — из кучи runtime
  по умолчанию; явные аллокаторы — v0.3.
- **Долгоживущие связи — хэндлы с поколением** (`Pool` и `Handle` в
  библиотеке): устаревший хэндл обнаруживается, а не даёт неопределённое
  поведение.
- **Ресурсные типы — линейные:** значение ресурсного типа обязано быть
  освобождено или передано на всех путях; проверка — потоком данных, как
  определённая инициализация. Освобождение — явное, обычно через
  `defer`.
- **`unsafe`** — сырые адреса и ручное время жизни, видимо и
  перечислимо по модулю (Р11).

| гарантия | как обеспечена |
|---|---|
| нет чтения неинициализированного | статически |
| нет висячих ссылок | статически (ссылки без побега) |
| нет конфликтующего изменяемого доступа | статически (исключительность на границе вызова) |
| ресурс не утёк и не освобождён дважды | статически (линейные ресурсы) |
| нет null | статически (тип «может не быть») |
| выход за границы, переполнение | во время выполнения (ловушка) |
| обращение по устаревшему хэндлу | во время выполнения (поколение) |
| нарушение контракта | во время выполнения (ловушка) |
| всё прочее | только в `unsafe` |

Что проверить программами v0.1–v0.3 (О4): доля ложных отказов
компилятора, удобство кода с хэндлами вместо указателей, цена проверок
на нагрузках `docs/policy/BENCHMARKS.md`.

## 3. Параллелизм и система задач

### 3.1. Модели

| модель (откуда) | что даёт | цена | для VoxelRPG | вывод |
|---|---|---|---|---|
| владение и заимствование + Send/Sync (Rust) | гонки исключены статически | сложность, аннотации | мощно, но дорого | взять идею: «передаваемый» тип и «конкурентный» тип |
| передача сообщений (Go, Erlang) | просто, изоляция | копирование, задержка | загрузка ресурсов, фоновые задачи | каналы в библиотеке |
| системы задач движков | производительность параллельных циклов | при ручной дисциплине — гонки | основа кадра | библиотека поверх структурной модели |
| структурный параллелизм (Trio, группы задач Swift) | нет «осиротевших» задач, ошибки и отмена — по области | долгоживущие задачи — явно | да | основа |
| акторы (Swift, Pony) | изоляция состояния | асинхронные переходы, сложность | мало для симуляции | не в ядре до v1.0 |
| `unsafe` | свои потоки и разделяемая память | без гарантий | узкие места | только явно |

### 3.2. Выбранная модель (О13)

- **Структурные задачи:** задачи создаются в области, и область
  дожидается всех; отдельный долгоживущий поток — явным типом библиотеки
  с обязательным присоединением (линейный ресурс).
- **Что можно передать в задачу:** значения «передаваемых» типов (без
  ссылок и сырых адресов) — по значению; общие данные — только для
  чтения на время области (исключительность гарантирует, что пишущего
  нет); изменяемые — непересекающимися частями (разбиение срезов и
  пулов).
- **Общее изменяемое** — только через конкурентные типы библиотеки:
  атомики, мьютекс, владеющий данными, каналы.
- **Детерминизм (Р29):** в детерминированном классе — только
  конструкции с детерминированным результатом (параллельный цикл и
  отображение с упорядоченным объединением); мьютексы и каналы —
  недетерминированный класс.
- **Сложность компилятора** — средняя: переиспользует проверки ссылок без
  побега и исключительности; «передаваемость» вычисляется по структуре
  типа.
- **Проверка модели** — программа с системой задач (v0.3), TSan на
  сгенерированном C, детерминированные повторы при разном числе потоков.

## 4. Ошибки и контракты

| что | механизм | когда |
|---|---|---|
| ожидаемая ошибка (файл не найден, Vulkan вернул ошибку) | «значение или ошибка»: тип ошибки — объявленная сумма типов, может нести данные (Р41); `try` передаёт выше; `errdefer` чистит; молча проигнорировать нельзя (Р10) | обрабатывается кодом |
| невозможное и внутренний сбой (выход за границы, переполнение, нарушенный контракт, `unreachable`, ложный `assert`) | ловушка: детерминированная остановка с диагностикой (Р36) | ошибка программы |
| контракты | `pre`/`post` в сигнатуре, `assert` в теле; проверяются в `debug` и `release` (Р11); дорогие — с пометкой, только в `debug` и `test` | Р13 |
| инварианты типов | после v1.0, если понадобятся (О14) | — |
| исчерпывающий разбор | компилятор проверяет полноту `match` по суммам типов | всегда |
| проверка при компиляции | константы и статические утверждения о константах (Р42) | всегда |
| ошибки платформы | сгенерированные привязки переводят коды (`VkResult`, `errno`, `HRESULT`) в «значение или ошибка»; сырой вызов — в `unsafe` | раздел 5 |

Скрытого потока управления нет: выход — `return`, `try`, `break` и
`continue`, ловушка; `defer` срабатывает на видимой границе области.

## 5. Взаимодействие с native-миром (Р17, Р30)

| что | как |
|---|---|
| вызов C | объявления `extern`, сгенерированные из заголовков шагом сборки |
| вызов dpl из C | экспорт с генерацией заголовка C |
| native-структуры | `extern`-структуры с раскладкой C; явные `align`/`packed` — только у них; размеры и смещения проверяются статическими утверждениями в привязках |
| указатели на функции, обратные вызовы | тип `extern`-функции; контекст обратного вызова — сырой адрес в `unsafe`; для известных шаблонов генератор делает безопасную обёртку |
| границы владения | у каждого API записано, кто выделяет и кто освобождает; чужие дескрипторы — ресурсные типы; строки C — с явным выделением |
| правила безопасности FFI | вызов внешнего кода — `unsafe`, кроме объявлений, признанных безопасными правилами генератора или ревью; нулевой адрес — тип «может не быть» |
| Vulkan | привязки из `vk.xml`: дескрипторы — разные типы, `VkResult` — ошибки, помощь с цепочками `sType`/`pNext`, загрузка функций |
| платформенные SDK | Android NDK, JNI, AAudio, Win32 — через их C API, привязки из заголовков где возможно |
| C++ | только через C-прослойку `extern "C"`, написанную на C++ (вручную или генератором для простых случаев); шаблоны C++ — никогда |
| смешанная программа | dpl → C → тот же компилятор и линкер, что у кода C++; поставка модуля dpl — статическая библиотека + заголовок C для хоста C++ (CMake, Gradle) |

До v1.0 смешанные программы с VoxelRPG — только proof-of-concept вне его
обязательной части (Р22).

## 7. Слои: язык, стандартная библиотека, runtime, внешние пакеты (Р19)

Правило: **примитив языка** — то, что требует синтаксиса, типизации или
проверки компилятором; **стандартная библиотека** — код на dpl с
версионированным API (кроме встроенных функций); **runtime** — связка с
целью; **внешний пакет** — всё прочее.

| область | язык | стандартная библиотека | runtime | внешний пакет |

| коллекции | массивы, срезы | динамический массив, упорядоченная хэш-таблица (О12), множество, пул и хэндлы, кольцевой буфер | — | пространственные индексы; ECS — кандидат в библиотеку (Р19) |
