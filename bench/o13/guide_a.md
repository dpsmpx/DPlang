# Параллелизм в dpl: модель задач А (блок задач)

Это руководство дополняет спецификацию: параллелизм в ней ещё не описан.

## Параллельный цикл

`parallel for i in 0..n { … }` (и `parallel for x in &xs`, `&mut xs`) —
итерации идут одновременно в пуле потоков. Тело не выходит из цикла
(`break`, `return`, `fail`, `try` — ошибка; `continue` кончает итерацию),
пишет снаружи только элемент по переменной диапазона (`out[i] = …`,
`out[i].push(v)`; у обхода `&mut xs` — сам элемент) и читает такую
переменную только так же; файлов,
аргументов программы, функций C и задач в теле нет — и в функциях, которые
оно зовёт. Вывод (`println`) выходит в порядке итераций.

```dpl
var sums: List[i64] = repeat(i64(0), parts)
parallel for p in 0..parts {
    sums[p] = sum_part(&xs, p, parts)
}
```

## Общие значения

Создаются встроенными функциями, тип — из записи переменной:

| значение | создание | методы |
|---|---|---|
| `Atomic[T]` (целое или `bool`) | `let c = atomic(i64(0))` | `c.load()`, `c.store(v)`, `c.add(v)` и `c.sub(v)` (→ прежнее; переполнение — ловушка), `c.swap(v)` (→ прежнее), `c.cas(old, new)` (→ `bool`) |
| `Mutex[T]` | `let m = mutex(v)` | блок `lock m as t { … }`: `t` — данные мьютекса до конца блока; снятие — на любом выходе; повторный `lock` тем же потоком — ловушка |
| `Channel[T]` | `let ch: Channel[T] = channel(n)` (ёмкость `n >= 1`) | `ch.send(v)` (ждёт места; в закрытый — ловушка), `ch.recv()` → `?T` (ждёт; `none` — закрыт и пуст), `ch.try_recv()` → `?T` (не ждёт), `ch.close()` (повторно — ловушка) |

Все операции атомиков — с последовательной согласованностью. Если все
потоки ждут канала, задач или конца блока — ловушка `deadlock`. Общие
значения нельзя использовать в функциях класса D (`@det`).

В этой модели общие значения не копируются: они живут в переменной,
созданной `atomic`, `mutex` или `channel`, и передаются по ссылке `&c`
(в поле, список и по значению их не положить — ошибка E0518).

## Задачи: блок `tasks`

```dpl
tasks {
    spawn load(&q, 1)
    for w in 0..workers {
        spawn work(&q, w, &mut out[w])
    }
    // код блока идёт в текущем потоке одновременно с задачами
}
// здесь все задачи блока кончились
```

- `spawn f(args)` — задача: вызов функции dpl в своём потоке. Функция
  ничего не возвращает: результат — через параметр `&mut`.
- Аргументы-значения копируются в задачу. `&x` и `&mut x` — только
  переменных, объявленных до блока; задача держит их до конца блока.
- Пока блок идёт, место, взятое задачей по `&mut`, не трогает больше
  никто (ни другие задачи, ни код блока); место, взятое по `&`, никто не
  меняет. `spawn` в цикле ставит задачу на каждой итерации, поэтому
  `&mut` — элемент по переменной диапазона (`&mut out[w]` у `for w in
  0..n`) или сам элемент обхода `&mut xs`. Общие значения
  (`Atomic`, `Mutex`, `Channel`) задачи делят по `&` свободно.
- Из блока не выходят раньше (`break`, `continue` за блок, `return`,
  `fail`, `try` — ошибка): блок кончается, когда кончились его задачи.
  Менеджер не может уйти раньше своих задач — для отмены нужен общий
  флаг `Atomic[bool]`, который задачи проверяют сами.
- Вывод задачи выходит после блока, по порядку запуска задач.
- Срезы и дескрипторы C в задачу не передаются.
