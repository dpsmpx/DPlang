# t22. Три расчёта одновременно, буфер на рабочего

Три разных расчёта над одним списком слов идут одновременно (fork-join);
первый из них сам делится между рабочими, и у каждого рабочего свой
буфер, который он переиспользует от слова к слову.

## Интерфейс

- `Stats` — структура: `distinct: список i64` (27 чисел), `longest: str`,
  `anagrams: i64`.
- `analyze(words: ссылка на список str, workers: i32) -> Stats` — три
  расчёта идут одновременно; функция возвращает, когда кончились все:
  1. `distinct[k]` — число слов, в которых ровно `k` разных букв `a`–`z`
     (другие байты не считаются). Слова делятся между `workers`
     рабочими (`workers >= 1`) частями подряд: рабочий `w` берёт слова с
     номерами от `n * w / workers` до `n * (w + 1) / workers` (без
     последнего). У каждого рабочего — свой буфер из 26 отметок, который
     он очищает перед каждым словом (без нового выделения на слово);
     счётчики рабочих складываются после;
  2. `longest` — первое из самых длинных слов (длина в байтах); у пустого
     списка — пустая строка;
  3. `anagrams` — число пар соседних слов `words[i]`, `words[i+1]`,
     которые анаграммы друг друга: у них одинаковые счётчики байтов
     (одинаковые слова — тоже анаграммы).

Работа действительно идёт в нескольких потоках; общих изменяемых данных
без синхронизации нет.

## Проверки

Драйвер — `expected.txt`: большой список при 1, 4 и 7 рабочих (итог не
зависит от их числа), пустой список, малые списки.
