# t20. Фоновая сборка по заказу

Игровой цикл заказывает сборку чанков в фоне и забирает готовые
результаты опросом раз в кадр, не дожидаясь их. Новый заказ того же
чанка делает прежний устаревшим. Менеджер может уйти раньше, чем
кончились заказы.

## Интерфейс

- `build(chunk: i64, seed: u64) -> i64` — дано в заготовке: чистая
  дорогая функция (сборка чанка).
- `Cmd` — структура команды сценария: `kind: i32`, `chunk: i64`,
  `seed: u64`.
- `run(script: ссылка на список Cmd, limit: i32) -> список str` —
  исполняет команды по порядку и возвращает строки вывода:
  - `kind = 0` — **заказ**: номер заказа — следующий по порядку (с 1);
    сборка `build(chunk, seed)` идёт в фоне, игровой цикл её не ждёт;
    заказ делает устаревшими прежние заказы того же чанка;
  - `kind = 1` — **кадр**: забрать готовые результаты, не больше `limit`
    за кадр, не ожидая остальных; результат устаревшего заказа
    выбрасывается, остальные применяются: значение чанка — результат;
  - `kind = 2` — **сверка**: дождаться всех заказов и забрать все
    результаты (без предела, устаревшие — выбросить), затем добавить
    строку `sync K: C1=V1 C2=V2 ...` — `K` — номер сверки (с 1), чанки с
    применённым значением по возрастанию; без них — `sync K:`;
  - `kind = 3` — **уход**: менеджер уходит, не дожидаясь незаконченных
    заказов; их результаты не применяются; остальные команды не
    исполняются.

  `limit >= 1`. Функция может вернуться, пока сборки ещё идут (после
  ухода); программа при этом не должна падать или терять память иначе
  чем по правилам языка.

Сборки идут в нескольких потоках одновременно; общих изменяемых данных
без синхронизации нет.

## Проверки

Драйвер — `expected.txt`: сценарий из заказов, кадров и сверок с
устаревшими заказами, уход с незаконченными заказами, пустой сценарий.
