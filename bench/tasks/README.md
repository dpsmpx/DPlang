# Эталонный набор задач (v0.0, шаг 0.1)

Мера целей языка (`docs/direction/GOAL.md`, раздел 2): одни и те же задачи
решаются на C++ и на вариантах синтаксиса C- (`ROADMAP/IMPLEMENTATION.md`,
v0.0). Набор — **внутренний материал** (Р5): не публикуется. Кода VoxelRPG
в нём нет — задачи описаны заново и лишь похожи по роду на работу движка и
игры.

## Состав

| задача | что проверяет | род работы |
|---|---|---|
| `t01_ring` | структуры, «может не быть», ошибки | контейнер |
| `t02_toml_line` | строки, разбор, суммы типов, ошибки, края `i64` | контент, разбор |
| `t03_npc_fsm` | суммы типов, исчерпывающий `match`, правила с приоритетом | игровая логика, ИИ |
| `t04_handle_pool` | хэндлы с поколением, устаревшие ссылки | сущности, память |
| `t05_keyed_rng` | беззнаковая арифметика по модулю 2^64, детерминизм | процедурная генерация |
| `t06_greedy_mesh` | двумерные массивы, точный алгоритм | мир и чанки |
| `t07_grid_path` | очередь, поиск в ширину, «может не быть» | ИИ, поиск пути |
| `t08_aabb_pairs` | сортировка, обход, стабильный порядок вывода | физика |
| `t09_inventory` | правила с краевыми случаями, ошибки без изменения состояния | игровые системы |
| `t10_delta_codec` | байты, varint, zigzag, все пути ошибок | сохранение, сериализация |
| `t11_fixed_physics` | фиксированная точка, деление к нулю, `i64` | физика, детерминизм |
| `t12_bugfix_average` | исправление ошибок в чужом коде, а не написание заново | сопровождение |

## Устройство задачи

- `task.md` — постановка и интерфейс (в нейтральной записи: в каждом
  варианте синтаксиса интерфейс записывается своим способом).
- `ref.cpp` — эталон на C++20: над строкой `// --- driver ---` — решение,
  под ней — драйвер, печатающий результаты.
- `expected.txt` — ожидаемый вывод драйвера.
- `buggy.cpp` (только `t12`) — версия с ошибками, которую нужно исправить.

В опыте (шаг 0.5) модель получает `task.md`, краткую спецификацию варианта
и драйвер на этом варианте и пишет решение; решение принято, если вывод
драйвера совпадает с `expected.txt`.

## Проверка

```sh
python3 bench/run_refs.py          # входит в tools/check/run.sh
python3 bench/run_refs.py --bless  # переписать expected.txt — только осознанно
```

Эталоны собираются с `-Wall -Wextra -Werror`, без исключений и RTTI, под
ASan и UBSan (если компилятор их умеет). Для `t12` проверяется ещё, что
`buggy.cpp` **не** проходит. `--bless` — только после ручной сверки вывода
с постановкой; дифф `expected.txt` — на ревью.
