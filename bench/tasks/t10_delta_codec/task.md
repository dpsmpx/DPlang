# t10. Кодек правок мира

Правка — `Edit { x: i32, y: i32, z: i32, block: i32 }` (`block` 0…65535).
Список правок кодируется в байты:

1. число правок — беззнаковый varint (LEB128: по 7 бит, младшие первыми,
   старший бит байта — «есть продолжение»);
2. для каждой правки: `dx`, `dy`, `dz` — разность с предыдущей правкой
   (для первой — с `(0, 0, 0)`), вычисленная в `i64`, в кодировке zigzag
   (`(n << 1) ^ (n >> 63)`) и затем varint; потом `block` — varint.

Декодирование — обратное; ошибки:

- `Truncated` — данные кончились посреди значения;
- `BadValue` — varint длиннее 10 байт, координата вне `i32` или `block`
  вне 0…65535;
- `TrailingBytes` — после последней правки остались байты.

## Интерфейс

- `encode(edits: срез Edit) -> список u8`
- `decode(bytes: срез u8) -> ошибка DecodeError | список Edit`

## Проверки

Драйвер печатает байты в шестнадцатеричном виде, результат обратного
декодирования и ошибки на испорченных данных (`expected.txt`).
