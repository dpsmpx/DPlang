# t21. Шаг симуляции с упорядоченной свёрткой

Цепочка грузов на пружинах: `n` грузов на прямой, оба конца цепочки
закреплены (за краями смещение равно 0). Шаг считается в нескольких
потоках, итог не зависит от их числа (`docs/policy/DETERMINISM.md`).

## Интерфейс

- `simulate(x: срез f64, steps: i32, threads: i32) -> список f64` —
  начальные смещения `x`, скорости равны 0. Константы: `K = 0.25`,
  `DT = 0.1`. Шаг:
  1. для каждого `i` по состоянию **до** шага: `f = K * (l - 2.0 * x[i] + r)`,
     где `l = x[i-1]` (0.0 у `i = 0`), `r = x[i+1]` (0.0 у `i = n-1`);
  2. `v[i] = v[i] + f * DT`, затем `x[i] = x[i] + v[i] * DT` — в новое
     состояние: шаг читает только прежнее;
  3. энергия шага `E` по новому состоянию: `E = 0.0`, затем для `i` по
     возрастанию `E = E + 0.5 * v[i] * v[i]` и `E = E + 0.5 * K * d * d`,
     где `d = x[i] - x[i-1]` (`x[i] - 0.0` у `i = 0`); в конце
     `E = E + 0.5 * K * x[n-1] * x[n-1]` (у пустой цепочки `E = 0.0`).

  Результат — энергии всех шагов по порядку (`steps = 0` — пустой
  список). Пункты 1 и 2 считаются в `threads` потоках (`threads >= 1`)
  по частям массива; энергия — в порядке индексов, поэтому итог
  побитово одинаков при любом `threads`.

Произведения считаются слева направо: `0.5 * v * v` — это `(0.5 * v) * v`.
Работа действительно делится между потоками; общих изменяемых данных без
синхронизации нет.

## Проверки

Драйвер — `expected.txt`: энергии большой цепочки при одном потоке и
совпадение итога при 3 и 8 потоках, малые цепочки. Числа `f64`
печатаются с 17 значащими цифрами.
