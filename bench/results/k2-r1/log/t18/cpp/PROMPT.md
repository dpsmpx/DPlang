## t18. Исправление ошибок: планировщик событий

Дана реализация с ошибками (начальный код задачи): планировщик событий
на двоичной куче. Ошибок несколько, и они в разных функциях. Нужно найти
и исправить их, не переписывая решение заново: мера задачи — точность
правки. Устройство (куча, отмена пометкой, счётчик ожидающих) менять не
нужно.

### Что должно получаться

Планировщик хранит текущее время `now` (сначала 0) и события. Событие —
номер `id`, время `at`, приоритет, период `every` и имя.

- `sched_new() -> Scheduler` — пустой планировщик.
- `sched_add(s, at: i64, priority: i32, every: i64, name: str) ->
  ошибка BadTime | i32` — добавляет событие и возвращает его номер:
  1, 2, 3, … по порядку успешных добавлений. `at < now` или
  `every < 0` — ошибка `BadTime`, планировщик не меняется. `at == now`
  допустимо. `every == 0` — событие разовое, иначе — периодическое.
- `sched_cancel(s, id: i32) -> ошибка NotFound | ok` — отменяет
  ожидающее событие (у периодического — все его будущие срабатывания).
  Нет события с таким номером, оно уже отменено или (разовое) уже
  сработало — `NotFound`.
- `sched_run(s, until: i64) -> список строк` — срабатывают по очереди все
  ожидающие события с `at <= until`. Очередь: по возрастанию `at`, при
  равном `at` — по убыванию приоритета, при равных — по возрастанию
  `id`. Срабатывание даёт строку `"AT NAME"`. Периодическое событие
  после срабатывания снова ждёт, со временем `at + every` и тем же
  `id` и приоритетом; если это время тоже `<= until`, оно сработает в
  этом же вызове — в своё место очереди. После вызова `now = until`
  (если `until < now`, ничего не срабатывает и `now` не меняется).
- `sched_pending(s) -> i32` — сколько событий ждёт (отменённые не
  считаются).
