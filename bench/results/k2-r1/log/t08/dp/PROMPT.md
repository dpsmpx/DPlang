## t08. Пересекающиеся пары AABB

Прямоугольники `Box { min_x, min_y, max_x, max_y: i32 }` (`min < max`).
Пара пересекается, если строго `a.min_x < b.max_x && b.min_x < a.max_x`
и то же по `y` (касание краёв — не пересечение).

### Интерфейс

- `overlapping_pairs(boxes: срез Box) -> список Pair` — все пары `(i, j)`,
  `i < j`, по возрастанию `i`, затем `j`. Алгоритм — любой (в том числе
  сортировка и проход по оси).

### Проверки

Драйвер печатает число пар и сами пары (`expected.txt`), в том числе на
200 прямоугольниках из детерминированного генератора.

## Спецификация dpl (ядро v0.1)

### 1. Лексика

**[lex.source]** Исходный файл модуля — текст в UTF-8 с расширением
`.dpm` (Р46). Неверная последовательность UTF-8 в любом месте файла —
ошибка E0101.

**[lex.newline]** Конец строки — LF (`\n`) или CRLF (`\r\n`). Одиночный
CR — ошибка E0108. Конец строки значим: он завершает инструкцию
(раздел 2).

**[lex.space]** Пробел и табуляция разделяют токены и иначе не значат
ничего.

**[lex.comment]** Комментарий — от `//` до конца строки. Он стоит на
своей строке или после кода в конце строки. Блочных комментариев нет.

**[lex.ident]** Имя — латинская буква или `_`, затем латинские буквы,
цифры и `_`: `count`, `_tmp`, `Vec2`. Регистр различается. `_` отдельно —
имя-заглушка: отбросить значение, пропустить переменную цикла.

**[lex.keyword]** Ключевые слова не могут быть именами:

```
fn struct enum const import pub let var if else while for in match
return break continue defer fail try parallel none true false mut
```

Зарезервированы на будущее (E0109): `unsafe extern errdefer`. Слова
`some`, `ok`, `err` — не ключевые: они значат особое только в образцах
`match` (раздел 6).

**[lex.int]** Целый литерал:
- десятичный `42`;
- шестнадцатеричный `0xFF`;
- двоичный `0b1010`;
- восьмеричный `0o17`.

`_` стоит только между двумя цифрами: `1_000_000`, `0xFFFF_FFFF`.
Значение — не больше 2^64 − 1 (иначе E0106); подходит ли оно типу,
решает проверка типов (раздел 4). Знака у литерала нет: `-1` — унарный
минус и литерал. Буква или цифра сразу за литералом — ошибка E0107.

**[lex.float]** Литерал с плавающей точкой — цифры, точка и цифры
(`1.5`, `0.25`) и/или порядок `e`/`E` со знаком (`2e10`, `1.5e-3`). Цифры
есть по обе стороны точки: `1.` и `.5` — не литералы. `1..5` — литерал `1`,
оператор `..` и литерал `5`. Значение вне `f64` — ошибка E0110.

**[lex.str]** Строковый литерал — текст между `"` на одной строке
исходника (иначе E0103). Он может содержать любые символы, кроме `"`,
`\` и управляющих символов (E0102). Табуляция — допустима. Значение —
байты UTF-8.

**[lex.escape]** Экранирование в строковом и байтовом литералах:

| запись | значение |
|---|---|
| `\n` `\t` `\r` `\0` | перевод строки, табуляция, возврат каретки, байт 0 |
| `\\` `\"` `\'` | обратная косая, кавычка, апостроф |
| `\xHH` | байт с кодом HH (две шестнадцатеричные цифры) |
| `\u{H…}` | символ Unicode — 1–6 шестнадцатеричных цифр, без суррогатов, не больше U+10FFFF; только в строке |

В строке `\xHH` — не больше `\x7f`, чтобы строка осталась UTF-8. Иначе —
ошибка E0104.

**[lex.byte]** Байтовый литерал — один символ ASCII (кроме `'` и `\`)
или одно экранирование между `'`: `'a'`, `'\n'`, `'\xff'`. Тип — `u8`.
Иначе — ошибка E0105.

**[lex.punct]** Операторы и знаки:

```
+  -  *  /  %  +%  -%  *%  &  |  ^  ~  <<  >>  !  &&  ||
== != <  <= >  >=  ??  =  += -= *= /= %= &= |= ^= <<= >>=
.  .. ,  :  => (  )  [  ]  {  }  ?  @
```

Из нескольких подходящих знаков берётся самый длинный: `a<<=b` — это
`a`, `<<=`, `b`. `;` лексер узнаёт, но в грамматике его нет: инструкция
кончается концом строки (раздел 2). Другой символ вне строки и
комментария — ошибка E0102.

### 2. Грамматика

**[syntax]** Запись ниже — EBNF: `{x}` — ноль и больше раз, `[x]` —
необязательно, `|` — выбор, в кавычках — токены. `NL` — один или
несколько концов строки. Разбор не зависит от типов (Р7).

```
module   = { item NL } .
item     = { "@" ident NL } [ "pub" ] ( fn | struct | enum | const ) | "import" ident .
fn       = "fn" ident "(" [ param { "," param } [ "," ] ] ")" [ type ] block .
param    = ident ":" [ "&" [ "mut" ] ] type .
struct   = "struct" ident "{" { field SEP } "}" .
field    = ident ":" type [ "=" expr ] .
enum     = "enum" ident "{" { variant SEP } "}" .
variant  = ident [ "(" type { "," type } ")" | "{" field { "," field } "}" ] .
const    = "const" ident ":" type "=" expr .
SEP      = NL | "," .

type     = "?" type | "!" type | "[" "]" type
         | path [ "[" type { "," type } "]" ] [ "!" type ] .
path     = ident [ "." ident ] .

block    = "{" { stmt NL } "}" .
stmt     = ( "let" | "var" ) ident [ ":" type ] [ "=" expr ]
         | expr [ assignop expr ]
         | "if" cond block [ "else" ( if | block ) ]
         | "while" expr block
         | [ "parallel" ] "for" ident "in" ( "&" [ "mut" ] expr | expr [ ".." expr ] ) block
         | "match" expr "{" { pattern "=>" ( block | stmt ) NL } "}"
         | "return" [ expr ] | "break" | "continue" | "fail" expr
         | "defer" ( block | stmt ) | block .
cond     = expr | "let" ident "=" expr .
assignop = "=" | "+=" | "-=" | "*=" | "/=" | "%=" | "&=" | "|=" | "^=" | "<<=" | ">>=" .

pattern  = alt { "|" alt } .
alt      = "_" | ident | "none" | literal | "-" number
         | ( "some" | "ok" | "err" ) "(" pattern ")"
         | ( "." | ident { "." ident } "." ) ident [ "(" pattern { "," pattern } ")" | "{" fpat { "," fpat } "}" ] .
fpat     = ident [ ":" pattern ] .

expr     = unary { binop unary } .              (приоритеты — expr.prec)
unary    = ( "-" | "!" | "~" | "try" | "&" [ "mut" ] ) unary | postfix .
postfix  = primary { "(" [ expr { "," expr } [ "," ] ] ")" | "[" expr "]"
         | "[" [ expr ] ".." [ expr ] "]" | "." ident | "{" inits "}" } .
primary  = literal | ident | "(" expr ")" | "[" [ expr { "," expr } [ "," ] ] "]"
         | "." ident [ "(" [ expr { "," expr } ] ")" | "{" inits "}" ] .
inits    = [ ident [ ":" expr ] { "," ident [ ":" expr ] } [ "," ] ] .
```

**[syntax.newline]** Конец строки завершает объявление, поле, вариант,
инструкцию и ветвь `match`. Он не завершает их:

- внутри `( )` и `[ ]`;
- внутри фигурных скобок литерала структуры и варианта;
- после бинарного оператора, `=` и оператора присваивания.

Перед `else` перенос допустим. Метод на новой строке (`.name` в начале
строки) не продолжает выражение.

**[syntax.item]** Объявления верхнего уровня — `fn`, `struct`, `enum`,
`const`, `import`. Они идут по одному на строке.
- `pub` делает объявление видимым другим модулям (раздел 3); у `import`
  его нет (E0206).
- Атрибут `@имя` стоит только перед функцией (E0205); `@det` — класс
  детерминированного кода (Р12), `@test` — тест (module.test).
  Другой атрибут и повтор атрибута — E0319.
- Поля структуры и варианты перечисления — по одному на строке или через
  запятую.

**[syntax.type]** Типы в записи:

| запись | тип |
|---|---|
| `T`, `m.T` | тип по имени; из модуля `m` |
| `List[T]` | встроенный обобщённый тип (Р42) |
| `[]T` | срез |
| `?T` | может не быть |
| `E!T` | значение `T` или ошибка из перечисления `E` (Р41) |
| `!T` | то же с выводимым типом ошибки (Р41) |

**[syntax.stmt]** Инструкция занимает строку. `;` в языке нет (E0202);
лишние токены после инструкции — ошибка E0204.
- `let` требует начального значения.
- `var` может обойтись без него, если указан тип; тогда переменная
  получает значение позже (раздел 4).

**[syntax.block]** Блок — `{`, инструкции по одной на строке, `}`. Пустой
блок — `{` и `}` на соседних строках. В заголовке `if`, `while`, `for` и
`match` литерал структуры без скобок не пишется: `if p == (Point { x: 0 })`.
Иначе `{` начинает тело.

**[syntax.pattern]** Образцы `match` — раздел 6. `some`, `ok` и `err`
значат особое только перед `(`.

**[syntax.nesting]** Глубина вложенности — предел реализации. Считаются
выражения, инструкции, блоки, образцы и типы внутри друг друга, в том
числе цепочки операторов и постфиксов: `1 + 1 + …`, `x.f().g()…`.
Глубже предела — ошибка E0002, и модуль дальше не проверяется. Предел
`dpl` — 2000 уровней; онлайн-профиль задаёт меньший (Р49). Программа,
принятая с меньшим пределом, принимается и с большим.

**[expr.prec]** Бинарные операторы — от слабого к сильному. Внутри
уровня — слева направо.

| уровень | операторы |
|---|---|
| 1 | `\|\|` |
| 2 | `&&` |
| 3 | `== != < <= > >=` — не сцепляются: `a < b < c` — ошибка E0203 |
| 4 | `??` |
| 5 | `+ - \| ^ +% -%` |
| 6 | `* / % << >> & *%` |

`<<`, `>>` и `&` — того же уровня, что `*`: `x << 7 * i` — это
`(x << 7) * i`, `v & 0x7f | 0x80` — `(v & 0x7f) | 0x80`.

**[expr.unary]** Унарные `-`, `!`, `~`, `try` и пометки `&x`, `&mut x`
сильнее бинарных: `try f() + 1` — это `(try f()) + 1`. Пометка `&` и
`&mut` стоит только у аргумента вызова и после `for … in` (раздел 8).

**[expr.postfix]** Вызов, индекс, срез и поле сильнее унарных:
`-a.b[i]` — это `-((a.b)[i])`.

### 3. Модули и имена

**[module.file]** Модуль — один файл `.dpm` (Р46). Имя модуля — имя
файла без расширения; оно должно быть именем и не ключевым словом
(E0317). Программа — главный модуль, который назван компилятору, и все
модули, которые он импортирует.

**[module.import]** `import world` делает модуль `world` видимым в этом
файле.
- Поиск — `world.dpm` рядом с главным модулем программы, затем
  стандартная библиотека; не найден — ошибка E0302.
- Повторный `import` того же модуля в одном файле — ошибка E0303.

**[module.graph]** Импорты не образуют цикла, в том числе модуль не
импортирует сам себя (E0301). Модули проверяются в порядке зависимостей.

**[module.scope]** Имена верхнего уровня модуля — его функции,
структуры, перечисления, константы и импортированные модули.
- Повтор имени — ошибка E0304.
- Совпадение с именем импортированного модуля — ошибка E0305.
- Повтор поля, варианта или параметра — ошибка E0318.

Порядок объявлений не важен: функция может вызвать функцию, объявленную
ниже.

**[module.pub]** Другим модулям видно только объявленное с `pub`
(иначе E0306).
- Поля открытой структуры и варианты открытого перечисления открыты
  вместе с ней.
- Открытое объявление не упоминает закрытых типов: ни в сигнатуре, ни
  в полях, ни в вариантах (E0309).

**[module.lookup]** Имя в выражении ищется по порядку:
1. локальная переменная;
2. объявление модуля или импортированный модуль;
3. встроенная функция или встроенный тип (раздел 9).

Не найдено — ошибка E0307. Член модуля — `world.spawn`, `world.Unit`;
вариант перечисления — `Event.Tick`, `world.Kind.Wall`. Нет такого
члена — E0311, нет варианта — E0312.

**[module.local]** Локальные имена — параметры, `let` и `var`,
переменная цикла, `if let`, имена в образцах. Имя видно от объявления
до конца его блока; переменная `let` и `var` — со следующей инструкции.
- Затенения нет: локальное имя не повторяет другое локальное имя,
  видимое в этом месте функции (E0310). В соседних блоках имена могут
  повторяться.
- `_` — не имя: оно отбрасывает значение (`_ = f()`), пропускает
  переменную цикла и подходит к любому значению в образце.

**[module.summary]** Сводка модуля — его открытые объявления с
разрешёнными типами (Р14): сигнатуры функций, поля структур, варианты
перечислений, типы констант. Тел функций и значений констант в ней нет.
Зависимый модуль проверяется по сводке, поэтому правка тела сводку не
меняет. Публичная функция поэтому пишет тип ошибки явно (Р41,
раздел 7). `dpl debug summary` печатает сводки программы.

**[module.main]** Программа начинается с функции `main` главного модуля.
У `main` нет параметров; она не возвращает значения или возвращает
`E!void` (`!void`), если может не удаться. Нет `main` или у неё другая
сигнатура — ошибка E0322 при запуске и сборке программы. Модулю, который
только импортируют, `main` не нужна, и проверка модуля (`dpl check`)
её не требует. Как программа завершается — раздел 10, trap.exit.

**[module.test]** Тест — функция с атрибутом `@test` (Р50). У неё нет
параметров; она не возвращает значения или возвращает `E!void`
(`!void`). Другая сигнатура — ошибка E0323. Команда `dpl test`
исполняет тесты всех модулей программы, кроме стандартной библиотеки,
по порядку модулей и объявлений, каждый — отдельным процессом. Тест
прошёл, если вернулся без ловушки и без ошибки. В остальном тест —
обычная функция: её можно вызвать, а `main` для тестов не нужна.

### 4. Типы

**[type.names]** Встроенные типы:

| тип | что это |
|---|---|
| `i8 i16 i32 i64`, `u8 u16 u32 u64` | целые фиксированной ширины |
| `int` | то же, что `i64`: целое размера адреса на целях первой волны (64 бита) |
| `f32 f64` | IEEE 754 binary32 и binary64 |
| `bool` | `true`, `false` |
| `str` | строка: байты UTF-8 (Р42), неизменяемая |
| `List[T]` | динамический массив, владеет элементами |
| `[]T` | срез — представление элементов без владения, только для чтения |
| `?T` | значение `T` или `none` |
| `E!T` | значение `T` или ошибка — вариант перечисления `E` (раздел 7) |

Ещё — объявленные `struct` и `enum`. `void` пишется только как значение
результата: `!void`, `E!void`. Неверное число аргументов типа — E0314.
Неизвестный тип — E0313. Пользовательских обобщённых типов в v0.1 нет
(Р42).

**[type.enum]** Вариант перечисления:
- без данных — `Tick`;
- с позиционными данными — `Move(i32, i32)`;
- с полями — `Hit { target: i32, damage: i32 }`.

Значение пишется так же, как объявлен вариант (E0414). Вариант с данными
без данных — ошибка.

**[type.recursive]** Структура или перечисление не содержит значения
своего типа (E0423): ни в поле, ни в данных варианта, ни через `?T`,
`E!T` или другую структуру и перечисление. У такого значения не было бы
конца. Вложенные значения своего типа хранятся в `List`:
`children: List[Tree]`.

**[type.conv]** Неявно — только преобразования без потерь (Р42):
- целое в более широкое целое, вмещающее все его значения: `i32 → i64`,
  `u8 → i32`; но не `i32 → u32` и не `u64 → i64`;
- `f32 → f64`;
- `List[T] → []T`;
- `T → ?T` и `T → E!T` (обёртка).

Остальное — явно (раздел 5, expr.convert); иначе — ошибка E0401. Целое и
плавающее неявно друг в друга не переходят.

### 5. Выражения

**[expr.literal]** Литерал получает тип из контекста:
- целый литерал — тип ожидаемого целого или плавающего; без контекста —
  `int`; вне диапазона типа — E0402;
- литерал с точкой — `f32` или `f64` по контексту, иначе `f64`;
- `'a'` — `u8`;
- `none`, `[]` и краткий вариант `.V` требуют ожидаемого типа (E0404).

У `.V` без ожидаемого типа берётся единственное видимое перечисление с
этим вариантом. Контекст — тип переменной, параметра, поля, результата,
элемента списка или другого операнда: в `x + 1` литерал получает тип `x`.

**[expr.names]** Имя функции, типа или модуля — не значение (E0405).
Функции вызываются, типы стоят в записи типов, преобразованиях и
литералах, модули — перед точкой.

**[expr.ops]** Операнды бинарного оператора приводятся к общему типу —
тому, к которому другой операнд преобразуется неявно (иначе E0401).

| операторы | операнды | результат |
|---|---|---|
| `+` | числа или `str` (склейка) | общий |
| `- * /` | числа | общий |
| `%`, `& \| ^`, `+% -% *%` | целые | общий |
| `<< >>` | целое; число сдвига — любое целое | тип левого |
| `&& \|\| !` | `bool` | `bool` |
| `-` унарный | знаковое целое или плавающее | тот же |
| `~` | целое | тот же |
| `??` | слева `?T`, справа `T` | `T` |

Не подходит — E0403. `a ?? b` — значение `a`, если оно есть, иначе `b`.
Поведение во время выполнения (переполнение, деление на ноль, сдвиг) —
раздел 10.

**[expr.order]** Выражение вычисляется слева направо.
- Операнды бинарного оператора, аргументы вызова, элементы списка и
  значения полей литерала — в порядке записи. У метода сначала
  вычисляется получатель (у изменяющего метода — его место), затем
  аргументы.
- В присваивании `p = e` сначала вычисляется место `p` (его индексы),
  затем `e`. В `x op= e` значение `x` читается до `e`.
- `&&` и `||` вычисляют правую часть, только если левой мало для ответа.
  `a ?? b` вычисляет `b`, только если у `a` нет значения.

Вызов, который меняет переменную через `&mut`, не меняет уже
вычисленные левее операнды: `c + bump(&mut c)` складывает прежнее `c`
с результатом вызова.

**[expr.compare]**
- `==` и `!=` сравнивают значения целиком, кроме результатов `E!T`.
- `< <= > >=` определены для чисел, `bool`, `str` (по байтам), а также
  для структур (по полям по порядку), перечислений (по номеру варианта,
  затем по данным) и списков (по элементам), если упорядочены их части.

Иначе — ошибка E0422.

**[expr.field]** `a.f` — поле структуры. Нет поля — E0406. У ссылок `&T`
поля читаются так же, как у значения.

**[expr.struct]** Литерал структуры `S { f: e, g }` даёт каждое поле
один раз.
- `g` — то же, что `g: g`.
- Поля со значением по умолчанию можно не писать.
- Лишнее, повторённое или пропущенное поле — E0413.
- Вариант с полями пишется так же: `E.V { ... }`, `.V { ... }`; у его
  полей значений по умолчанию нет.

**[expr.call]** Вызов `f(a, b)` передаёт столько аргументов, сколько
параметров (E0407). Пометка аргумента совпадает с режимом параметра
(E0408): `&x` для `&T`, `&mut x` для `&mut T`, без пометки для значения.
Тип помеченного аргумента равен типу параметра точно. Вызвать можно:
- функцию;
- встроенную функцию;
- метод `List` и `str`;
- преобразование `T(x)` и `T.wrap(x)`;
- вариант с позиционными данными `E.V(a)`.

Остальное — E0409.

**[expr.convert]** Явные преобразования (E0418 — недопустимое):
- `T(x)` между числовыми типами проверяется: значение вне `T` — ловушка;
  из плавающего в целое — с отбрасыванием дробной части к нулю. Литерал
  в `T(5)` получает тип `T` сразу, вне диапазона — ошибка компиляции.
- `T.wrap(x)` — целое в целый тип `T` по модулю 2^N: `u32.wrap(-1)` —
  `4294967295`.
- `str(x)` — запись числа, `bool` или строки строкой:
  - целое — десятичная запись, у отрицательного — `-`;
  - `bool` — `true` или `false`;
  - плавающее — наименьшее число значащих цифр (от 1 до 17), с
    которым запись читается обратно в то же число (у `f32` — в то же
    `f32`), Р48. Из таких записей берётся ближайшая к числу, из двух
    одинаково близких — с чётной последней цифрой: у `f32` 3739017.75 —
    `3739017.8`. При десятичном порядке от −4 до 15 форма обычная, без
    хвоста `.0`: `0.1`, `100`, `0.0001`. Иначе — экспоненциальная, с
    порядком не короче двух цифр: `1e+16`, `1.5e-07`. Ещё: `-0`, `inf`,
    `-inf`, `nan`.

### 6. Инструкции

**[stmt.expr]** Инструкция-выражение — вызов или `try` вызова (E0411).
Результат вызова, кроме `E!T`, можно не использовать.

**[stmt.assign]** Присвоить и изменить можно место:
- переменную `var`;
- параметр `&mut`;
- переменную `for … in &mut`;
- поле или элемент `List` такого места.

`let`, параметры-значения, параметры `&`, срезы и строки только читаются
(E0412). Методы, меняющие `List`, требуют того же. Составное
присваивание `x op= e` значит `x = x op e` с типом `x`.

**[stmt.init]** `var x: T` без значения получает его позже. Чтение до
присваивания на каком-либо пути — ошибка E0503. После `if` значение есть,
если оно есть в обеих ветвях. После цикла — если было до цикла.

**[stmt.if]** Условие `if` и `while` — `bool`. `if let v = e` — ветвь,
если у `e: ?T` есть значение; `v: T` видно только в ней.

**[stmt.loop]** `while`, `break`, `continue`. `break` и `continue` —
только внутри цикла (E0420).

**[stmt.for]** Формы `for`:
- `for i in a..b` — целые от `a` до `b - 1`; тип — общий тип `a` и `b`.
- `for x in &xs` — элементы `List`, среза или байты `str` (`u8`),
  только чтение.
- `for x in &mut xs` — элементы `List`, их можно менять.

Переменная цикла — элемент `xs[i]` по индексу: длина проверяется на
каждом шаге, поэтому изменение `xs` в теле не оставляет висячей ссылки
(раздел 8). Без пометки коллекцию не обходят (E0419). `parallel for i in
a..b` проверяется как `for`. В v0.1 итерации выполняются по очереди —
это допустимый порядок; потоки — в v0.3 (О13).

**[stmt.match]** `match e { образец => инструкция … }` — ветви
проверяются по порядку, выполняется первая подходящая.
- Ветви покрывают все значения (E0415): все варианты перечисления;
  `some` и `none`; `ok` и `err`; `true` и `false`. Для прочих типов
  нужна ветвь `_` или имя.
- Ветвь, которую закрыли прежние, — ошибка E0416.

**[pattern.types]** Образцы и их тип (несовпадение — E0417):

| образец | подходит к |
|---|---|
| `_` | любому значению |
| имя | любому значению; связывает копию |
| литерал целого (со знаком), `'a'`, строка, `true`/`false` | равному значению; литералов с точкой нет |
| `none`, `some(p)` | `?T` |
| `ok(p)`, `err(p)` | `E!T`; `err` связывает вариант `E` |
| `.V`, `E.V`, `.V(p, q)`, `.V { f, g: p }` | варианту перечисления |

`.V` без данных подходит к варианту с любыми данными. Поля образца с
полями можно перечислить не все.

**[pattern.or]** `p | q` — любой из образцов; имена в нём не связываются
(E0321).

**[stmt.return]**
- `return e` — результат функции.
- Функция без результата пишет `return` без значения (E0509).
- Функция с результатом не может дойти до конца тела без `return` или
  `fail` (E0504). Для `!void` и `E!void` конец тела — успешный возврат.

**[stmt.defer]** `defer инструкция` или `defer { … }` выполнится при
выходе из блока. Порядок — обратный порядку `defer`. Выход — конец
блока, `return`, `break`, `continue`, `fail` и ошибка `try`. Тело
вычисляется целиком при выходе, со значениями переменных на этот
момент. Из тела `defer` нельзя выйти: `return`, `break`, `continue`,
`fail`, `try` — ошибка E0508. При ловушке тела `defer` не выполняются
(раздел 10).

**[decl.const]** Константа — число, `bool`, `str` или `List` из них. Её
значение вычисляется при компиляции (Р42) из литералов, других констант,
операторов и преобразований `T(x)`, `T.wrap(x)`. Иначе — E0421. Цикл
зависимостей констант и переполнение в константе — тоже ошибки.

### 7. Ошибки

**[error.sig]** Ошибка — значение: вариант перечисления ошибок (Р10).
Функция, которая может не удаться, возвращает `E!T`.
- Публичная функция пишет `E` явно (Р41, E0308).
- Тип в `E!T` — перечисление (E0316).

**[error.infer]** Непубличная функция может писать `!T`: тип ошибки
выводится из её `fail` и `try` (Р41).
- `fail .V` даёт перечисления с вариантом `V`; `fail E.V` — `E`.
- `try f()` даёт тип ошибки `f`.
- Тип — единственное общее перечисление всех источников.
- Нет источников, их типы расходятся, или источник по записи не
  определить (например, `fail e`) — ошибка E0507: пишите `E!T`.

**[error.flow]**
- `fail e` возвращает ошибку `e`.
- `try f()` — значение или немедленный возврат той же ошибки.

Оба допустимы только в функции с результатом `E!T`, и тип ошибки должен
совпадать (E0505). Значение `T` и `none` при возврате оборачиваются сами:
`return v` в функции `E!T`.

**[error.handle]** Результат `E!T` нельзя молча потерять (E0506):
передайте его `try`, разберите `match` с `ok(v)` и `err(e)` или
отбросьте явно: `_ = f()`. `e == .V` проверяет вариант ошибки.

### 8. Ссылки и память

**[ref.marks]** Ссылки `&T` и `&mut T` бывают только у параметров
функций и у переменной `for … in &xs` (Р44). Пометка `&x`, `&mut x`
стоит только у такого аргумента и после `in` (E0501). Аргумент-ссылка —
переменная, поле или элемент. Ссылку нельзя хранить и вернуть: значение
по ссылке копируется при чтении. Поэтому висячая ссылка в языке
невозможна.

**[ref.slices]** Срез `[]T` — представление элементов чужого `List`,
поэтому он, как и ссылка, только тип параметра-значения (Р44). Срез не
может быть полем, данными варианта, элементом списка, результатом,
переменной, константой и не стоит за `&` (E0510). Срез получают на месте
передачи: `f(xs)`, `f(xs[1..])`. Срез `str` — строка `str`, обычное
значение-копия.

**[ref.alias]** В одном вызове `&mut x` не передаётся вместе с другой
ссылкой в ту же переменную `x`: в её поле или элемент, или срезом `x`
(E0502).
Вызываемая функция могла бы изменить `x` — например, вырастить список —
и оставить вторую ссылку висячей. Это малая часть исключительного
доступа (О4). Полностью он придёт в v0.3.

**[memory.values]** Все значения, включая `List[T]` и `str`, — значения
(Р45):
- присваивание, передача по значению и запись в поле копируют
  содержимое;
- общих изменяемых данных нет;
- память `List` и `str` освобождается сама, когда значение выходит из
  области или перезаписывается;
- деструкторов у пользовательских типов нет.

Явные аллокаторы и арены — v0.3.

### 9. Встроенное

**[builtin.functions]**

| функция | что делает |
|---|---|
| `len(x)` | длина `List`, среза или `str` (в байтах) — `int` |
| `repeat(v, n)` | `List` из `n` копий `v` |
| `min(a, b)`, `max(a, b)` | меньшее и большее из чисел: `min` — `a`, если `a < b`, иначе `b`; `max` — `b`, если `a < b`, иначе `a` |
| `abs(a)` | модуль знакового числа; `abs(-0.0)` — `0`; `abs` минимального целого — ловушка |
| `parse_int(s)` | `?i64` из десятичной записи: необязательный знак `+` или `-`, затем цифры, без пробелов; иначе и вне `i64` — `none` |
| `is_digit(b)`, `is_alpha(b)`, `is_space(b)`, `is_alnum(b)` | классы байта ASCII `u8` |
| `assert(c)` | ловушка, если `c` ложно |
| `print(s)`, `println(s)` | вывод строки в stdout (`println` — с переводом строки) |
| `eprintln(s)` | вывод строки с переводом строки в stderr |

**[builtin.methods]** Методы (другие — E0410):

| метод | что делает |
|---|---|
| `xs.push(v)`, `xs.insert(i, v)` | добавить в конец и в позицию `i` |
| `xs.pop()` | `?T` — снять последний |
| `xs.remove(i)` | `T` — убрать элемент `i` |
| `xs.clear()` | очистить |
| `xs.sort()` | устойчиво по возрастанию; элементы должны быть упорядочены |
| `xs.contains(v)` | `bool`; метод есть и у среза |
| `s.trim()` | строка без пробелов ASCII по краям |
| `s.find(t)` | `?int` — позиция первого вхождения |
| `s.starts_with(t)` | `bool` |
| `s.split(sep)` | `List[str]` частей между разделителями, включая пустые: `"a,,b".split(",")` — `["a", "", "b"]` |

Методы `List`, кроме `contains`, меняют список и требуют изменяемого
места (раздел 6).

### 10. Ловушки во время выполнения

**[trap.def]** Ловушка — детерминированная остановка программы при
нарушенной проверке (Р36). Программа печатает в stderr строку
`файл:строка:столбец: trap: сообщение` с местом операции в исходнике и
завершается с кодом 101. Напечатанное до ловушки сохраняется.
Продолжить после ловушки нельзя: тела `defer` не выполняются. На одних и
тех же входах программа останавливается в одном и том же месте.

**[trap.int]** Целые:
- `+`, `-`, `*` и унарный `-` — ловушка, если результат вне типа;
- `/` отбрасывает дробную часть к нулю, знак `%` — знак делимого:
  `-7 / 2` — `-3`, `-7 % 2` — `-1`. Делитель 0 — ловушка. `MIN / -1` —
  ловушка, `MIN % -1` — `0`;
- `+%`, `-%`, `*%` — по модулю 2^N; `&`, `|`, `^`, `~` — ловушек нет;
- `x << n` и `x >> n` — ловушка, если `n` отрицательно или не меньше
  ширины типа `x`. `<<` отбрасывает вышедшие биты: `u8 200 << 1` —
  `144`, `i8 1 << 7` — `-128`. `>>` у знакового типа заполняет знаком
  (`i8 -128 >> 1` — `-64`), у беззнакового — нулями.

Составное присваивание `x op= e` проверяется как `x op e`.

**[trap.float]** Плавающие — IEEE 754 с округлением к ближайшему,
ловушек нет:
- деление на ноль даёт `inf`, `-inf` или `nan`;
- операция над `f32` округляется до `f32` на каждом шаге, в том числе
  при вычислении констант;
- сравнение с `nan` ложно, кроме `!=`; `-0.0 == 0.0`.

**[trap.convert]** Преобразования `T(x)` (expr.convert):
- целое в целое — ловушка, если значение вне `T`;
- плавающее в целое — с отбрасыванием дробной части к нулю; `nan`,
  бесконечность и значение вне `T` — ловушка;
- целое в плавающее и `f64` в `f32` — округление к ближайшему. Конечное
  `f64` больше наибольшего конечного `f32` по модулю — ловушка; `inf` и
  `nan` сохраняются.

`T.wrap(x)` и неявные преобразования (type.conv) ловушек не дают.

**[trap.index]** Индексы и срезы:
- `xs[i]` и `s[i]` — ловушка, если не `0 <= i < len`;
- срез `x[a..b]` — ловушка, если не `0 <= a <= b <= len`; пропущенная
  граница — `0` и `len`;
- срез `str` — ловушка, если `a` или `b` попадает внутрь символа UTF-8:
  строка остаётся UTF-8;
- `xs.remove(i)` — ловушка, если не `0 <= i < len`; `xs.insert(i, v)` —
  если не `0 <= i <= len`.

**[trap.builtin]** Встроенное: ложный `assert(c)` — ловушка `assertion
failed`; `repeat(v, n)` с отрицательным `n` и `s.split("")` — ловушка.

**[trap.memory]** Нехватка памяти для `List` и `str` и слишком глубокая
вложенность вызовов — ловушка. Пределы зависят от реализации;
у эталонного интерпретатора — `docs/ir/README.md`, раздел 5.

**[trap.exit]** Код выхода программы (module.main):
- `0` — `main` вернулась;
- `1` — `main` вернула ошибку. В stderr — `error: main failed with E.V`,
  где `E.V` — вариант ошибки. Тела `defer` выполняются, как при любом
  возврате;
- `101` — ловушка.
