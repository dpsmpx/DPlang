## Правила

- Задачи решаются по порядку, следующая — после того, как кончилась предыдущая. У каждой задачи своя папка (в её разделе): читай этот файл и `src/` папки задачи, правь файлы в её `src/`. Других файлов не открывай, по диску и в сети не ищи.

- Попыток проверки на задачу — не больше 5, каждая записывается. Проверяй, когда решение готово целиком, а не для разведки.
- Задача кончается на «принято» или когда попытки кончились. Ответ в конце — по строке на задачу: задача, номер последней попытки и её итог.

### t15. Книга счетов с вложенными транзакциями

Интерпретатор команд книги счетов. Каждая команда — одна строка текста;
ответ — одна строка. Суммы — целые (копейки), тип `i64`.

#### Разбор строки

- Слова разделены одним или несколькими пробелами; пробелы в начале и в
  конце строки не значат ничего. Других разделителей нет: табуляция —
  часть слова.
- Первое слово — команда (таблица ниже), дальше — аргументы. Неизвестная
  команда, пустая строка, не то число аргументов — `error syntax`.
- Имя счёта: от 1 до 16 байт, первый — `a`–`z`, остальные — `a`–`z`,
  `0`–`9` или `_`. Иное — `error syntax`.
- Число: от 1 до 18 десятичных цифр, без знака. Иное — `error syntax`.
  Ведущие нули допустимы: `007` — 7.

#### Команды

| команда | что делает | ответ при успехе |
|---|---|---|
| `open NAME LIMIT` | открывает счёт с балансом 0 и кредитным лимитом `LIMIT` | `ok` |
| `deposit NAME AMOUNT` | баланс += `AMOUNT` | `ok BAL` |
| `withdraw NAME AMOUNT` | баланс −= `AMOUNT` | `ok BAL` |
| `transfer FROM TO AMOUNT` | `FROM` −= `AMOUNT + FEE`, `TO` += `AMOUNT` | `ok BAL_FROM BAL_TO` |
| `balance NAME` | — | `BAL` |
| `close NAME` | закрывает счёт | `ok` |
| `begin` | начинает транзакцию (вложенную, если уже идёт другая) | `ok depth N` |
| `commit` | завершает текущую транзакцию, её изменения остаются | `ok depth N` |
| `rollback` | отменяет все изменения текущей транзакции | `ok depth N` |
| `report` | — | открытые счета |

- `BAL` — баланс после команды в десятичной записи (у отрицательного —
  `-`). `N` — глубина вложенности после команды (вне транзакций — 0).
- Комиссия перевода `FEE = AMOUNT / 100` (с отбрасыванием дробной
  части), но не меньше 1. Комиссия никуда не зачисляется.
- `report` — открытые счета по возрастанию имени (байтами), через
  пробел, каждый — `NAME:BAL`; нет открытых счетов — `(empty)`.
- Баланс счёта не может стать меньше `-LIMIT` его счёта.
- Модуль баланса не может стать больше `10^15` (1000000000000000).
- `rollback` возвращает книгу ровно в состояние на момент парного
  `begin`: открытые и закрытые в транзакции счета, балансы — всё.
  `commit` вложенной транзакции передаёт её изменения внешней: их ещё
  может отменить `rollback` внешней.
- Глубина вложенности — не больше 8.

#### Ошибки

Команда с ошибкой книгу не меняет. Проверки — строго в этом порядке,
ответ — первая нарушенная:

1. разбор строки — `error syntax`;
2. сумма `AMOUNT` равна 0 — `error amount` (`LIMIT` может быть 0);
3. счёт не открыт — `error unknown NAME` (у `transfer` — сначала `FROM`,
   потом `TO`); у `open` счёт уже открыт — `error exists NAME`;
4. `transfer` со счёта на него же — `error same`;
5. баланс стал бы меньше `-LIMIT` — `error funds`;
6. модуль баланса стал бы больше `10^15` — `error bound` (у `transfer` —
   сначала `FROM`, потом `TO`);
7. `close` счёта с ненулевым балансом — `error nonzero`;
8. `begin` при глубине 8 — `error depth`; `commit` и `rollback` вне
   транзакции — `error depth`.

#### Интерфейс

- `ledger_new() -> Ledger`
- `ledger_exec(l: &mut Ledger, line: str) -> str` — выполняет одну
  строку и возвращает ответ.

### t16. Калькулятор целых выражений с переменными

`calc(src)` вычисляет программу из одной строки и возвращает строку:
значение последней инструкции в десятичной записи или ошибку
`error at COL: MESSAGE`. `COL` — номер байта строки, с 1. Значения —
`i64`. Каждый вызов независим: переменные одного вызова другому не
видны.

#### Лексика

- Пробел (` `) разделяет лексемы и сам ничего не значит.
- Число — одна или больше цифр `0`–`9`. Знака у числа нет: `-5` — это
  унарный минус и число. Число больше 9223372036854775807 — ошибка
  `number too large` у его первой цифры.
- Имя — `a`–`z` или `_`, затем `a`–`z`, `0`–`9`, `_`.
- Операторы: `+ - * / % ^ ( ) = ;`.
- Любой другой байт — ошибка `unexpected character 'C'`, где `C` — сам
  байт. Во входе только печатные символы ASCII и пробелы.
- Лексема — самая длинная возможная: `2x` — число `2` и имя `x`.

#### Грамматика

```
program = stmt { ";" stmt }
stmt    = NAME "=" expr | expr
expr    = term { ("+" | "-") term }
term    = unary { ("*" | "/" | "%") unary }
unary   = "-" unary | power
power   = atom [ "^" unary ]
atom    = NUMBER | NAME | "(" expr ")"
```

`stmt` — присваивание, если это имя и за ним сразу `=`. Бинарные `+ -
* / %` — левые; `^` — правый и сильнее унарного минуса: `-2^2` — `-4`,
`2^3^2` — `512`, `2^-1` — показатель `-1`.

#### Порядок работы

1. **Разбор** всей строки — по лексемам слева направо до первой ошибки.
   Ошибка — у первой лексемы, которую нельзя прочитать (ошибки лексики
   выше) или которая не может стоять на своём месте по грамматике; на
   одном месте ошибка лексики важнее. Ошибки грамматики:
   - `unexpected 'T'` — лексема `T` (текст лексемы) не может стоять
     здесь;
   - `expected ')'` — после выражения в скобках нет `)`: у лексемы на
     её месте, а в конце строки — у столбца `длина строки + 1`;
   - `unexpected end` — строка кончилась, а выражение — нет; столбец —
     `длина строки + 1` (пробелы в конце строки входят в длину).
2. Только если разбор прошёл, **вычисление**: инструкции по порядку, у
   бинарного оператора сначала левый операнд, потом правый. Первая
   ошибка вычисления — результат:
   - `unknown variable 'x'` — чтение имени, которому ещё ничего не
     присвоено; столбец — у имени;
   - `division by zero` — делитель `/` или `%` равен 0; столбец — у
     оператора;
   - `overflow` — точный результат `+ - * / ^` или унарного минуса вне
     `i64`; столбец — у оператора;
   - `negative exponent` — показатель `^` меньше 0; столбец — у `^`.

Значение присваивания — присвоенное значение. `/` отбрасывает дробную
часть к нулю, знак `%` — знак делимого. `a % b` с `b = -1` — `0`.
`0^0` — `1`. `^` вычисляется быстро при любом показателе
(`1^1000000000000` — `1`), а `overflow` — только если вне `i64` точный
результат: `(-2)^63` — `-9223372036854775808`.

#### Интерфейс

- `calc(src: str) -> str`

Драйвер — `expected.txt`.

### t17. Перенос и выравнивание текста

`wrap(text, width, align)` разбивает текст на строки не длиннее `width`
байт и выравнивает их. Текст — байты ASCII, строки текста разделены
`\n`.

#### Абзацы и слова

- Пустая строка текста — пустая или только из пробелов. Абзац —
  наибольшая группа подряд идущих непустых строк.
- Слово — наибольшая цепочка байт без пробела (` `) и без `\n`. Другие
  байты, в том числе табуляция, — части слов.
- Результат — строки всех абзацев по порядку; между соседними абзацами —
  ровно одна пустая строка `""`. Пустых строк в начале и в конце нет;
  в тексте без слов результат пуст.

#### Заполнение

Строки абзаца заполняются жадно: слова идут по порядку, в строке они
разделены одним пробелом. Слово дописывается в текущую строку, если
строка после этого не длиннее `width`; иначе текущая строка кончается,
и слово начинает следующую.

Слово длиннее `width`:
1. текущая непустая строка кончается;
2. пока остаток слова длиннее `width`, от него отрезается кусок в
   `width - 1` байт; кусок с дефисом `-` в конце — отдельная строка;
3. остаток (не длиннее `width`) начинает новую строку, как обычное
   слово: за ним могут идти следующие слова.

#### Выравнивание

`align` — одно из `Left`, `Right`, `Center`, `Justify`:
- `Left` — строка как есть;
- `Right` — пробелы слева, длина строки — ровно `width`;
- `Center` — слева `(width - длина) / 2` пробелов (с отбрасыванием
  дробной части), справа ничего;
- `Justify` — строка растягивается до ровно `width`: лишние пробелы
  делятся между промежутками между словами поровну, а остаток деления —
  по одному в первые промежутки слева. Не растягиваются, а остаются как
  при `Left`: последняя строка абзаца и строка из одного слова (кусок
  длинного слова с дефисом — тоже одно слово).

Ни одна строка не кончается пробелом.

#### Ошибки

`width` вне `2..200` (включительно) — ошибка `BadWidth`.

#### Интерфейс

- перечисление `Align`: `Left | Right | Center | Justify`
- `wrap(text: str, width: i32, align: Align) -> ошибка BadWidth | список строк`

### t18. Исправление ошибок: планировщик событий

Дана реализация с ошибками (начальный код задачи): планировщик событий
на двоичной куче. Ошибок несколько, и они в разных функциях. Нужно найти
и исправить их, не переписывая решение заново: мера задачи — точность
правки. Устройство (куча, отмена пометкой, счётчик ожидающих) менять не
нужно.

#### Что должно получаться

Планировщик хранит текущее время `now` (сначала 0) и события. Событие —
номер `id`, время `at`, приоритет, период `every` и имя.

- `sched_new() -> Scheduler` — пустой планировщик.
- `sched_add(s, at: i64, priority: i32, every: i64, name: str) ->
  ошибка BadTime | i32` — добавляет событие и возвращает его номер:
  1, 2, 3, … по порядку успешных добавлений. `at < now` или
  `every < 0` — ошибка `BadTime`, планировщик не меняется. `at == now`
  допустимо. `every == 0` — событие разовое, иначе — периодическое.
- `sched_cancel(s, id: i32) -> ошибка NotFound | ok` — отменяет
  ожидающее событие (у периодического — все его будущие срабатывания).
  Нет события с таким номером, оно уже отменено или (разовое) уже
  сработало — `NotFound`.
- `sched_run(s, until: i64) -> список строк` — срабатывают по очереди все
  ожидающие события с `at <= until`. Очередь: по возрастанию `at`, при
  равном `at` — по убыванию приоритета, при равных — по возрастанию
  `id`. Срабатывание даёт строку `"AT NAME"`. Периодическое событие
  после срабатывания снова ждёт, со временем `at + every` и тем же
  `id` и приоритетом; если это время тоже `<= until`, оно сработает в
  этом же вызове — в своё место очереди. После вызова `now = until`
  (если `until < now`, ничего не срабатывает и `now` не меняется).
- `sched_pending(s) -> i32` — сколько событий ждёт (отменённые не
  считаются).

### Целевой интерфейс

## dpl: краткое руководство

Как писать на dpl: приёмы с примерами. Нормативный текст —
`docs/spec/core.md` (ядро v0.1). Если руководство и спецификация
расходятся, права спецификация; руководство тогда исправляется.

### Файл, модуль, программа

```dpl
// Файл world.dpm — модуль world. Комментарий — от // до конца строки.
import os                        // модуль рядом с главным или из стандартной библиотеки

pub struct Unit {                // pub — видно другим модулям
    hp: i32
    alive: bool = true           // поле со значением по умолчанию
}

const LIMIT: i32 = 100

pub fn spawn(units: &mut List[Unit], hp: i32) int {
    units.push(Unit { hp })      // alive — по умолчанию; `hp` — то же, что `hp: hp`
    return len(units) - 1
}

fn main() {                      // вход программы — main главного модуля
    var units: List[Unit] = []
    let i = spawn(&mut units, 5)
    println("unit " + str(i))
}
```

- Инструкция занимает строку. `;` нет. Порядок объявлений не важен.
- Из другого модуля имена берутся через модуль: `world.spawn(...)`,
  `world.Unit { hp: 1 }`, `world.Kind.Wall`. Видно только `pub`.
- `main` без параметров, без результата или с `E!void`. Ошибка из `main` —
  код выхода 1.

### Переменные и типы

```dpl
let a = 5                // неизменяемая; тип int (= i64)
var b: i32 = 0           // изменяемая
var c: str               // без значения — присвоить до чтения
b += 1
```

- Типы: `i8`…`i64`, `u8`…`u64`, `int` (= `i64`), `f32`, `f64`, `bool`,
  `str` (байты UTF-8), `List[T]`, `Map[K, V]`, `?T`, `E!T`, свои `struct`
  и `enum`.
- Литерал берёт тип из контекста: в `b + 1` единица — `i32`.
- **Неявно только без потерь:** `i32 → i64`, `u8 → i32`, `f32 → f64`.
  Остальное — явно: `i32(x)`, `u8(n)`, `f64(n)`, `int(x)`.
  `len(xs)` — `int`, поэтому `let n: i32 = i32(len(xs))`.
- **Затенения нет:** имя не повторяет другое локальное имя, видимое в
  функции (E0310). Возьмите другое имя.
- Значения копируются: присваивание и передача `List`, `Map` и `str` копируют
  содержимое. Общих изменяемых данных нет.

### Целые и переполнение

- `+ - *`, унарный минус и `T(x)` вне диапазона — **ловушка**: программа
  останавливается с кодом 101 и местом в исходнике.
- `/` отбрасывает дробную часть к нулю, знак `%` — знак делимого.
  Деление на 0 — ловушка.
- Арифметика по модулю 2^N — `+%`, `-%`, `*%` и `T.wrap(x)`
  (`u32.wrap(-1)` — 4294967295). Сдвиги `<<`, `>>`, биты `& | ^ ~`.
- Проверка без ловушки — `checked_add`, `checked_sub`, `checked_mul`,
  `checked_div`, `checked_neg`: результат `?T`, `none` — если вне типа
  (у `checked_div` — и при делителе 0).

```dpl
fn total(xs: []i64) ?i64 {
    var sum: i64 = 0
    for x in &xs {
        if let s = checked_add(sum, x) {
            sum = s
        } else {
            return none                  // переполнение — данные, не ловушка
        }
    }
    return sum
}

let q = checked_div(a, b) ?? 0           // делитель 0 — none
let m: i32 = 2147483647
let bad = checked_mul(m, 2) == none      // true: вне i32
```

### Строки и байты

```dpl
let s = "a,b,,c"
let first: u8 = s[0]             // байт; литерал байта — 'a', '\n'
let part = s[2..3]               // срез — новая строка; s[..2], s[2..]
let parts = s.split(",")         // ["a", "b", "", "c"]
let t = "  x ".trim()            // "x"
if let at = s.find(",") {        // ?int — позиция первого вхождения
    println(s[..at])
}
var out = ""
out += "n=" + str(42)            // str(x) — запись числа, bool, строки
for c in &s {                    // байты строки
    if is_digit(c) { ... }       // is_alpha, is_space, is_alnum
}
let n = parse_int("-17") ?? 0    // ?i64: знак и цифры, иначе none
```

- Сравнение строк — `==`, `<` (по байтам). Строка неизменяема:
  новая строка — склейкой `+` или срезом.
- Байт в строку: `s[i..i + 1]`. Число байта — `str(c)`.

### Списки

```dpl
var xs: List[i32] = []
xs.push(3)
xs.insert(0, 1)                  // в позицию
let last = xs.pop()              // ?i32
let y = xs.remove(0)             // i32; индекс вне — ловушка
xs.sort()                        // устойчиво; структуры — по полям по порядку
let zeros = repeat(0, 8)         // List из 8 копий
let has = xs.contains(3)
for i in 0..len(xs) { xs[i] += 1 }
for x in &xs { println(str(x)) } // только чтение
for x in &mut xs { x *= 2 }      // изменение элементов
```

- Индекс вне диапазона — ловушка. Срез `xs[a..b]` — представление
  `[]T` только для передачи в функцию с параметром `[]T`.
- Вложенные списки: `var grid: List[List[i32]] = repeat(repeat(0, w), h)`,
  `grid[y][x] = 1`.

### Отображения `Map[K, V]`

```dpl
var bal: Map[str, i64] = []      // только пустой литерал
bal["bob"] = 5                   // вставка или замена
bal["bob"] += 2                  // ключ должен быть: иначе ловушка
let x = bal["ann"]               // нет ключа — ловушка
let y = bal.get("ann") ?? 0      // ?V, без ловушки
if !bal.contains("ann") { bal["ann"] = 0 }
let old = bal.remove("bob")      // ?V; порядок остальных сохраняется
for k in &bal { println(k + " " + str(bal[k])) }   // ключи по возрастанию
for k in &bal.keys() { bal[k] = 0 }                 // менять — в обходе копии ключей
```

- Ключ — целое, `bool` или `str`. Обход и `keys()` — всегда по
  возрастанию ключа: сортировать вывод не нужно.
- В теле `for k in &m` менять `m` нельзя (E0412).
- `len(m)` — число ключей; `m.clear()` — очистить. Сравнивать
  отображения нельзя.

### Функции и ссылки

```dpl
fn total(xs: []i32) int { ... }          // срез: принимает List
fn bump(c: &mut Counter, by: i32) { c.n += by }
fn show(c: &Counter) str { return str(c.n) }

var c = Counter { n: 0 }
bump(&mut c, 2)                  // пометка у аргумента — как у параметра
println(show(&c))
println(str(total(xs)))
```

- `&T` — чтение без копии, `&mut T` — изменение. Ссылки бывают только у
  параметров; вернуть или сохранить ссылку нельзя.
- В одном вызове нельзя передать `&mut x` вместе с другой ссылкой на
  `x` (E0502).
- Внутри функции параметр `&mut` пишется как обычная переменная:
  `c.n += 1`, `xs.push(v)`; дальше передаётся снова с `&mut`.

### Обход и изменение

```dpl
for x in &mut xs { x += 1 }                   // менять — через переменную цикла
for i in 0..len(xs) { xs.push(xs[i]) }        // менять сам xs — обходом индексов
let first = xs[0]
for x in &mut xs { x += first }               // читать xs — до цикла
let old = xs
println(str(sum(old, grow(&mut xs))))         // вид и изменение xs в одном вызове — через копию
```

- Пока идёт `for x in &xs` или `for x in &mut xs`, сам `xs` менять нельзя,
  а в `&mut`-обходе — и читать: только через `x` (E0412). Другое поле той
  же структуры можно: `for b in &mut w.bodies { w.hits += 1 }`.
- Срез `xs[a..b]`, список `xs` как срез или `&xs[i]` в аргументе и
  изменение `xs` правее в том же выражении — ошибка (E0502): сначала
  копия `let old = xs`.
- В `parallel for i in 0..n` снаружи пишется только `out[i]` по
  переменной цикла (E0412); итоги складываются после цикла.

### Структуры и перечисления

```dpl
pub struct Point {
    x: i32
    y: i32
}

pub enum Shape {
    Empty
    Circle(Point, i32)               // позиционные данные
    Rect { min: Point, max: Point }  // поля
}

let p = Point { x: 1, y: 2 }
let s: Shape = .Circle(p, 5)         // .V — когда тип известен из контекста
let r = Shape.Rect { min: p, max: Point { x: 3, y: 4 } }
var q = p
q.x = 10                             // q — копия
```

- Свой тип не содержит себя напрямую (E0423). Дерево — в `List`:
  `children: List[Node]` или узлы в одном списке с индексами.
- `==`, `<` работают для структур, перечислений и списков по частям.

### `match`

```dpl
match s {
    .Empty => println("empty")
    .Circle(c, r) => println(str(r))
    .Rect { min, max } => {
        println(str(max.x - min.x))
    }
}
match code {
    0 => println("zero")
    1 | 2 => println("small")
    _ => println("other")
}
```

- Ветви покрывают все значения (E0415): все варианты, `some` и `none`,
  `ok` и `err`; для чисел и строк нужна ветвь `_`.
- Полнота не смотрит во вложенные образцы. Вместо
  `ok(.Pair { … })` пишите `ok(v) => match v { … }`.

### «Может не быть»: `?T`

```dpl
fn find(xs: []i32, v: i32) ?int {
    for i in 0..len(xs) {
        if xs[i] == v {
            return i                 // T оборачивается в ?T сам
        }
    }
    return none
}

if let i = find(xs, 3) { println(str(i)) } else { println("нет") }
let j = find(xs, 4) ?? -1
match find(xs, 5) {
    some(i) => println(str(i))
    none => println("нет")
}
```

`opt == none` и `opt != none` — проверка без распаковки.

### Ошибки: `E!T`

```dpl
pub enum ParseError {
    Empty
    BadDigit
}

pub fn digit(s: str) ParseError!i32 {    // pub — тип ошибки пишется явно
    if len(s) == 0 {
        fail .Empty
    }
    if !is_digit(s[0]) {
        fail .BadDigit
    }
    return i32(s[0] - '0')
}

fn twice(s: str) ParseError!i32 {
    let d = try digit(s)                 // ошибка — сразу наверх
    return d * 2
}

match digit("7") {
    ok(d) => println(str(d))
    err(e) => {
        if e == .Empty { println("пусто") } else { println("не цифра") }
    }
}
_ = digit("x")                           // отбросить результат — только явно
```

- `E!void` — успех без значения: функция просто доходит до конца или
  делает `return`.
- Непубличная функция может писать `!T`: тип ошибки выводится из `fail`
  и `try` в теле.
- Результат `E!T` нельзя потерять молча (E0506): `try`, `match` или
  `_ =`. Сравнивать результат `E!T` целиком нельзя — только вариант
  ошибки `e == .V` внутри `err(e)`.

### Циклы и прочее

```dpl
while i < n { i += 1 }
for i in 0..n { if i == 3 { continue } }
for i in i32(0)..n32 { ... }             // тип переменной — общий тип границ
defer println("выход")                   // при выходе из блока, в обратном порядке
assert(n >= 0)                           // ложь — ловушка
let m = min(a, b) + max(a, b) + abs(d)
```

- Функция с результатом не должна дойти до конца без `return` или
  `fail` (E0504).
- `print`, `println` — в stdout; `eprintln` — в stderr.
- Плавающие: `str(0.1)` — `0.1`, `str(1e16)` — `1e+16` (кратчайшая
  запись, Р48).

### Чего в dpl нет и чем заменить

| нет | вместо этого |
|---|---|
| методов у своих типов, `impl` | функции: `fn area(s: &Shape) int` |
| обобщённых функций и своих обобщённых типов | отдельная функция на тип |
| замыканий и лямбд | именованная функция |
| кортежей | структура: `struct Pair { a: int, b: int }` |
| `if` и `match` как выражения, `?:` | `var x = …`, затем присваивание в ветвях |
| форматной строки | склейка: `"x=" + str(x)` |
| типа символа | байт `u8`; текст — `str` |
| `++`, `--`, `loop` | `i += 1`, `while true` |
| изменяемых глобальных | `const` или параметр `&mut` |
| исключений и `null` | `E!T` с `try`, `?T` с `none` |

- `&` берётся только у переменной, поля или элемента. Результат вызова
  сначала кладётся в `let`: `let d = f()`, затем `g(&d)`. Исключение —
  обход: `for k in &m.keys()`.

### Частые приёмы

```dpl
fn words(s: str) List[str] {             // split(" ") даёт "" между пробелами подряд
    var out: List[str] = []
    for w in &s.split(" ") {
        if len(w) > 0 { out.push(w) }
    }
    return out
}

fn join(parts: []str, sep: str) str {
    var out = ""
    for i in 0..len(parts) {
        if i > 0 { out += sep }
        out += parts[i]
    }
    return out
}

fn index_of(xs: []str, v: str) ?int {
    for i in 0..len(xs) {
        if xs[i] == v { return i }
    }
    return none
}
```

- Список из значений — литерал: `[x]`, `[a, b]`. `n` пробелов —
  `for i in 0..n { s += " " }`.
- `?T` сравнивается со значением: `peek(&p) == '+'`, `m.get(k) == 3`.
- Счётчик: `counts[w] = (counts.get(w) ?? 0) + 1`.
- Снимок и откат — копией: `let saved = state` … `state = saved`.
  Стек снимков — `List[State]`, откат — `if let s = stack.pop() { state = s }`.
- Разбор строки — структура с позицией и функции с `&mut`; ошибка —
  `E!T` и `try`:

```dpl
struct Parser {
    src: str
    pos: int
}

fn peek(p: &Parser) ?u8 {
    if p.pos < len(p.src) { return p.src[p.pos] }
    return none
}

fn number(p: &mut Parser) ParseError!i64 {
    let start = p.pos
    while p.pos < len(p.src) && is_digit(p.src[p.pos]) { p.pos += 1 }
    if p.pos == start { fail .Expected }
    if let v = parse_int(p.src[start..p.pos]) { return v }
    fail .TooBig                               // больше i64
}

fn sum(p: &mut Parser) ParseError!i64 {
    var total = try number(&mut p)
    while peek(&p) == '+' {
        p.pos += 1
        let n = try number(&mut p)
        if let t = checked_add(total, n) { total = t } else { fail .TooBig }
    }
    return total
}
```

### Частые ошибки компилятора

| код | что значит | как исправить |
|---|---|---|
| E0401 | типы не сходятся (часто `int` и `i32`) | явное преобразование `i32(x)` |
| E0408 | пометка аргумента не та | `&x` для `&T`, `&mut x` для `&mut T`, без пометки — значение |
| E0504 | функция может дойти до конца без `return` | `return` в конце |
| E0506 | потерян результат `E!T` | `try`, `match` или `_ =` |
| E0310 | имя уже есть в функции | другое имя |
| E0412 | изменение неизменяемого | `var` вместо `let`, параметр `&mut` |
| E0415 | `match` не покрывает все случаи | ветвь `_` или недостающий вариант |
| E0308 | у `pub fn` нет типа ошибки | `MyError!T` вместо `!T` |

Объяснение любого кода — `dpl explain E0401`.
