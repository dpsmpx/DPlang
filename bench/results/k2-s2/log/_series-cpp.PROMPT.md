### t15. Книга счетов с вложенными транзакциями

Интерпретатор команд книги счетов. Каждая команда — одна строка текста;
ответ — одна строка. Суммы — целые (копейки), тип `i64`.

#### Разбор строки

- Слова разделены одним или несколькими пробелами; пробелы в начале и в
  конце строки не значат ничего. Других разделителей нет: табуляция —
  часть слова.
- Первое слово — команда (таблица ниже), дальше — аргументы. Неизвестная
  команда, пустая строка, не то число аргументов — `error syntax`.
- Имя счёта: от 1 до 16 байт, первый — `a`–`z`, остальные — `a`–`z`,
  `0`–`9` или `_`. Иное — `error syntax`.
- Число: от 1 до 18 десятичных цифр, без знака. Иное — `error syntax`.
  Ведущие нули допустимы: `007` — 7.

#### Команды

| команда | что делает | ответ при успехе |
|---|---|---|
| `open NAME LIMIT` | открывает счёт с балансом 0 и кредитным лимитом `LIMIT` | `ok` |
| `deposit NAME AMOUNT` | баланс += `AMOUNT` | `ok BAL` |
| `withdraw NAME AMOUNT` | баланс −= `AMOUNT` | `ok BAL` |
| `transfer FROM TO AMOUNT` | `FROM` −= `AMOUNT + FEE`, `TO` += `AMOUNT` | `ok BAL_FROM BAL_TO` |
| `balance NAME` | — | `BAL` |
| `close NAME` | закрывает счёт | `ok` |
| `begin` | начинает транзакцию (вложенную, если уже идёт другая) | `ok depth N` |
| `commit` | завершает текущую транзакцию, её изменения остаются | `ok depth N` |
| `rollback` | отменяет все изменения текущей транзакции | `ok depth N` |
| `report` | — | открытые счета |

- `BAL` — баланс после команды в десятичной записи (у отрицательного —
  `-`). `N` — глубина вложенности после команды (вне транзакций — 0).
- Комиссия перевода `FEE = AMOUNT / 100` (с отбрасыванием дробной
  части), но не меньше 1. Комиссия никуда не зачисляется.
- `report` — открытые счета по возрастанию имени (байтами), через
  пробел, каждый — `NAME:BAL`; нет открытых счетов — `(empty)`.
- Баланс счёта не может стать меньше `-LIMIT` его счёта.
- Модуль баланса не может стать больше `10^15` (1000000000000000).
- `rollback` возвращает книгу ровно в состояние на момент парного
  `begin`: открытые и закрытые в транзакции счета, балансы — всё.
  `commit` вложенной транзакции передаёт её изменения внешней: их ещё
  может отменить `rollback` внешней.
- Глубина вложенности — не больше 8.

#### Ошибки

Команда с ошибкой книгу не меняет. Проверки — строго в этом порядке,
ответ — первая нарушенная:

1. разбор строки — `error syntax`;
2. сумма `AMOUNT` равна 0 — `error amount` (`LIMIT` может быть 0);
3. счёт не открыт — `error unknown NAME` (у `transfer` — сначала `FROM`,
   потом `TO`); у `open` счёт уже открыт — `error exists NAME`;
4. `transfer` со счёта на него же — `error same`;
5. баланс стал бы меньше `-LIMIT` — `error funds`;
6. модуль баланса стал бы больше `10^15` — `error bound` (у `transfer` —
   сначала `FROM`, потом `TO`);
7. `close` счёта с ненулевым балансом — `error nonzero`;
8. `begin` при глубине 8 — `error depth`; `commit` и `rollback` вне
   транзакции — `error depth`.

- `ledger_new() -> Ledger`
- `ledger_exec(l: &mut Ledger, line: str) -> str` — выполняет одну
  строку и возвращает ответ.

### t16. Калькулятор целых выражений с переменными

`calc(src)` вычисляет программу из одной строки и возвращает строку:
значение последней инструкции в десятичной записи или ошибку
`error at COL: MESSAGE`. `COL` — номер байта строки, с 1. Значения —
`i64`. Каждый вызов независим: переменные одного вызова другому не
видны.

#### Лексика

- Пробел (` `) разделяет лексемы и сам ничего не значит.
- Число — одна или больше цифр `0`–`9`. Знака у числа нет: `-5` — это
  унарный минус и число. Число больше 9223372036854775807 — ошибка
  `number too large` у его первой цифры.
- Имя — `a`–`z` или `_`, затем `a`–`z`, `0`–`9`, `_`.
- Операторы: `+ - * / % ^ ( ) = ;`.
- Любой другой байт — ошибка `unexpected character 'C'`, где `C` — сам
  байт. Во входе только печатные символы ASCII и пробелы.
- Лексема — самая длинная возможная: `2x` — число `2` и имя `x`.

#### Грамматика

```
program = stmt { ";" stmt }
stmt    = NAME "=" expr | expr
expr    = term { ("+" | "-") term }
term    = unary { ("*" | "/" | "%") unary }
unary   = "-" unary | power
power   = atom [ "^" unary ]
atom    = NUMBER | NAME | "(" expr ")"
```

`stmt` — присваивание, если это имя и за ним сразу `=`. Бинарные `+ -
* / %` — левые; `^` — правый и сильнее унарного минуса: `-2^2` — `-4`,
`2^3^2` — `512`, `2^-1` — показатель `-1`.

#### Порядок работы

1. **Разбор** всей строки — по лексемам слева направо до первой ошибки.
   Ошибка — у первой лексемы, которую нельзя прочитать (ошибки лексики
   выше) или которая не может стоять на своём месте по грамматике; на
   одном месте ошибка лексики важнее. Ошибки грамматики:
   - `unexpected 'T'` — лексема `T` (текст лексемы) не может стоять
     здесь;
   - `expected ')'` — после выражения в скобках нет `)`: у лексемы на
     её месте, а в конце строки — у столбца `длина строки + 1`;
   - `unexpected end` — строка кончилась, а выражение — нет; столбец —
     `длина строки + 1` (пробелы в конце строки входят в длину).
2. Только если разбор прошёл, **вычисление**: инструкции по порядку, у
   бинарного оператора сначала левый операнд, потом правый. Первая
   ошибка вычисления — результат:
   - `unknown variable 'x'` — чтение имени, которому ещё ничего не
     присвоено; столбец — у имени;
   - `division by zero` — делитель `/` или `%` равен 0; столбец — у
     оператора;
   - `overflow` — точный результат `+ - * / ^` или унарного минуса вне
     `i64`; столбец — у оператора;
   - `negative exponent` — показатель `^` меньше 0; столбец — у `^`.

Значение присваивания — присвоенное значение. `/` отбрасывает дробную
часть к нулю, знак `%` — знак делимого. `a % b` с `b = -1` — `0`.
`0^0` — `1`. `^` вычисляется быстро при любом показателе
(`1^1000000000000` — `1`), а `overflow` — только если вне `i64` точный
результат: `(-2)^63` — `-9223372036854775808`.

#### Интерфейс

- `calc(src: str) -> str`

### t17. Перенос и выравнивание текста

`wrap(text, width, align)` разбивает текст на строки не длиннее `width`
байт и выравнивает их. Текст — байты ASCII, строки текста разделены
`\n`.

#### Абзацы и слова

- Пустая строка текста — пустая или только из пробелов. Абзац —
  наибольшая группа подряд идущих непустых строк.
- Слово — наибольшая цепочка байт без пробела (` `) и без `\n`. Другие
  байты, в том числе табуляция, — части слов.
- Результат — строки всех абзацев по порядку; между соседними абзацами —
  ровно одна пустая строка `""`. Пустых строк в начале и в конце нет;
  в тексте без слов результат пуст.

#### Заполнение

Строки абзаца заполняются жадно: слова идут по порядку, в строке они
разделены одним пробелом. Слово дописывается в текущую строку, если
строка после этого не длиннее `width`; иначе текущая строка кончается,
и слово начинает следующую.

Слово длиннее `width`:
1. текущая непустая строка кончается;
2. пока остаток слова длиннее `width`, от него отрезается кусок в
   `width - 1` байт; кусок с дефисом `-` в конце — отдельная строка;
3. остаток (не длиннее `width`) начинает новую строку, как обычное
   слово: за ним могут идти следующие слова.

#### Выравнивание

`align` — одно из `Left`, `Right`, `Center`, `Justify`:
- `Left` — строка как есть;
- `Right` — пробелы слева, длина строки — ровно `width`;
- `Center` — слева `(width - длина) / 2` пробелов (с отбрасыванием
  дробной части), справа ничего;
- `Justify` — строка растягивается до ровно `width`: лишние пробелы
  делятся между промежутками между словами поровну, а остаток деления —
  по одному в первые промежутки слева. Не растягиваются, а остаются как
  при `Left`: последняя строка абзаца и строка из одного слова (кусок
  длинного слова с дефисом — тоже одно слово).

Ни одна строка не кончается пробелом.

#### Ошибки

`width` вне `2..200` (включительно) — ошибка `BadWidth`.

#### Интерфейс

- перечисление `Align`: `Left | Right | Center | Justify`
- `wrap(text: str, width: i32, align: Align) -> ошибка BadWidth | список строк`

### t18. Исправление ошибок: планировщик событий

Дана реализация с ошибками (начальный код задачи): планировщик событий
на двоичной куче. Ошибок несколько, и они в разных функциях. Нужно найти
и исправить их, не переписывая решение заново: мера задачи — точность
правки. Устройство (куча, отмена пометкой, счётчик ожидающих) менять не
нужно.

#### Что должно получаться

Планировщик хранит текущее время `now` (сначала 0) и события. Событие —
номер `id`, время `at`, приоритет, период `every` и имя.

- `sched_new() -> Scheduler` — пустой планировщик.
- `sched_add(s, at: i64, priority: i32, every: i64, name: str) ->
  ошибка BadTime | i32` — добавляет событие и возвращает его номер:
  1, 2, 3, … по порядку успешных добавлений. `at < now` или
  `every < 0` — ошибка `BadTime`, планировщик не меняется. `at == now`
  допустимо. `every == 0` — событие разовое, иначе — периодическое.
- `sched_cancel(s, id: i32) -> ошибка NotFound | ok` — отменяет
  ожидающее событие (у периодического — все его будущие срабатывания).
  Нет события с таким номером, оно уже отменено или (разовое) уже
  сработало — `NotFound`.
- `sched_run(s, until: i64) -> список строк` — срабатывают по очереди все
  ожидающие события с `at <= until`. Очередь: по возрастанию `at`, при
  равном `at` — по убыванию приоритета, при равных — по возрастанию
  `id`. Срабатывание даёт строку `"AT NAME"`. Периодическое событие
  после срабатывания снова ждёт, со временем `at + every` и тем же
  `id` и приоритетом; если это время тоже `<= until`, оно сработает в
  этом же вызове — в своё место очереди. После вызова `now = until`
  (если `until < now`, ничего не срабатывает и `now` не меняется).
- `sched_pending(s) -> i32` — сколько событий ждёт (отменённые не
  считаются).

### Целевой интерфейс

```cpp
// Модуль cart (после рефакторинга): корзина.
#pragma once
#include <cstdint>
#include <string>
#include <vector>

#include "catalog.hpp"

struct CartLine {
    ItemId item;
    int32_t qty;
};

// Строки — в порядке первого добавления.
struct Cart {
    std::vector<CartLine> lines;
    int32_t discount_percent = 0;
};

enum class CartError { None, UnknownItem, NotInCart, BadQuantity, BadDiscount };
```
