# План реализации: v0.0, v0.1, v0.2

Минимальный путь от проекта к работающему ядру. Шаг — законченный кусок
с проверками и документами, отдельным коммитом. Порядок — сверху вниз;
шаг не начинается, пока не решены открытые вопросы из его строки
(`docs/direction/OPEN_DECISIONS.md`).

## v0.0. Замер до компилятора

| № | шаг | результат | проверки | документы |
|---|---|---|---|---|
| 0.1 | Эталонный набор | 12–16 задач: структуры данных, разбор текста, конечный автомат игровой логики, обход сущностей, генерация по ключевой случайности, сериализация, путь ошибки, рефакторинг через несколько модулей, исправление ошибки в данном коде, параллельная свёртка; у каждой — описание, интерфейс, эталон на C++ и тесты | эталоны проходят тесты | `bench/tasks/README.md` (внутреннее, Р5) |
| 0.2 | Измерительная обвязка | прогон задачи моделью с заданной спецификацией: правильность (тесты), циклы исправления, токены (Р35: API подсчёта токенов Claude) | повторный прогон даёт сопоставимые числа | `bench/README.md` |
| 0.3 | Варианты синтаксиса | 2–3 варианта, различающиеся в спорных местах (объявления, ошибки, ссылки, блоки, атрибуты, классы поведения); у каждого — краткая спецификация (3–5 тыс. токенов) и 3 образцовые программы | — | `docs/research/syntax/` |
| 0.4 | Прототип проверки | одноразовый переводчик подмножества каждого варианта в C++ (Python), чтобы запускать тесты набора; не компилятор (выведенное правило `DECISIONS.md`) | образцовые программы и решения набора переводятся и проходят тесты (`bench/syntax/run_variants.py` в `tools/check/run.sh`) | `bench/syntax/` (переводчик и опора), решения — `bench/tasks/*/cm/` |

## v0.2. Native-срез

Цели первой волны и порядок их проверки — `docs/policy/PLATFORMS.md`;
инструменты целей (MinGW-w64, Android NDK) ставит пользователь, в
поставку они не входят (`docs/policy/LICENSING.md`, раздел 3).

| № | шаг | результат | проверки | документы |
|---|---|---|---|---|
| 1 | Описание целей | `--target` у `build` и `test`: `linux-x86_64` (хост), `windows-x86_64`, `android-arm64`; тройка, размеры, компилятор C и флаги, проверка инструментов | тесты CLI; ошибка при недоступных инструментах — понятная диагностика | `docs/compiler/cli.md`, `docs/policy/PLATFORMS.md` |
| 2 | Windows x86-64 | порт runtime (вход, вывод, ловушки, файлы, коды выхода); кросс-сборка clang + lld поверх MinGW-w64 | проход `windows` в `tests/run.py`: набор исполнения под Wine совпадает с интерпретатором | `docs/runtime/README.md` |
| 3 | Android arm64 | порт runtime; сборка NDK clang | проход `android`: набор исполнения под qemu-aarch64 совпадает с интерпретатором | `docs/runtime/README.md`, `docs/policy/PLATFORMS.md` |
| 4 | Класс D | `@det import m` и `@det fn` (Р55): проверка в компиляторе, детерминированные функции библиотеки; канон NaN после каждой операции (Р56) | тесты отказа; повтор программы-симуляции побитово на x86-64 и arm64 | спецификация; Р55, Р56 |
| 5 | C ABI и FFI (Р59) | 5а — `extern fn`, `@link`, `extern type`, `@c struct`, соответствие типов; 5б — `@linear` и `errdefer` (Р57, Р60); 5в — вызов dpl из C | тесты на трёх целях | спецификация; Р57, Р59 |
