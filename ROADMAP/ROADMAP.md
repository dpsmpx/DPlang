# Планы разработки языка: v0.x → v1.0

Как читать:

- `[+]` — сделано, `[ ]` — открыто. Версии идут по порядку; текущая —
  первая открытая.
- У версии — **ворота**: условие, без которого следующая не начинается.
  Сравнения — по порядку целей Р6 и Р25: сначала корректность, потом
  скорость разработки и токены. Критерии остановки — `docs/direction/RISKS.md`.
- **После каждой версии — аудит** (`docs/policy/ENGINEERING.md`, раздел 4):
  фактическая цена версии в шагах, прогноз до v1.0, проверка критериев
  остановки К-1…К-3.
- Открытые решения с этой версией в сроке — `docs/direction/OPEN_DECISIONS.md`;
  их решают до соответствующего шага.
- **Срок.** Язык получает ориентировочно 1/6 рабочего ресурса автора и
  развивается параллельно VoxelRPG; календарных сроков нет, VoxelRPG
  язык не ждёт (Р21).
- **VoxelRPG.** До v1.0 основная кодовая база VoxelRPG на язык не
  переносится и его production-конвейер C++ не заменяется; можно —
  тесты, замеры, синтетические проекты, proof-of-concept и тестовые
  приложения (Р22). После v1.0 — только по Р31 и решению в
  `DECISIONS.md` VoxelRPG.
- Подробный первый план реализации (v0.0, v0.1) —
  [`IMPLEMENTATION.md`](IMPLEMENTATION.md). Definition of Done v1.0 —
  [`docs/direction/DEFINITION_OF_DONE.md`](../docs/direction/DEFINITION_OF_DONE.md).

**Закрыты с оговоркой** 10 октября 2026 по решению автора (история

**Состояние (12 октября 2026):** шаги 1–7 плана (`IMPLEMENTATION.md`,
v0.2) сделаны:
- `--target`, цели `windows-x86_64` и `android-arm64`; набор исполнения
  под Wine и qemu-aarch64 совпадает с интерпретатором;
- класс D (Р55, Р56): `@det import`, `@det fn`, E0425, канонический NaN;
  программа-симуляция `tests/run/det_sim` даёт один вывод на x86-64 и
  arm64.
- шаг 5а — FFI (Р59): `extern fn`, `@link`, `extern type`, `@c`;
  набор `tests/ffi` (функции libc и libm) совпадает на трёх целях.
- шаг 5б — линейные ресурсы (Р57, Р60): `@linear`, разбор
  `let S { ... } = v`, `errdefer`; проверка закрытия ровно один раз на
  каждом пути — при компиляции.
- шаг 5в — вызов dpl из C (Р61): `@export`, тип `extern fn(...)` для
  обратных вызовов, `dpl build --lib` (статическая библиотека и
  заголовок C); колбэк в `qsort` и хост на C (`tests/lib`) — на трёх
  целях.
- шаг 6 — привязки (Р58, Р62, Р63): структуры C для привязок
  (заимствующие поля, `@count`, `[N]T`, `@union`, общее начало, ноль
  у `@c`; `?H` — указатель или NULL); генератор Vulkan из `vk.xml`
  1.3.275 (ядро 1.3 и `VK_KHR_surface`, `VK_KHR_swapchain`) — раскладка
  всех структур совпадает с `vulkan.h`, программа на lavapipe заливает
  буфер командой в очереди; генератор SDL3 3.4.18 из заголовков списка
  — окно offscreen, события и поверхность Vulkan на lavapipe; JNI из
  `jni.h` AOSP — функции `JNIEnv` и `JavaVM` через `@slot(N)`, программа
  на JVM хоста зовёт Java.
- шаг 7 — графическая программа `examples/triangle` (Р64): треугольник
  SDL3 + Vulkan, снимок кадра побайтно равен эталону на Linux (lavapipe)
  и на Windows под Wine (окно Windows, Vulkan хоста); пакет APK для
  Android собирается в сессии, на устройстве автора 19 октября кадр
  равен эталону.
- шаг 8 (17 октября) — замер ворот в сессии: полный набор со всеми
  проходами — 1014 тестов; кадр на Linux и под Wine равен эталону,
  повтор `det_sim` совпадает на x86-64 и arm64, APK собран и передан
  автору; цена класса D (Р56) — +7–8% и +17–26% на двух нагрузках
  (`bench/det/measure.py`). Аудит — `docs/audits/2026-10-17-v0.2-audit.md`.
